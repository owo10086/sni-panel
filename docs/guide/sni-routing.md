# SNI 分流

SNI 分流让多条 TCP 转发规则共用同一个入口端口，并由出口主机根据 TLS ClientHello 中的完整 SNI 域名选择最终目标。入口主机只负责传输连接，域名匹配、按规则限速、连接数限制和流量统计均在出口主机的分流器执行。

管理员管理的对象始终是 **SNI 分流规则**。分流器内部持有的分流表由面板根据启用的规则生成，属于运行时派生数据，没有单独的创建页面，也不应手动维护。

## 使用条件

开始配置前，先确认以下条件：

1. 出口主机的 Agent 版本为 `2.2.195` 或更高版本，并且状态在线。
2. 流量能够到达链路入口，出口主机能够访问每条规则填写的目标地址和目标端口。
3. 承载资源已经在「链路管理」中创建并启用。SNI 分流支持转发链、单机端口转发和直接隧道。
4. 单机端口转发使用主机型资源，并且只包含一台启用的主机。
5. 直接隧道使用单一出口主机，未启用出口组、负载均衡或额外出口节点。
6. 当前账号具有管理员权限。普通用户无法创建或修改 SNI 分流规则。

## 创建承载资源

首次配置可以使用单机端口转发完成最短验证：

1. 按照[安装 Agent](./agent.md)和[主机管理](./hosts.md)将一台主机接入面板，并确认主机在线。
2. 进入「链路管理」，创建端口转发资源。
3. 资源类型选择主机，只添加上述在线主机，并启用该资源。
4. 确认主机允许使用计划中的入口端口，并且目标服务可从该主机访问。

生产链路也可以使用转发链或直接隧道。转发链至少需要入口主机和出口主机，SNI 分流器运行在最后一台启用的主机上。直接隧道需要先配置入口主机、单一出口主机和隧道协议，并保持出口组与负载均衡关闭。三种承载资源使用相同的 SNI 规则字段，切换承载方式时无需修改域名和目标。

## 创建第一条规则

进入「转发规则」，选择「添加规则」，然后填写以下字段：

| 字段 | 填写要求 |
| --- | --- |
| 规则名称 | 填写能够区分业务用途的名称 |
| 使用资源 | 选择已经启用的转发链、单机端口转发或直接隧道 |
| 入口端口 | 填写客户端实际连接的端口，例如 `443` |
| SNI 域名 | 填写完整域名，例如 `api.example.com` |
| 目标地址 | 填写出口主机最终访问的 IP 地址或域名，例如 `10.0.0.20` |
| 目标端口 | 填写目标服务监听端口，例如 `8443` |
| 规则限速 Mbps | 填写该域名允许使用的带宽，`0` 表示无限制 |
| 最大连接数 | 填写该域名允许同时建立的连接数，`0` 表示无限制 |

填写 SNI 域名后，协议固定为 TCP，出站故障转移关闭。SNI 域名只填写域名本身，不包含 `https://`、端口、路径或通配符。域名匹配忽略大小写和末尾的点，但建议始终使用规范的小写完整域名。

保存规则后，客户端仍然连接链路入口地址与入口端口。例如入口为 `203.0.113.10:443`，SNI 域名为 `api.example.com`，客户端发出的 TLS ClientHello 必须携带 `api.example.com`。分流器匹配成功后，连接才会转发到该规则的目标地址和目标端口。

## 让多个域名共用入口端口

继续创建规则，并保持「使用资源」和「入口端口」与第一条规则一致。每条规则填写各自唯一的完整 SNI 域名、目标地址和目标端口：

| 入口端口 | SNI 域名 | 目标 |
| --- | --- | --- |
| `443` | `api.example.com` | `10.0.0.20:8443` |
| `443` | `files.example.com` | `10.0.0.30:9443` |
| `443` | `admin.example.com` | `10.0.0.40:443` |

同一承载资源和入口端口组成一个 SNI 分流组。组内规则共用入口监听、隧道出口端口和出口分流器端口，各条规则仍独立保存目标、限速、连接数限制和流量统计。某条规则未设置限速或最大连接数时，该规则保持无限制，不会继承用户、隧道或转发组的同类限制。同一入口主机上的相同完整域名无法重复保存，即使两条规则使用不同入口端口或承载资源。

入口端口由整个 SNI 分流组独占。普通转发规则、其它承载资源的 SNI 分流规则以及当前分流组无法同时使用该入口端口。切换承载资源时，应保证新资源支持 SNI 分流并且入口端口可供该分流组使用；域名和目标配置无需随链路类型改变。

## 检查生效状态

规则列表会把同一承载资源和入口端口的 SNI 分流规则显示为一组。展开分组后检查以下信息：

| 信息 | 含义 |
| --- | --- |
| 规则状态 | `运行中` 表示出口主机已经确认对应域名进入当前配置 |
| 当前生效版本 | 出口分流器正在使用的配置版本；修改后应更新为新版本 |
| 未匹配连接 | 到达出口分流器但没有命中任何完整域名的累计连接数 |
| 上次配置错误 | 最近一次应用分流配置失败的原因；存在旧版本时，既有版本继续生效 |

保存或修改规则后，先等待分组状态变为运行中，再使用携带正确 SNI 的客户端连接入口地址和端口。仅验证端口建立 TCP 连接不足以证明域名已经匹配，实际请求必须发送 TLS ClientHello。

## 配置变化与既有连接

| 配置变化 | 既有连接 | 新连接 |
| --- | --- | --- |
| 修改域名、目标地址或目标端口 | 仅该规则的既有连接断开 | 使用新配置 |
| 修改单条规则的限速或连接数上限 | 仅该规则的既有连接断开，分流器进程保持 | 使用新限制 |
| 新增同组规则 | 保持连接 | 可以匹配新增域名 |
| 停用或删除单条规则 | 该规则的既有连接断开；隧道承载时，共享入口代表变化可能同时中断同组连接 | 该域名停止匹配并断开 |
| 停用最后一条规则或停用承载资源 | 整组连接断开 | 入口停止提供该分流组服务 |
| 出口主机离线或分流器重启 | 整组连接断开 | 恢复运行前无法建立连接 |

## 连接问题排查

规则创建后无法连接时，按照以下顺序检查：

1. 比对客户端发送的 SNI 与规则中的域名是否完全一致。`example.com`、`www.example.com` 和 `api.example.com` 是三个不同的匹配值。
2. 查看分组的「未匹配连接」是否增加。计数增加表示流量已经到达出口分流器，但域名没有匹配；修正客户端 SNI 或规则域名。
3. 未匹配连接数没有增加时，检查客户端是否连接了正确的入口地址和端口，再检查入口安全组、防火墙、链路状态以及出口主机是否在线。
4. 确认目标服务能够从出口主机访问，并检查目标地址、目标端口和目标服务证书配置。

配置修改后未生效时，检查出口主机对应分组的「当前生效版本」和「上次配置错误」。版本保持不变并出现错误时，出口分流器仍使用上一份成功配置；根据错误内容修正端口占用、规则字段或 Agent 运行环境。

## 行为边界与限制

未匹配任何 SNI 域名的连接会立即断开，系统不会设置默认目标。入口端口只响应分流组中配置的特定域名，因此端口扫描、普通 TCP 探测或未携带 SNI 的客户端可能表现为连接后立即关闭。

SNI 分流只支持 TCP，并依赖客户端发送可解析的 TLS ClientHello。客户端携带加密客户端问候（ECH）扩展不影响分流：只要 ClientHello 中的明文 SNI 可读，连接就按该域名匹配。只有完全取不到明文 SNI 的连接才无法匹配。

出口主机是整个分流组的单点。出口主机离线、网络中断或分流器停止时，同组全部域名均无法访问。

客户端真实 IP 无法保留到最终目标。最终目标看到的连接来源是出口主机或分流器使用的本机地址，不能依赖来源地址执行客户端访问控制或审计。

入口端口由分流组独占，并且只对已配置的完整域名产生有效转发。这一行为会影响通用端口探测、监控和不携带 SNI 的健康检查，监控请求应使用分流组中的实际域名。
