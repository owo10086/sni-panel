# SNI 分流

SNI 分流让多条 TCP 转发规则共用同一个入口端口，并根据 TLS ClientHello 中的完整 SNI 域名选择转发目标。转发链的入口分流器按域名选择该规则所属转发链的下一跳，出口分流器再按域名选择落地机。因此，不同转发链可以共用同一台入口主机的同一个入口端口，每条转发链仍可以配置多台落地机。

按规则限速、连接数限制和流量统计统一由出口分流器执行。入口组可以包含多台并行接收连接的主机，在入口分别执行限制会使总额度随入口数量增加；出口是连接到达落地机前的唯一必经点。入口分流器产生的流量数据会被忽略，出口继续提供唯一计量来源。

管理员管理的对象始终是 **SNI 分流规则**。分流器内部持有的分流表由面板根据启用的规则生成，属于运行时派生数据，没有单独的创建页面，统一由面板维护。每台入口主机的入口分流表只包含引用该主机和入口端口的规则，路由目标为各条转发链自己的下一跳；出口分流表的路由目标为各条规则保存的落地机地址和端口。

## 使用条件

开始配置前，先确认以下条件：

1. 出口主机的 Agent 版本为 `2.2.195` 或更高版本，并且状态在线。使用转发链时，所有相关入口主机也须满足同一最低版本要求，入口组中的每台主机均须检查。
2. 流量能够到达入口，转发链入口能够访问下一跳，出口主机能够访问每条规则填写的落地机地址和端口。
3. 承载资源已经在「链路管理」中创建并启用。SNI 分流支持转发链、单机端口转发和直接隧道。
4. 单机端口转发使用主机型资源，并且只包含一台启用的主机。
5. 直接隧道使用单一出口主机，未启用出口组、负载均衡或额外出口节点。
6. 当前账号具有管理员权限。普通用户无法创建或修改 SNI 分流规则。

转发链入口 Agent 版本不足、未上报版本或版本格式无法识别时，入口版本检查视为未满足要求，相关规则显示入口版本异常并停止运行。创建、修改、启用和批量导入 SNI 分流规则时均会检查入口版本，错误提示包含所需最低版本。

## 创建承载资源

首次配置可以使用单机端口转发完成最短验证：

1. 按照[安装 Agent](./agent.md)和[主机管理](./hosts.md)将一台主机接入面板，并确认主机在线。
2. 进入「链路管理」，创建端口转发资源。
3. 资源类型选择主机，只添加上述在线主机，并启用该资源。
4. 确认主机允许使用计划中的入口端口，并且目标服务可从该主机访问。

生产链路也可以使用转发链或单出口隧道。转发链至少需要入口主机和出口主机，也可以引用入口组。所有相关入口主机均运行入口分流器，最后一台启用的主机运行出口分流器。两跳转发链的入口将连接送往出口分流器；三跳及更长转发链的入口将连接送往下一台中转主机的监听端口。转发方式只影响中转成员，两跳转发链的入口和出口均由分流器承担。

单出口隧道需要先配置入口主机、单一出口主机和隧道协议，并保持出口组与负载均衡关闭。隧道入口维持原有传输方式，分流器仍位于出口。单机端口转发只有一台主机，由该主机的分流器监听入口端口并选择落地机。三种承载资源使用相同的 SNI 规则字段，切换承载方式时可以保留域名和目标，并重新检查新资源的端口与版本要求。

## 创建第一条规则

进入「转发规则」，选择「添加规则」，先选择承载资源，然后打开「SNI 分流转发」开关。开关位于协议与源端口之间，打开后表单切换为分流形态：入口端口自动设为 `443` 并锁定，SNI 域名成为必填项，协议锁定为 TCP，出站故障转移关闭，并出现限速与最大连接数两个字段。

开关置灰时，灰色文字写明了原因，常见的是承载资源不支持分流（转发组、多出口隧道、含多台主机的端口转发资源）。普通用户看不到该开关。

打开开关后填写以下字段：

| 字段 | 填写要求 |
| --- | --- |
| 规则名称 | 填写能够区分业务用途的名称 |
| 使用资源 | 选择已经启用的转发链、单机端口转发或直接隧道 |
| 入口端口 | 开关打开后自动锁定为 `443`，无需填写 |
| SNI 域名 | 填写完整域名，例如 `api.example.com` |
| 目标地址 | 填写落地机的 IP 地址或域名，例如 `10.0.0.20` |
| 目标端口 | 填写目标服务监听端口，例如 `8443` |
| 规则限速 Mbps | 填写该域名允许使用的带宽，`0` 表示无限制 |
| 最大连接数 | 填写该域名允许同时建立的连接数，`0` 表示无限制 |

SNI 域名只填写域名本身，不包含 `https://`、端口、路径或通配符。域名匹配忽略大小写和末尾的点，但建议始终使用规范的小写完整域名。填写完域名后面板会校验该域名在当前入口主机上是否已被占用，冲突时在输入框下方写明与哪条规则冲突。

入口端口锁定后跳过普通规则的端口占用探测，因为多条 SNI 分流规则可以共用入口监听。保存时仍检查普通转发规则占用、域名重复及端口范围。关闭开关后恢复普通转发规则的端口探测，入口端口也恢复为打开开关之前的值。

### 使用 443 以外的入口端口

需要把分流组建在别的端口上时，点击锁定框右侧的「修改入口端口」，端口即可编辑。三种情况会用到它：

- 主机或链路资源限定的端口范围不包含 `443`。
- 面板自身占用了该主机的 `443`（见 [Cloudflare CDN](./cloudflare-cdn.md)），此时 `443` 上的分流规则无法启动。
- 要往一个已经建在非 `443` 端口上的分流组里补充域名。

编辑一条已有的 SNI 分流规则时，入口端口保持规则原有的值并锁定，不会被改写为 `443`。

保存规则后，客户端仍然连接链路入口地址与入口端口。例如入口为 `203.0.113.10:443`，SNI 域名为 `api.example.com`，客户端发出的 TLS ClientHello 必须携带 `api.example.com`。分流器匹配成功后，连接才会转发到该规则的目标地址和目标端口。

## 让多个域名共用入口端口

继续创建规则，打开「SNI 分流转发」开关，并保持入口端口与第一条规则相同。使用转发链时，可以继续选择同一条转发链，也可以选择另一条引用相同入口主机的转发链。每条规则填写各自唯一的完整 SNI 域名和落地机地址、端口：

| 入口端口 | SNI 域名 | 转发链 | 落地机 |
| --- | --- | --- | --- |
| `443` | `api.example.com` | 转发链 A | `10.0.0.20:8443` |
| `443` | `files.example.com` | 转发链 B | `10.0.0.30:9443` |
| `443` | `admin.example.com` | 转发链 A | `10.0.0.40:443` |

上述示例中的两条转发链须引用同一台入口主机或具有共同成员的入口组。该入口主机的 `443` 端口只有一个入口分流器，分流表同时包含三条路由，并将每个域名送往所属转发链的下一跳。各条转发链保留自身的出口分流器端口，各条规则独立保存落地机、限速、连接数限制和流量统计。

跨资源共用入口端口仅适用于转发链之间。隧道 SNI 分流规则仍须引用同一条隧道才能共用入口端口；单机端口转发 SNI 分流规则仍须引用同一个端口转发资源。隧道、单机端口转发和转发链之间保持入口端口互斥。

普通转发规则与 SNI 分流规则保持端口互斥。同一入口主机上的相同完整域名仍须唯一，即使规则引用不同入口端口或承载资源。某条规则未设置限速或最大连接数时，该规则保持无限制，也保持独立于用户、隧道或转发组的同类限制。

## 检查生效状态

规则列表仍按同一承载资源和入口端口显示 SNI 分流规则分组。转发链规则只有在所有相关入口分流器和出口分流器都确认对应域名进入当前有效配置后，才显示为运行中。仅出口确认、仅入口确认或入口组中部分主机确认时，规则继续等待生效。规则还须处于启用状态，承载资源处于启用状态，入口版本满足要求，且规则尚未进入删除等待状态。

分组信息分别展示入口与出口，入口组保留每台入口主机的明细。展开分组后检查以下信息：

| 信息 | 含义 |
| --- | --- |
| 入口与出口生效状态 | 分别检查每台入口主机和出口主机是否得到运行观测、对应域名是否生效 |
| 当前生效版本 | 各个分流器正在使用的配置版本；规则保存完成与配置生效是两个独立状态 |
| 入口未匹配连接 | 客户端使用该入口主机未配置的域名，常见原因包括域名拼写错误、DNS 指向错误或端口扫描 |
| 出口未匹配连接 | 转发链场景中通常提示入口与出口配置尚未同步，因为入口只转发匹配的域名，出口保留来自上一跳的来源限制 |
| 最近配置错误 | 各个分流器最近一次应用配置失败的原因；存在有效旧版本时，继续使用该版本 |

转发链的两类未匹配计数分别显示，入口计数与出口计数分别用于检查客户端域名和双端配置。隧道和单机端口转发维持出口确认域名生效的运行状态定义。

保存或修改规则后，先等待分组状态变为运行中，再使用携带正确 SNI 的客户端连接入口地址和端口。仅验证端口建立 TCP 连接不足以证明域名已经匹配，实际请求必须发送 TLS ClientHello。

## 查看入口全貌

管理员通过侧边栏的「SNI 入口」进入只读页面。页面按「入口主机 + 入口端口」展示转发链 SNI 分流规则，包含规范化域名、规则名称、启用状态、所属转发链及规则保存的落地机地址和端口。落地机以规则保存的地址和端口显示，地址本身表示服务目标，是否在面板登记为主机资源须另行确认。

每台入口主机同时显示 Agent 当前版本、最低版本 `2.2.195` 和版本要求满足状态。版本不足、未上报或无法识别时，应在「主机管理」检查对应 Agent 的版本并完成升级，再确认入口域名生效。

相关入口主机在相同端口上共享规则时，页面比较各台主机的启用域名集合，集合存在差异时标记差异并列出各台主机缺少的域名。单入口与多入口配置可以合法并存，集合差异只作为检查提示。例如 `api.example.com` 引用双入口转发链、`files.example.com` 引用单入口转发链时，另一台入口会缺少 `files.example.com`；客户端 DNS 应与规则实际引用的入口一致。

页面仅提供查看和搜索能力，配置变更仍通过「转发规则」完成。页面和入口全貌查询均限定管理员访问。

## 配置变化与既有连接

| 配置变化 | 既有连接 | 新连接 |
| --- | --- | --- |
| 修改域名 | 仅该规则的既有连接断开，其余规则保持连接 | 使用新域名 |
| 修改落地机地址或端口 | 仅该规则的既有连接断开；转发链入口分流表保持原配置 | 使用新落地机 |
| 修改单条规则的限速或连接数上限 | 仅该规则的既有连接断开，分流器进程保持 | 使用新限制 |
| 新增共用入口端口的规则 | 保持该端口上的既有连接，包括其它转发链的规则 | 可以匹配新增域名 |
| 停用或删除单条规则 | 仅该规则的既有连接断开，其余规则保持连接 | 该域名停止匹配并断开 |
| 停用承载资源 | 该资源的全部连接断开，共用入口端口的其余转发链保持连接 | 该资源的域名停止匹配 |
| 停用或删除入口端口上的最后一条规则 | 该端口的连接断开 | 入口停止提供该端口的分流服务 |
| 出口主机离线或出口分流器重启 | 使用该出口分流器的全部规则连接断开 | 恢复运行前无法建立连接 |
| 入口主机离线或入口分流器重启 | 使用该入口主机和端口的全部转发链连接断开 | 恢复运行前，该入口无法建立连接 |

转发链入口分流器的运行时身份由「入口主机 + 入口端口」确定，删除编号最小的规则也保持相同身份。新增、修改和删除路由使用分流表热更新，监听端口保持打开，只关闭本次发生变化的规则连接。修改落地机地址仅改变出口分流表，入口下一跳和入口分流表内容保持相同。隧道删除首条 SNI 分流规则后，其余规则共用的入口配置也保持相同。

## 升级前检查

面板升级确认区域复用「SNI 入口」的只读查询，检查转发链 SNI 分流规则关联的入口 Agent 版本。所有入口满足要求时显示检查通过和最低版本；存在版本异常时列出主机名称、当前版本或未上报状态，并提供进入入口全貌页面的导航。查询期间显示检查状态，查询失败时显示错误原因。没有转发链 SNI 分流规则时，省略入口版本提示。

升级前须确保所有相关入口 Agent 支持分流器。面板升级后，已有转发链 SNI 分流规则的入口监听统一切换为入口分流器，切换时既有连接发生一次中断。完成切换后的新增、修改和删除继续使用分流表热更新，并按上表处理连接。入口 Agent 版本异常时，相关规则停止运行并显示异常；恢复符合要求的版本后，继续检查入口和出口的生效状态。

## 连接问题排查

规则创建后无法连接时，按照以下顺序检查：

1. 比对客户端发送的 SNI 与规则中的域名是否完全一致。`example.com`、`www.example.com` 和 `api.example.com` 是三个不同的匹配值。
2. 使用转发链时，分别查看入口和出口的未匹配连接数。入口计数增加时，检查域名拼写、客户端 DNS 指向及「SNI 入口」中该主机的域名集合；出口计数增加时，检查入口和出口的生效状态、配置版本与最近配置错误。隧道或单机端口转发的出口计数增加时，检查客户端域名是否存在于出口分流表。
3. 使用入口组时，检查每台入口主机的 Agent 版本和域名生效状态。只有部分入口生效时，客户端可能因 DNS 选择不同入口而出现连接差异。
4. 未匹配连接数没有增加时，检查客户端是否连接了正确的入口地址和端口，再检查入口安全组、防火墙、转发链各台主机以及出口主机是否在线。
5. 确认目标服务能够从出口主机访问，并检查落地机地址、端口和目标服务证书配置。

配置修改后未生效时，检查对应入口主机与出口主机的「当前生效版本」和最近配置错误。受影响的分流表版本保持相同并出现错误时，该分流器仍使用上一份成功配置；根据错误内容修正端口占用、规则字段或 Agent 运行环境。仅修改落地机地址时，入口分流表内容保持相同属于预期行为。

## 行为边界与限制

未匹配任何 SNI 域名的连接会立即断开，系统不会设置默认目标。入口端口只响应分流组中配置的特定域名，因此端口扫描、普通 TCP 探测或未携带 SNI 的客户端可能表现为连接后立即关闭。

转发链入口分流器接收公网客户端连接，入口分流表采用开放的来源策略；出口继续保留上一跳来源 IP 限制。未知域名、未携带 SNI、非 TLS 或握手未在读取时间内完成的连接均在入口断开，匹配成功的 TLS 握手原样传输到后续目标。

SNI 分流只支持 TCP，并依赖客户端发送可解析的 TLS ClientHello。客户端携带加密客户端问候（ECH）扩展不影响分流：只要 ClientHello 中的明文 SNI 可读，连接就按该域名匹配。只有完全取不到明文 SNI 的连接才无法匹配。

出口主机是整个分流组的单点。出口主机离线、网络中断或分流器停止时，同组全部域名均无法访问。

共用同一台入口主机和端口的转发链也共用一个入口分流器，该进程停止会同时影响该端口的全部转发链。分流表热更新保持监听运行，日常规则变更仅影响对应规则的连接。

客户端真实 IP 无法保留到最终目标。最终目标看到的连接来源是出口主机或分流器使用的本机地址，不能依赖来源地址执行客户端访问控制或审计。

SNI 分流规则共用的入口端口仅对分流表中的完整域名产生有效转发，并保持与普通转发规则互斥。这一行为会影响通用端口探测、监控和未携带 SNI 的健康检查，监控请求应使用该入口分流表中的实际域名。
