# 端口转发使用多个入口

[English](./port-entry-groups.en.md)

一条规则可以通过入口组在多台主机同时提供服务，每台入口直接访问规则保存的目标，不需要额外的隧道或公共出口。客户端连到哪台入口，就由哪台转发；不会把一次连接复制给所有入口。

## 配置步骤

1. 在「链路管理」创建入口组，添加需要同时服务的主机，最多 20 台。填写入口组域名；自行管理 DNS 时关闭自动解析。
2. 创建或编辑「端口转发」资源，把「入口类型」设为「入口组」，选择刚保存的组和普通转发工具。
3. 添加转发规则，选择该资源，填写统一入口端口、协议、目标地址和目标端口。
4. 保存后打开资源的「节点详情」，分别检查各台入口。实际客户端连接成功后再投入使用；保存完成和 Agent 在线都不代表业务已经连通。

例如 A、B 同时提供 `18443`，目标是 `service.example.com:443`。客户端连接 A 时走「客户端 → A → 目标」，连接 B 时走「客户端 → B → 目标」，A、B 之间不串联。

## 端口、故障和限制

入口端口应在所有启用入口允许范围的交集中，并通过面板内已有规则的占用检查。创建时不会先读取主机现场端口占用来阻断保存。某台主机下发后出现实际占用或应用失败时，应单独查看它的原因，其他正常入口继续工作。

入口组中某台主机缺少普通转发工具时，缺项只限制该入口；其他正常入口继续服务。单主机资源保留自己的保存前工具检查。SNI 使用独立分流器，不以普通 GOST 工具检查代替它的能力确认。

修改目标、协议、端口或启停开关后，面板同步相关入口。增删成员只调整对应入口，未修改的健康规则保持运行。移除成员后保留该规则已经产生的历史用量，停止尚未确认时仍可能显示待收尾，不能只删除页面记录就认为机器已停止。

节点详情分别显示主机在线情况、启用规则、同步错误、执行失败次数和最早重试时间。同步冲突约 60 秒后可以重试，配套 Agent 执行失败约 30 秒后可以重试；这不是保证完成的时间，仍取决于连接、心跳和调度。缺少新版报告时显示未确认，不编造次数。

限制由每台入口分别执行。例如每条规则限速 10 Mbps，A、B 各自执行 10 Mbps，同时访问时不能当作全组严格共用 10 Mbps。流量则把 A、B 的实际用量各计算一次，汇总到同一原规则及所属用户；不重复累计派生规则或中转流量。

更多运行诊断和资源统计说明见[入口组](./groups.md#入口组)。

## 按域名分流

需要多个域名共用 TCP 端口时，使用相同的端口资源，然后由管理员添加 SNI 分流规则。A、B 各自直接连接每条规则的落地机。它与选择一个当前入口的主备转发组不同；配置、逐入口确认、解析和连接影响见[SNI 多入口直达落地](./sni-routing.md#端口资源通过入口组直接分流)。

SNI 不能按共享端口猜测来源属于哪个域名，本轮不增加专用来源采集。ny 实验导入也不支持 SNI 规则。
