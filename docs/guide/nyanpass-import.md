# ny / Nyanpass 导入（实验性）

[English](./nyanpass-import.en.md)

在「转发规则 → 批量管理 → 批量导入」选择「ny（实验性）」，粘贴 ny 导出的逐行 JSON，或上传 `.json`、`.jsonl`、`.ndjson`、`.txt` 文件。也接受一个 JSON 对象或对象数组；这里不接收完整数据库备份。

## 导入前

1. 先在本面板创建并选择目标端口转发、隧道、转发链或转发组。
2. 明确选择 TCP、UDP 或 TCP+UDP。导出内容不足以自动还原原来的拓扑、协议和暂停状态。
3. 核对预览中的名称、入口端口、目标、限速、PROXY 设置和目标选择方式，再确认实验性说明。
4. 导入完成后先检查规则。**所有 ny 规则初始停用**，确认实际配置后再启用。

导入只转换规则配置，不导入主机、组、账户、密码或流量历史，也不保证与 ny 节点互通。建议先用少量规则检查真实通信。

## 支持范围

| 内容 | 处理方式 |
| --- | --- |
| 单目标 IP、域名、`[IPv6]:端口` | 继续检查目标资源权限和端口范围 |
| 多目标 | 最多 11 个，仅支持 TCP 的 GOST 普通端口资源 |
| `random`、`round`、`ip_hash`、`failover` | 转为本面板对应方式，检测和切换时间按本面板执行 |
| TCP PROXY | 仅支持已有设置匹配的 GOST／Realm 普通端口资源，不擅自修改共享资源 |
| `speed_limit` | 管理员可导入能精确换算为整数 Mbps 的值，125000 字节／秒等于 1 Mbps |
| UDP PROXY、`least_load`、TLS／SNI 子规则 | 明确拒绝，不作为普通规则导入 |
| 非零 `ip_limit`／`connection_limit`、未知字段 | 明确拒绝，不静默丢弃 |

## 部分失败与重试

这类导入沿用本地整批保存，每条输入都有对应结果。一条失败不会撤销其他成功项。指定端口冲突或超出范围时保留原内容并说明原因，不自动换号；只有 `listen_port: 0` 请求按资源允许范围分配。

修改后只重试失败项，已经成功的规则不会重复提交，也不会覆盖旧规则。普通规则的手动四段格式仍可使用，SNI 则有自己的导入模式，详见[普通规则批量导入](./rules.md#普通规则批量导入)及[SNI 分流](./sni-routing.md)。
