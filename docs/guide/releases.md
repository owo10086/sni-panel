# 版本与文档更新

## 本版源码 3.9.0

面板、Agent 和 ForwardX FXP runtime 源码版本统一为 `3.9.0`，累计兼容固定上游 2.3.290—2.3.292。新增批量规则后台任务、端口范围与 TXT 导入导出、安装实例接管、连接数、受限 LXC 流量统计回退和三日日志；加固登录签名密钥与请求接收，改进数据库查询、记账及网页。套餐和按量管理保留卡片／表格双视图，本地 SNI、入口健康、DDNS、Docker 共存及已落地的交接修复继续保留。

安装实例接管、连接数、流量统计回退和 Agent 日志需要更新配套 Agent／FXP。接管保留主机和规则，新实例重新确认当前配置；旧转发不会自动撤销，旧版 Agent 需手动停止服务或先升级。安装命令复制前会实时核对绑定并提示确认。三种数据库的新建与升级、实际验证和环境限制以本轮记录为准。正式附件以本项目 [GitHub Releases](https://github.com/owo10086/sni-panel/releases) 为准；本轮实施交付为本地提交，发布与生产升级另行执行。

## 3.8.0

面板、Agent 和 FXP 运行时源码版本均为 3.8.0。本版修复原生 nftables 转发在运行 Docker 的入口上全部连接超时的问题：Docker 的 `FORWARD` 默认 DROP 链盖住了 ForwardX 自己的放行，规则却仍显示运行。现在面板在 `DOCKER-USER` 链里为每条 IPv4 规则安装按规则、入口原始端口、协议、转换后目标和回程方向限定的放行，管理员的显式拒绝仍然优先，不改 FORWARD 策略。

Agent 的就绪判断不再只看 DNAT，而是核实 IP 转发、源地址转换、转发与回程放行和 Docker 放行；安装或清理失败的原因会进入动作状态。自测只证明检测来源到目标的连接，网页分开展示“目标连接成功／失败”和“外部经入口的转发路径：未验证”。主备组仍按入口自身运行状态选择入口，业务目标失败不触发整组切换。

**完整行为需要一起更新面板与配套 Agent。** 仅升级面板会恢复转发，但旧 Agent 仍发现不了缺失；仅升级 Agent 时，Docker 主机上的旧面板不会安装放行，规则会如实报为未就绪并给出原因。只处理 IPv4 与“FORWARD 默认 DROP + 跳转 DOCKER-USER”的结构，ufw、自定义防火墙和 Docker 的 nftables 原生后端不判断、不修改；入口修复不保证业务目标自身恢复。

正式附件、镜像和文档必须对应同一提交并经完整核对，具体发布状态以本项目的 [GitHub Releases](https://github.com/owo10086/sni-panel/releases) 为准。开发检查、人工验收、发布和生产升级分别记录。

## 运行兼容

V3 的底层代码纳入本地构建，但网页与直接请求接口都不开放新建或切换 V3，现有 V1／V2 不自动转换。以后如开放，还须确认两端程序实际兼容，不能只看版本号相同。

此前同样显示 `3.3.0` 的旧 FXP 可能没有局部新增接口；新 Agent 会拒绝不支持的新增，保持现有业务。端口工具和诊断信息需要配套 Agent 的实际报告；未确认不能当作已经支持。

局部新增保留连接不等于升级过程不断线：更新二进制、首次启用控制入口、修改或删除已有监听，以及故障恢复仍可能替换进程。回执丢失时须核对真实状态，不能把它当成已撤回。升级前先[备份](./upgrade-backup.md)，之后验证真实 TCP／UDP 业务。

## 核对文档来自哪里

- **源码提交**表示保存了代码记录，不代表已构建或已发布安装包。
- **正式附件**以 [本项目 Releases](https://github.com/owo10086/sni-panel/releases) 为准。本轮本地检查不会覆盖已有附件、版本标签、镜像或 `latest`。
- **文档站**单独构建。站点显示的版本与已安装面板的版本可能不同，本地构建也不代表网站已经更新。

文档左上角显示构建时的面板版本。[构建信息](../build-info.json) 提供版本、代码记录、构建时间和本次内容的文件指纹。`sourceDirty: true` 表示含有尚未提交的文档或版本配置，不能只凭提交编号认为其中已包含这些改动；文件指纹可进一步核对内容。源码压缩包没有 Git 记录时，提交显示为 `local`，是否有未提交改动显示为未知。

1. 查看 [本项目 Docs 流程](https://github.com/owo10086/sni-panel/actions/workflows/docs.yml)，确认构建和部署是否实际完成。

维护者另行决定发布后，可运行文档部署流程。这里说明核对方式，发布流程会构建和部署文档；是否已经更新以流程结果和构建信息为准。
