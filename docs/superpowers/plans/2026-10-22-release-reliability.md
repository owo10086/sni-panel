# 修复发布失败，并建立统一的发布检查流程

用户于 2026-10-22 明确授权实施。基线：948fa84eea48e06c04b18f46b11d28cab8665b0d。

## 问题与目标

功能工单完成不代表发布完成。已定位：批量操作受并行测试争用影响超过 5 秒；DNS 测试只固定日期而没有控制后台队列；FXP 旧会话被未完成控制帧刷新；面板与 Agent 发布各自启动并互相等待。

目标：稳定复现并修正已知失败；任何检查失败都阻止不完整版本发布。

## 实施内容

1. DNS：独立进程接管后台队列入队，由测试明确推进；真实 HTTP 和数据库保留。触发器记录命中阶段，核对同组和跨组共享监听期间旧决定未发往 DNS；另验证真实队列自动执行和重新检查，不用固定休眠。保留 ADR-0006、ADR-0008。
2. FXP：无业务、无待发送控制帧的连接构造旧会话，验证关闭、移除、新连接收发和池计数归零；保留成功写入刷新活跃时间检查。生产策略不变。
3. 性能：四类资源独立入口，每类 20 批、每批 7 条、并发上限 6、每批严格少于 5000 毫秒。独立 Linux 任务、文件并行数 1，保留全部行为断言；逐批记录类型、轮次、阶段、耗时、环境和超时进度。不得通过放宽标准获得通过。
4. 统一检查：Ubuntu 24.04、Node 22.23.3、pnpm 10.28.1、Go 1.23.12；锁文件安装。覆盖现有 CI 和发布检查并集，增加 SNI 分类、网页分类、域名异常；依赖构建的检查放在构建后。分别呈现功能、性能、双语与类型、数据库升级、Agent/FXP。
5. 统一发布：固定提交 → 构建及全部检查 → 组装面板、Agent、镜像候选 → 验证安装包与镜像 → 草稿附件 → 完整性核对 → 正式发布。Agent/FXP 构建一次，面板内置与附件相同；镜像复用已验证产物，按摘要验证启动和原生依赖。
6. 发布清单记录提交、组件版本、检查记录、附件校验及镜像摘要；正式发布前保持草稿及旧 latest。各平台收尾记录状态，部分失败标记未完成；按原提交、原产物恢复。测试失败不重试；网络传输至多 3 次，间隔 5、15 秒。

## 验收

- 性能四类各连续 3 轮，每轮 20 批，逐批 <5000 毫秒。
- DNS 同组和跨组共享监听各 100 次，包含提前入队、延迟执行，记录触发顺序。
- FXP 1 核和 4 核各 1000 次，相关 Go 检查与竞态检查无泄漏。
- 全新 Linux 检出通过统一入口。
- 模拟测试失败、附件缺失、哈希错误、上传失败、重复执行与恢复；正式发布前失败不更新公开版本。
- 附件、镜像、安装启动与文档同提交全部核对，才记录正式发布完成。

## 边界与交付

范围为测试、检查脚本、发布流程，不改生产转发策略、数据库迁移或业务接口。面板准备 3.5.2，Agent/FXP 保持 3.5.0，不改 v3.5.1 标签，不涉及原生客户端。

按 DNS、FXP、性能、统一检查与发布编排拆中文本地提交。只向 sni-panel/main 推送；版本标签与 main 同推，不创建 worktree。本次授权涵盖实现、验证与本地提交，推送、正式发布、生产升级另需明确授权。

状态独立记录：开发检查通过、人工验收通过、发布检查通过、正式发布完成。不能把本机验证写成远端 Linux 发布完成。
