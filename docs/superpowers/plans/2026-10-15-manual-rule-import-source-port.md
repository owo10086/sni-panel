# 普通规则批量导入：指定规则名和源端口调整计划

> 实施方式：取得用户对代码修改的明确同意后，在当前目录按本计划逐项实施；不创建工作树。接手时先阅读本文件和 `AGENTS.md`，可使用 `executing-plans` 技能跟踪步骤。

**目标：** 在批量导入的“手动输入”中支持 `规则名称#源端口#目标地址#目标端口`，让每条普通规则保留用户填写的名称和入口端口。

**使用现有能力：** 沿用当前网页、格式检查、逐条创建和测试工具；不增加依赖，不增加后台接口或数据库字段，不升级 Agent。

## 一、格式与行为约定

### 支持两种格式

同一个“手动输入”框允许按行混用以下两种格式，不增加模式开关：

```text
官网#10443#example.com#443
内网服务#18080#10.0.0.8#8080
IPv6服务#18443#[2001:db8::1]#8443
example.net:443
[2001:db8::2]:8443
```

前三条按填写的名称和源端口创建；后两条继续以目标地址和端口作为规则名称，并随机分配源端口。例如第一条表示“所选入口的 10443 转发到 example.com 的 443”，名称为“官网”。

| 项目 | 本次约定 |
| --- | --- |
| 格式识别 | 行内有 `#` 时按新格式检查，必须正好四项；没有 `#` 时按原有 `地址:端口` 处理。新格式错误时不能退回原格式尝试创建 |
| 规则名称 | 去除两端空白后必须为 1–128 个字符；保留名称内部空格和用户文字；`#` 是分隔符，本次不提供在名称中输入 `#` 的写法 |
| 新格式源端口 | 只接受由十进制数字组成、数值为 1–65535 的端口；不接受空白、0、负数、小数、科学计数或十六进制。需要随机端口时使用原格式 |
| 新格式目标端口 | 与新格式源端口采用相同的数字和范围要求 |
| 新格式目标地址 | 接受现有导入支持的域名、IPv4，以及使用 `[地址]` 写法的有效 IPv6；保存 IPv6 时去掉方括号；地址去除两端空白后不超过 253 个字符 |
| 原格式兼容 | 保留原手动导入现有的地址拆分、端口识别、名称生成和随机端口分配方式，不借此收紧原格式的检查；包括当前已接受的 `example.com:1e3`、`example.com:0x50`、`2001:db8::2:8443`。混用时的提交顺序按下述约定执行 |
| 空行和数量 | 忽略空行；单次最多 500 条非空行；错误中的行号仍按输入框实际行数计算 |
| 其他配置 | 协议、转发工具、启用状态和其他默认值沿用原手动导入；四段格式不增加新的配置项 |
| 可选入口 | 沿用现有端口转发、隧道、转发链、转发组的选择范围和权限要求；整批使用当前选中的资源 |

### 提交顺序、指定端口失败和重试

- 仅“手动输入”按两组先后提交：先提交所有指定源端口的规则，等待这一组全部成功或失败后，再提交随机源端口规则。不能只调整数组排列后仍同时提交两组，避免随机规则抢走同批指定的端口。
- 每组内部最多同时处理 6 条，组内沿用原输入顺序安排。只有一种格式时直接处理对应一组，空组不发请求。
- 提交顺序的变化只用于创建；预览、最终结果、错误行号和失败回填仍按原输入顺序对应，不按实际完成顺序重排。
- 新格式指定的端口遇到面板已有规则冲突、同批多个指定端口相同、资源端口范围或套餐端口范围限制时，该条报错，不自动改用随机端口，也不修改已有规则。
- 一条创建失败，其他已经成功的条目保留；指定端口组有失败也继续处理随机端口组，不新增整批撤回逻辑。
- 失败行保留输入原文，包含名称、源端口、目标地址和目标端口；原格式失败行也保留原文。仅去掉行首、行尾空白，保留行内内容和失败项的相对顺序。
- 用户修改失败行后再次导入，只提交留下的失败项，已经成功的规则不再提交。
- 输入检查不通过时，指出具体行和原因，导入按钮不可用，整批不发出创建请求。创建阶段出错时，列出失败规则名称、原输入行号和原有错误原因。
- JSON 文件导入继续使用当前的端口冲突处理；SNI 专用输入的四段格式和统一入口端口继续使用当前规则。
- 沿用现有端口检查约定：不增加主机监听端口的创建前检查；保存成功不等于 Agent 已确认运行。
