# SNI 端口转发通过入口组直接连接各规则落地

**状态：已实现，等待人工验收。** 2026-10-19 用户在本地 284 → 上游 285 合并讨论中确认：端口转发资源可引用入口组；每台入口独立完成最终 SNI 分流，直接连接每条规则自己的固定落地。沿用上游入口组操作方式，满足多入口同时使用的需要，不依赖额外公共出口，也不把最后一个成员推断成出口。

例如入口组有 A、B，规则为 `a.example:443 → X:443`、`b.example:443 → Y:8443`。客户连接到 A 或 B 后，由那台入口直接连 X 或 Y；一条规则一个落地，不要求所有域名共用一个落地。落地无需因本方案安装 Agent／FXP，TLS 内容原样传递。

## 限制和累计的取舍

各入口分别执行每条规则的限速和最大连接数，实际用量与费用按既有去重、结算机制汇总到根规则和用户。例如每入口限制 10 Mbps／100 连接，A、B 同时使用可能合计 20 Mbps／200 连接；A 用 30 GB、B 用 20 GB，根规则累计 50 GB。接受这个边界，不增加跨入口实时协调的全组总上限。

本决定扩展 ADR-0001／0002 中单机端口转发的范围：新模式的最终分流器就在各入口。转发链与直接隧道原有出口分流、主机型主备转发组的既有路径继续按各自决定执行；新入口组同时接收流量，不使用“一个当前入口”的主备选择方式。

## 入口分别确认，DDNS 分别判断

延续 [ADR-0006](0006-sni-group-ddns-uses-confirmed-entry-health.md)：不逐条等待 SNI 落地探测结果；落地探测缺失、过期或失败，不能单独挡入口、卡 DDNS 或触发整组切换。仍须逐入口确认在线、当前完整分流配置实际生效、已开启的国内检测与设置中的观察等待。同组普通规则继续执行原有目标检测。

入口组被多个 SNI 资源引用时，确认涵盖该入口所有应运行的相关分流配置，包含域名、目标、端口及限制，并排除应撤销却仍在运行的旧内容。A 已完整且观察满足、B 少一个域名时，A 可发布、B 继续等待；A／AAAA 发布所有合格地址。CNAME 继续只有一个目标。

缺少落地检测记录与缺少实际生效配置分开判断。目标改动、离线重启或确认过期后仍须重新确认当前配置，不能凭保存成功、存在监听、曾经运行或版本号相同宣布就绪。
