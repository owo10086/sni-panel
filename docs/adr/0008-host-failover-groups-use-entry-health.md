# 主机型主备转发组按入口健康选择并更新解析

**状态：已采用并实现，对应面板 3.4.1。2026-10-19 用户选择三项推荐，要求不要扩大范围，并授权推送发布新版。自动验证与独立复核通过；生产部署及人工验收另行确认。**

**2026-10-28 收窄：** “保留故障与恢复观察”不适用于管理员调整引起的规则重新下发，移除当前入口改为先接后断，见 [ADR-0010](0010-host-failover-group-edits-switch-without-recovery-wait.md)。

主机型主备转发组按入口自身的运行与健康情况选成员。普通业务目标检测缺失、过期或失败，不单独阻止选入口、阻塞组域名解析或触发整组切换；目标检测继续用于每条规则的延迟、故障展示、历史与排查。本决定扩展 ADR-0006 中主机型主备组的普通部分，包括纯普通规则及 SNI 混合组。

例如，44 条规则中 20 个业务目标不可达、24 个正常，只要优先级较高的入口自身转发准备好、已开启的入口检测通过且既有观察条件满足，仍可由它承接组入口；那 20 条继续显示失败。切换入口未必能修复共同使用的落地服务，不能因此让其他规则也失去入口。

## 确认的三个边界

1. **仅适用于主机型主备组**：`groupType=host` 且 `groupMode=failover`。不改变多入口组、单机或多入口端口资源、出口组、转发链、隧道型主备组的策略。尤其 ADR-0007 中多入口直连资源的普通规则目标要求继续保留。
2. **关闭入口健康检测时只跳过那一项**：不检测外部指定地址，但仍要求入口在线、流量政策允许、应运行规则已运行及既有观察条件满足；不恢复业务目标门槛，不自动打开检测或更改目标。
3. **入口自身规则没有准备好仍会阻止选入**：应运行的普通规则缺少成员副本、被禁用、待删除或未运行，该入口暂不合格；优先选择自身规则准备好的成员。规则已经运行但落地端口不可达，分别判断。

## 保留的条件与代价

保留组和成员启用、有效在线判断、流量排除、故障与恢复观察、优先级、自动回切和解析发布前复核。SNI 继续要求当前完整分流配置生效及有效确认；普通规则沿用现有运行报告，不把它宣称为 SNI 完整分流确认。入口检测的完成结论不能替刚恢复的本机转发规则凑够恢复时间。

入口主动连接指定检测地址，只反映该项对外连接检查；它与公网业务端口或每条业务的实际可用性分别判断。本决定接受按入口资格维持组解析，每条业务故障继续如实呈现，不承诺更换入口能够修复目标服务。
