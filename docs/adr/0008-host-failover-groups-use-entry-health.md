# 主机型主备转发组按入口健康选择并更新解析

**状态：已采用、已随面板 3.4.1 发布。2026-10-19 用户明确要求把本次修复固化为长期约定，不采用上游逐条业务目标检测决定整组入口的逻辑。自动验证与独立复核通过；生产部署及人工验收另行确认。只有用户明确要求改变时，才调整本决定。**

**2026-10-28 收窄：** “保留故障与恢复观察”不适用于管理员调整引起的规则重新下发，移除当前入口改为先接后断，见 [ADR-0010](0010-host-failover-group-edits-switch-without-recovery-wait.md)。

主机型主备转发组按入口自身的运行与健康情况选成员。普通业务目标检测缺失、过期或失败，不单独阻止选入口、阻塞组域名解析或触发整组切换；目标检测继续用于每条规则的延迟、故障展示、历史与排查。本决定扩展 [ADR-0006](0006-sni-group-ddns-uses-confirmed-entry-health.md) 中主机型主备组的普通部分，包括纯普通规则及 SNI 混合组。

例如，44 条规则中 20 个业务目标不可达、24 个正常，只要优先级较高的入口自身转发准备好、已开启的入口检测通过且既有观察条件满足，仍可由它承接组入口；那 20 条继续显示失败。切换入口未必能修复共同使用的落地服务，不能因此让其他规则也失去入口。

## 本次修复的问题与取舍

原问题是把每条业务目标的检测结果都当作整组入口的条件。同组入口可能共用相同落地服务；一条目标端口失败、没有检测记录或记录过期，就可能让所有入口都被判为不合格，连正常业务也失去组解析。本地保留按入口自身运行与健康选择的办法，不采用上游这套逐条等待业务目标检测的通用逻辑。

例如，dmit7、dmit9、dmit10 属于同一个主机型主备组时，某条业务的目标服务停止，不应仅凭该目标失败就把三台入口都排除。入口在线、自身规则准备好，并满足已开启的入口检测和观察等待时，仍可按既有主备顺序维持解析；失败业务继续单独报错。这是判断原则示例，不代表这些主机已升级或该目标服务已恢复。

## 确认的三个边界

1. **仅适用于主机型主备组**：`groupType=host` 且 `groupMode=failover`。不改变多入口组、单机或多入口端口资源、出口组、转发链、隧道型主备组的策略。尤其 ADR-0007 中多入口直连资源的普通规则目标要求继续保留。
2. **关闭入口健康检测时只跳过那一项**：不检测外部指定地址，但仍要求入口在线、流量政策允许、应运行规则已运行及既有观察条件满足；不恢复业务目标门槛，不自动打开检测或更改目标。
3. **入口自身规则没有准备好仍会阻止选入**：应运行的普通规则缺少成员副本、被禁用、待删除或未运行，该入口暂不合格；优先选择自身规则准备好的成员。规则已经运行但落地端口不可达，分别判断。

## 保留的条件与代价

保留组和成员启用、有效在线判断、流量排除、故障与恢复观察、优先级、自动回切和解析发布前复核。SNI 继续要求当前完整分流配置生效及有效确认；普通规则沿用现有运行报告，不把它宣称为 SNI 完整分流确认。入口检测的完成结论不能替刚恢复的本机转发规则凑够恢复时间。

入口主动连接指定检测地址，只反映该项对外连接检查；它与公网业务端口或每条业务的实际可用性分别判断。本决定接受按入口资格维持组解析，每条业务故障继续如实呈现，不承诺更换入口能够修复目标服务。

## 两项配套修补必须保留

1. **故障等待在面板重启后接着计算。** 保存的是同一成员、同一普通规则、同一当前副本自身未运行的故障起点；持续故障不能因为重启重新等一轮。另一条规则、另一份副本、入口检测或成员总故障的时间不能拿来凑数。规则恢复或不再需要时清掉对应记录，成员或组删除时一并清理。恢复观察仍须满足原有等待，重启不能提前回切。
2. **待删除旧副本不能遮挡当前有效副本。** 普通规则从 A 组移到 B 组再移回 A 组时，入口资格使用当前有效副本，跳过待删除的旧副本；新副本按自己的状态和时间判断。这个处理仅限本决定中的普通规则选择，SNI 仍检查完整副本和分流配置，确认旧域名已经撤除。

例如，故障等待设为 10 秒，某条入口规则持续未运行，已等 9 秒后重启面板，应接着累计剩余时间；另一条规则或新副本刚开始故障，仍从自己的起点等待。

## 后续上游合并与审查

上游涉及组健康判断、目标探测、检测结果有效期、规则副本、成员同步、观察计时或 DDNS 的改动，都须按本决定兼容合入。不能整段覆盖本地入口判断，也不能借“跟随上游”“统一检测逻辑”把业务目标门槛加回来。合并说明应写明相关上游逻辑如何按本地决定处理。

合并或修改后的核对记录须覆盖以下结果；具体需要运行的回归按改动涉及的范围选择：

| 场景 | 必须保留的结果 |
| --- | --- |
| 普通业务目标失败、没有报告或报告过期 | 不单独排除整组入口、不阻塞 DDNS、不触发整组切换；逐条故障仍展示 |
| 关闭入口健康检测 | 只跳过该项，不恢复业务目标门槛 |
| 入口离线、流量政策排除、应运行规则未运行、已开启的入口检测不合格 | 仍按原有观察与主备规则处理入口资格 |
| SNI 当前完整分流配置缺失、失效或未确认 | 仍阻止该入口取得资格；目标检测结果不能代替完整配置确认 |
| 入口普通规则故障期间重启，或更换规则／副本 | 同一故障接续自己的时间，新故障不借用其他时间；恢复等待不能跳过 |
| 普通规则移组再移回，旧副本仍待删除 | 当前已运行副本能正常参与选择，SNI 旧配置撤除检查继续执行 |
| 发布 DDNS 前 | 复查候选成员当前入口资格及恢复等待，不重新加入业务目标门槛 |
| 多入口组、端口资源、出口组、转发链、隧道型主备组 | 继续各自既有判断，不扩大本决定的适用范围 |

本次实现与回归入口为 [组判断代码](../../server/repositories/forwardGroupRepository.ts) 和 [主备组回归](../../server/forwardGroupFailover.test.ts)；发布结果见 [3.4.1 版本说明](../guide/releases.md) 与 [正式发布页](https://github.com/owo10086/sni-panel/releases/tag/v3.4.1)。后续重构可以调整代码位置和写法，但必须保留本决定的行为与边界。
