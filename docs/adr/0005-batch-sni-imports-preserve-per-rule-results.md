# SNI 导入集中保存，保留逐项结果

当前 SNI 批量导入逐条创建，并反复整理同一组已有规则和成员副本。按用户要求，借鉴 Nekopass 的整批提交与集中保存方式，在保存结束前统一整理受影响的配置，以减少重复工作；沿用本项目逐项成功失败的约定，能够归属到单条的错误只撤回该条，最终公共保存失败则不确认尚未完成的新增，避免留下半套配置。

该方案覆盖现有全部 SNI 导入，保存完成与入口实际生效分别确认。按用户最后明确的范围，本轮不引入批次持久化、结果找回、重启续做或新的输入容错规则。完整范围与验证要求已通过 to-spec 整理到[仓库中的正式规格](https://github.com/owo10086/sni-panel/blob/main/.scratch/2026-10-15_%E6%9C%8D%E5%8A%A1%E7%AB%AF%E6%89%B9%E9%87%8F%E5%AF%BC%E5%85%A5/spec.md)；本记录确认设计方向，实际实现和检查结果以规格所链接的交付记录为准。

2026-10-15 后续范围更新：用户明确要求全部转发规则批量导入整批保存，普通规则与混合文件因此纳入[修订规格](../../.scratch/2026-10-15_服务端批量导入/spec.md)，并确认不设固定耗时门槛、混合文件按原始顺序处理额度和端口竞争。本记录上文保留原 SNI 阶段的决定；逐项结果与保存、生效分开继续适用。用户随后授权实施，新范围的本地实现与检查已完成，见[全部导入实施记录](../../.scratch/2026-10-15_服务端批量导入/全部导入实施记录.md)；本轮发布、生产验证及人工验收尚未执行。批次持久化等原有排除继续有效。
