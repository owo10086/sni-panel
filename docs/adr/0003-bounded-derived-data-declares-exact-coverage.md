# 有上限的派生数据按同一维度裁剪和声明覆盖

Agent 曾上报整台主机的监听记录，优先保留受管监听和常见端口，再按端口号声明已覆盖的范围。裁剪顺序与覆盖声明采用不同维度：即使某个较小端口的记录被丢弃，该端口仍可能落在声明范围内。面板会把该端口没有记录解释为空闲，或者把真正需要的端口长期视为未经核实。这类错误不会触发协议报错，只会让占用警告安静地消失。

## Decision

所有有体积上限的派生数据，都必须让裁剪单位与覆盖声明单位相同。本次端口占用上报以端口为单位收录监听，同时逐项声明已核实的端口和协议；超限时整端口退出监听与覆盖集合。未出现在集合中的端口只能得到未经核实的结果。

## Consequences

新增没有监听的规则端口也会改变覆盖集合和签名。单端口记录过多或整份上报触顶时，面板不会把缺失记录误读为空闲。上限依然存在，无法核实的端口需等待后续有效上报。
