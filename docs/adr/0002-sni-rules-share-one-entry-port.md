# SNI 分流规则共用同一个入口端口

ForwardX 一直强制同一主机上的源端口唯一（`isPortUsedOnHost`）。SNI 分流的全部意义是把「一个落地一个端口」压成「一个端口多个落地」，因此我们为带 SNI 域名的规则放开这条约束：同主机同端口可以并存多条 SNI 分流规则，只要它们的域名（规范化后）互不相同。

## Consequences

**未匹配一律断开，不允许兜底。** 域名不在表里、不带 SNI、不是 TLS、握手没在窗口内收完——四种情况全部断开连接。一旦某个端口被 SNI 分流规则占用，就不允许再建普通规则监听它。代价是这个端口对外表现为「只对特定域名有反应」；换来的是配错一个字母立刻可见，而不是把流量安静地送到别处。这类静默错配的症状和原因隔得极远，排查成本远高于它省下的配置便利。

**运行时的爆炸半径必须收窄。** 原本一条规则一个进程，重启只影响自己；现在多条规则共用一个分流器进程，沿用「配置变更即重启」会让每次改动踢掉该端口上的全部连接。因此分流器必须支持路由表热更新——换表不动监听 socket，新增规则不断任何连接，改某条的落地只掉这一条的既有连接。

**入口侧的按规则计量失效。** 计数链靠 (监听端口, 目标 IP, 目标端口) 三元组区分规则，而 SNI 规则在入口侧这三项完全相同。参见 ADR-0001：计量、限速、连接数上限一律由出口的分流器承担。

**单条规则的「运行中」需要重新定义。** 它不再是「端口已监听」（那对同端口的所有规则是同一个答案），而是「该域名已出现在分流器当前生效的配置版本里」。
