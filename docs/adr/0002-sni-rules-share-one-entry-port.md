# SNI 分流规则共用同一个入口端口

ForwardX 一直强制同一主机上的源端口唯一（`isPortUsedOnHost`）。SNI 分流的全部意义是把「一个落地一个端口」压成「一个端口多个落地」，因此我们为带 SNI 域名的规则放开这条约束：同一入口主机和入口端口可以并存多条 SNI 分流规则，只要它们的域名（规范化后）互不相同。转发链规则可以跨链路资源共用该端口，入口分流器按域名把连接送到各条转发链自己的下一跳。

## Consequences

**未匹配一律断开，不允许兜底。** 域名不在表里、不带 SNI、不是 TLS、握手没在窗口内收完——四种情况全部断开连接。一旦某个端口被 SNI 分流规则占用，就不允许再建普通规则监听它。代价是这个端口对外表现为「只对特定域名有反应」；换来的是配错一个字母立刻可见，而不是把流量安静地送到别处。这类静默错配的症状和原因隔得极远，排查成本远高于它省下的配置便利。

**运行时的影响范围必须缩小。** 原本一条规则一个进程，重启只影响自身；现在多条规则跨转发链共用一个分流器进程，沿用「配置变更即重启」会让每次改动断开该端口上的全部连接。因此分流器必须支持分流表热更新：换表时保持监听 socket，新增规则保持既有连接，修改某条规则的目标时只断开该规则的既有连接。入口分流器的身份固定为「入口主机 + 入口端口」，不能取自组内某条规则，删除任意规则都不会改变其余规则共用的运行时身份。

**按规则计量继续由出口承担。** 同一规则可能经由入口组中的多台主机进入，在入口分别计量会产生多个统计来源。参见 ADR-0001：转发链、单机端口转发和直接隧道的计量、限速、连接数上限由出口分流器承担。

**单条规则的「运行中」需要重新定义。** 它不再是「端口已监听」，因为同一端口上的所有规则会得到相同答案。使用入口分流器的转发链 SNI 规则只有在该域名同时出现在所有相关入口分流器与出口分流器当前生效的配置版本里时，才视为运行中。

## 2026-10-10：主机型转发组沿用共享端口

同一主机型转发组的多个域名在每台启用成员上共用业务端口，最终分流器身份固定为“主机 + 业务端口 + 分流角色”。删除第一条规则不改变其余域名的监听身份；热更新只关闭变化域名的连接，最后一条规则撤除时才清理监听。域名唯一检查按入口主机执行，跨端口、跨资源生效，同一根规则的合法成员副本被排除。

主机型转发组的运行中跟随当前入口，各备用成员分别展示最新配置生效情况。不能仅凭域名存在或版本号相同判断就绪，还须比较目标、限速、连接数等内容。原有转发链继续要求相关入口和出口全部确认。各入口实际用量都汇总到根规则；按成员执行的限制是 ADR-0001 新增范围中的取舍。
