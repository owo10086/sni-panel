# 主机型转发组的管理员调整不触发恢复观察，移除当前入口先接后断

**状态：已实施，2026-10-28；发布版本待发布时补充。2026-10-28 用户明确同意，收窄 [ADR-0006](0006-sni-group-ddns-uses-confirmed-entry-health.md) 第 3 条与 [ADR-0008](0008-host-failover-groups-use-entry-health.md)“保留故障与恢复观察”的适用范围。只有用户明确要求改变时，才调整本决定。**

主机型转发组（`groupType=host`、`groupMode=failover`）中，管理员调整引起的规则重新下发不算故障：成员的规则重新运行（SNI 组为分流表重新确认）后直接合格，不再等恢复观察。移除或停用当前入口时先接后断：下一个成员合格并切换解析，再过一个解析 TTL，才撤销原入口的转发。

## 起因

2026-10-28 用户把转发组「入口-tj2直接转发」的当前入口美国9929 移除，只留新加坡lin。面板先撤销美国9929 的转发，再给新加坡lin 重新下发全部规则，又把这次重新下发当作故障，等满 120 秒恢复观察才切换解析；期间一直保留已撤销入口的地址。从保存到切换约 3 分 52 秒，两台入口约 4.5 分钟都没有该组流量记录。

## 决定

1. **管理员调整不是故障。** 新建组、增删或停用成员、调整顺序、增改删组内规则、改域名，引起的重新下发在规则重新运行后不要求恢复观察。Agent 离线、重启、重连后的恢复，确认过期，以及入口自行上报的未运行，仍按原有故障与恢复观察处理。恢复观察用于防止真实故障后的反复切换；管理员调整不来自入口环境，等待不保护任何东西。
2. **保留运行确认门槛。** 应运行的普通规则须已在该入口运行，SNI 组仍须确认当前完整分流配置生效。实测这一步在秒级以内；去掉它节省有限，却可能把解析发布到没有准备好的入口。
3. **移除当前入口先接后断。** 原入口在解析切走且经过一个 TTL 前继续转发，因此切换前保留它的地址仍然有效。移除非当前成员、移除唯一成员时照常立即撤销。

## 不采用的做法

- **调整后不等任何条件立即解析**：省下的是秒级的运行确认，代价是下发失败时解析指向不工作的入口，并推翻 ADR-0006 的完整配置要求。
- **调小组的恢复时间**：能缩短本次等待，但同时削弱真实故障的防抖。
- **先断后接并保留旧地址**：旧入口已撤销转发，保留它的地址等于断流。

## 不变的部分

入口组、出口组、转发链、端口转发资源、隧道型主备组不在本决定范围内。ADR-0008 的入口健康判断、ADR-0006 的 SNI 完整配置确认、优先级、自动回切和发布解析前复核继续有效。单条规则因其他原因被反复重新下发、并拖累整台入口恢复观察的问题另行处理。
