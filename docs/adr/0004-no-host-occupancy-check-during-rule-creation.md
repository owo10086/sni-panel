# 创建规则时撤除主机端口占用校验

上一版端口占用设计要求创建、修改、启用和导入规则时检查主机上的监听。持续占用检测已经覆盖规则创建后的变化，用户态转发还会在绑定失败时上报规则级错误。创建时的监听检查需要确认弹窗、额外的输入状态与占用者记忆，无法保证创建以后端口仍保持原状。

## Decision

创建和修改路径只检查面板数据库中的端口冲突、端口范围与套餐限制。主机监听占用不会阻止创建、要求确认，也不会影响随机端口分配。内核转发仅在有效上报表明端口有监听时显示占用警告，并将规则主状态显示为黄色；用户态转发绑定失败时显示红色运行错误及具体原因。已停用规则保持灰色，已有明确运行错误不降为占用警告。

占用警告和绑定失败参与规则主状态判断，优先于成功探测、运行上报和历史绿色缓存。端口占用警告和绑定失败仅依据当前有效诊断显示，不能仅凭历史缓存恢复；诊断解除后按当前运行状态重新显示。

## Consequences

规则可以先创建，再根据持续检测警告或运行错误处理冲突。重新引入创建时的主机端口校验之前，必须先回答：它相对于“先创建，发生冲突后再报告错误”额外提供了什么价值，并验证该价值足以承担状态同步与多入口校验的成本。
