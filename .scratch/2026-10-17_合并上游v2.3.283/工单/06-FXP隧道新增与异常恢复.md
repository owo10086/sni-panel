## 使用例子

A、B 正在运行，C 已在主机上加入但面板没收到回复；再次核对或重试后只保留一份 C，A、B 持续可用，不能因为超时把正在使用的准备配置删掉。

## 验收条件

- [ ] V1 和 V2 的纯新增分别通过实际程序完成，未变化的健康监听、进程、TCP 连接与适用的 UDP 会话保留。
- [ ] 新增前检查全部准备，确定冲突或准备失败时只撤回本次尚未完成的新增，保留其他已存在业务。
- [ ] 重复发送同一份新增配置不重复建立监听；并发批次或较旧快照晚到，不吞掉其他批次已经成功的新增。
- [ ] 明确的停用和删除继续按当前保存的配置生效，不因合并新增快照恢复已经撤销的规则。
- [ ] 实际应用成功但回复丢失、运行配置文件写入失败或后续保存失败时，保留结果不确定所需的监听和 V2 准备，通过核对、重试继续处理。
- [ ] 必要的 V2 中间转发准备在结果确认后正确回收，重复重试不无限累积，也不提前断开仍被实际业务使用的准备。
- [ ] 旧 FXP 缺少局部新增入口时明确拒绝本次新增，保留旧连接；新 Agent 配旧 FXP 不能因版本数字相同误判能力。
- [ ] 只恢复已经停止且仍应存在的监听，不重建其余健康监听；修改、删除、首次启用及更新程序的影响按实际方式说明。
- [ ] 局部控制限本机使用，不替代现有 SNI 分流表更新，不扩大 SNI 支持范围，不公开凭据或完整配置。
- [ ] 保留整批导入、逐项结果及保存与应用的区分；已经保存但未运行的规则保留可理解的待同步或失败反馈。
- [ ] 独立验证 V1、V2、TCP、适用的 UDP、监听冲突、回复丢失、重复请求、较旧批次和文件保存失败，提供真实程序、连接及文件身份依据。
