# 04 — 数据库故障提示、恢复与 TLS 配置缓存

Status: complete

**Blocked by:** 01

**目标：** 完整接纳上游数据库不可用时的服务保护、页面提示和自动恢复，使前后端及后台任务对数据库状态保持一致。

规格见[数据库故障提示与恢复](../spec.md)。范围包括健康状态与探测模块、数据库运行层、HTTP/tRPC/Agent 异常处理、后台调度、前端健康提示和 `server/panelSsl.ts`。

## 实施范围

- [x] 故障期间保留静态页面和资源访问，展示脱敏原因、错误码和排查建议；保留登录 Cookie，连接恢复后自动恢复页面。
- [x] 处理 PostgreSQL 空闲连接错误、Agent 异步数据库读取和相关请求错误，避免未处理异常导致面板进程退出。
- [x] 接入默认每 15 秒且不重叠的健康检查，独立诊断连接设置连接和查询超时，不在故障期间累积探测任务。
- [x] 故障期间暂停数据库相关后台任务，恢复后避免重复注册定时器或重复启动后台工作。
- [x] 区分连接故障、初始化失败及 SQLite 只读、空间不足、损坏等状态；不能把一次读取成功视为所有故障已恢复。
- [x] 接纳已验证 TLS 设置缓存，配置目录持久化 `panel-ssl-runtime.json`、权限 `0600`，数据库不可用时按上游规则读取缓存或环境设置。
- [x] PEM 私钥及数据库凭据不进入公开提示、日志、版本库或诊断产物；缓存写入失败有可理解的日志，不能把未保存缓存当作已具备重启恢复能力。

## 验收条件

- 覆盖首次启动连接失败、正常运行中断连、连接恢复、PostgreSQL 空闲连接报错以及 Agent 请求期间数据库失败。
- 观察进程存活、静态资源可用、故障页内容、Cookie 保留、前端恢复和后台任务恢复，而不仅检查内部状态变量。
- 覆盖探测慢于调度间隔时不重叠，连接/查询超时后可继续下一轮；初始化或存储错误不被错误清除。
- 在隔离环境中用有效 TLS 缓存重启，确认数据库不可用期间的监听协议符合预期；覆盖缺失、损坏缓存和权限检查，不输出证书私钥。
- 在 `合并记录.md` 记录实际验证的 SQLite/MySQL/PostgreSQL 场景与未覆盖项。
