# 07 — 上线验收与统一发布

Status: ready-for-agent

**目标：** 对合并产物完成上线验收，再将上游集成与已经上线的来源限制修复统一发布到 sni-panel。

规格见[验收与发布安排](../spec.md)。此前“先提交最新代码”的步骤已在 `67fa23d` 完成，不重复发布来源限制修复。

## 上线验收

- [ ] 记录当前生产运行镜像、实际产物、版本和数据库状态，保存受限的配置与数据库备份，准备基于实际镜像/产物标识的回退；考虑本次增加的数据库字段。
- [ ] 从 06 通过的提交构建并部署候选产物，记录哈希和部署时间。发布前的就地验收应注明候选代码身份，不能仅凭仍显示的旧版本号识别构建。
- [ ] 验证登录、已有普通转发与 SNI 链路、来源限制清理状态、按用户管理规则及已授权的普通用户启停/删除行为。
- [ ] 流量故障转移在专用验收资源上验证，默认关闭的生产主机保持既有行为；数据库破坏性故障验证沿用隔离环境证据，不在生产制造损坏。
- [ ] 记录实际覆盖的拓扑和剩余场景；此前没有实测的真实公网换 IP、双栈或多跳场景不能因为用户反馈“功能正常”就写成已验证。
- [ ] 在本目录建立 `线上验收记录.md`，记录通过项、异常、恢复情况及回退位置，备份中的密钥、数据库和环境文件不进入仓库。

## 统一发布

- [ ] 验收通过后，按实际改动范围应用本项目版本规则：仅面板变化递增补丁位，涉及 Agent/FXP 时执行共同小版本规则；APK Release 跟随面板，Android APP 按自身实际变化处理。
- [ ] 完成发布说明、版本常量及版本校验；涉及最终构建的改动完成必要验证后提交。
- [ ] 将 `main` 和对应版本标签一并推送到 `sni-panel`，使用其发布与镜像构建流程；不向 `origin` 推送。
- [ ] 等待相关发布任务完成，核对 release、镜像、安装升级资产均来自 sni-panel。
- [ ] 部署正式版本镜像并核对版本、登录、关键转发及来源规则清理状态，确认正式产物与已验收代码对应。
- [ ] 在规格和工单中记录最终提交、版本、验证结果及实际未覆盖项，再标记完成。
