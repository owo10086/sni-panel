## 全部产品改动

### 主机流量故障转移

接纳主机级开关及百分比阈值。默认关闭，默认阈值 100%，有效范围 1—100；只有开启且主机流量限额大于零时才生效。流量使用主机已有计量口径。

达到阈值后，暂时排除主机参与转发组、故障转移以及隧道入口和出口组，保留保存的成员、端口和启用配置。流量重置或关闭开关后恢复参与资格，实际转发继续受其他既有运行条件约束。固定链必要节点不可用时暂停受影响的链，不任意跳过固定中继。

按上游自动同步逻辑增加主机字段 `trafficFailoverEnabled`、`trafficFailoverThresholdPercent`、`trafficFailoverExcluded` 及相关索引，旧主机默认不启用。运行时排除结果不能回写成删除成员或重新分配端口。

与本地 SNI 组合时必须满足：

1. 入口组 A、B 连接同一固定链，只有 A 超限时，仅撤除 A 的入口运行规则，B 和共同出口继续服务。
2. 固定中继或出口超限时，暂停经过该链的入口；同一入口端口上其他正常链的域名继续服务。
3. 先应用运行时排除，再构建入口、出口的 SNI 路由表；更新或撤除某条链时，不得误删其他域名仍在使用的共享监听。
4. 流量重置或关闭开关后，按原成员与端口恢复，不要求重建规则。

### 数据库故障提示与恢复

完整接纳故障页、健康状态、后端异常处理和后台任务协调逻辑。数据库不可用时，静态页面和故障提示仍可访问，提示包含脱敏原因、错误码及排查建议；保留登录 Cookie，连接恢复后自动恢复页面。

处理 PostgreSQL 空闲连接错误和 Agent 异步数据库读取异常，避免因此导致进程退出。健康检查默认每 15 秒进行且不重叠，独立诊断连接设置连接和查询超时，防止故障时在业务连接池排队。数据库相关定时任务在故障期间暂停，恢复后按既有调度继续。

保留上游对初始化失败及 SQLite 只读、空间不足、损坏等错误的区分；一次读取探测成功不能把这些错误误报为已经修复。

接纳已验证面板 TLS 配置缓存 `panel-ssl-runtime.json`，位于数据库配置文件所在目录，用于数据库不可用时启动。缓存权限为 `0600`；PEM 模式可能包含私钥，应随受限配置目录持久化和备份，不进入版本库、日志或公开诊断信息。

### 所选用户、SNI 权限与规则操作

管理员新增、复制、导入规则时，规则归当前选定用户；选择“所有用户”时默认归管理员本人。编辑现有规则不改变归属。目标用户的资源访问、套餐状态、余额、端口范围和规则、端口额度按上游逻辑校验。

SNI 需要明确区分两个身份：**操作人**是实际登录者，用于判断管理员权限；**归属用户**决定规则归谁以及资源和额度校验。不能通过把上下文的登录用户整体替换为归属用户来处理所有检查。

| SNI 操作 | 实际管理员 | 普通归属用户 |
| --- | --- | --- |
| 创建、复制、导入 | 可为自己或所选用户操作，并校验归属用户的限制 | 不允许 |
| 修改已有规则配置，包括仅修改其他配置字段 | 允许，沿用既有管理权限 | 不允许 |
| 启用、停用 | 沿用既有管理权限 | 允许操作自己的规则；重新启用检查当前资源权限、套餐状态和额度 |
| 删除根规则或模板 | 沿用既有管理权限 | 允许删除自己的规则 |
| 查看及重置统计 | 按已有权限及本规格的用户范围 | 仅自己的规则 |

直接隧道、转发组模板及单条、批量入口执行相同的权限规则。系统生成的子规则继续由根规则或模板管理，不能直接操作子规则绕过限制。前端按钮可用状态与后端鉴权应一致；批量入口仍使用既有逐项结果和错误提示方式。

沿用现有额度算法：系统子规则不重复计入规则数量，端口额度按归属用户的入口端口去重。同一入口端口的多条 SNI 规则分别占规则额度，共用一个端口额度。创建预留按实际新增端口计算，不能在复用已有端口时再次占用一份端口额度。

现有停用规则仍计入额度，重新启用不能再按新增规则重复计数；用户恰好达到上限时，不应因此无法恢复已有规则。套餐过期、余额不足或资源授权撤销不阻止用户停用、删除自己的规则；完整使用资格检查发生在重新启用时。

本地行内选择、全选、批量修改、删除和复制能力保留；普通用户的批量入口也须遵循上表，不能借普通字段修改或混合选中绕过 SNI 配置权限。

### 重置全部统计与有效端口策略

“重置全部统计”按当前用户范围覆盖所有分页，不受搜索、链路、规则类别或行内勾选影响：

| 当前范围 | 重置对象 |
| --- | --- |
| 管理员选择自己 | 管理员自己的全部规则 |
| 管理员选择所有用户 | 所有用户的全部规则 |
| 管理员选择指定用户 | 指定用户的全部规则 |
| 普通用户 | 自己的全部规则 |

确认提示说明实际范围。沿用已有模板展开和关联统计清理，不新增“重置选中统计”操作。规则统计清理不修改账户套餐已用流量、余额或按量计费记录。

规则编辑的可用端口提示采用服务端有效策略，合并主机、隧道、转发组及用户套餐限制。保留 SNI 强制 TCP、同端口复用等规则。此项不会恢复本项目此前撤除的创建时主机监听占用拦截；配置端口范围与真实监听占用继续按各自已有契约处理。

## 需要保留的本地能力

SNI 的可读明文域名分流及 ECH 兼容、未知域名和无 SNI 拒绝、入口和出口共享端口、按规则限速与连接数限制、出口计量及状态判断继续有效。

保留 `0ec1b0b` 的来源限制删除与迁移机制：下发空来源名单、清理本项目标记的 nftables/iptables/ip6tables 旧规则、成功回执确认和失败后的正常重试。不能因合并上游心跳或数据库故障处理而恢复来源名单或漏掉迁移。

安装、升级、发布和镜像保持 sni-panel 来源及现有 amd64 发布约定。上游版本常量作为上游发布元数据处理，按本项目版本规则维护面板、Agent、FXP、APK 相关常量，避免整体覆盖。已删除的 Android 发布密钥不恢复。

## 合并完成的验收条件

以下验收条件已经在隔离环境完成实现验证；实际覆盖范围见[验证记录](验证记录.md)，线上验收和发布由工单 07 继续：

3. SNI 普通归属用户可停用、重新启用和删除自己的根规则/模板；重新启用能拒绝失效的权限或额度，不能修改配置或管理其他用户规则。覆盖直接隧道、转发组及单条、批量入口；覆盖额度恰好已满时恢复原规则、同一用户复用已有 SNI 端口，以及资格失效后仍可停用和删除。
4. 流量开关默认不影响旧主机；按主机计量口径到达阈值后临时排除，恢复条件满足后重新参与。覆盖共享 SNI 入口、固定中继、出口及同端口其他健康链，确认保存的成员和端口不被修改。
5. 数据库启动时不可用、运行中断连及连接恢复均有可观察结果；故障页不泄漏凭据、Cookie 保留、进程和静态资源可用、检查不累积，后台任务和 TLS 缓存按约定工作。
6. 全部统计重置覆盖目标用户的所有分页，忽略列表筛选和勾选，不重置账户套餐用量或余额；端口提示与保存校验一致，并保留 SNI 端口复用。
7. 验证码/2FA 清理、iperf3 安装失败和提示框主题修复达到上游预期。
8. 本地 SNI 来源规则迁移、失败重试、真实 TLS 分流、批量操作和安装升级来源无回归。线上未覆盖的拓扑与场景应记录为未验证，不沿用旧结果声称已验证合并产物。
