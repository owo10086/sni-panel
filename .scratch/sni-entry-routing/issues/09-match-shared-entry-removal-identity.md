# 09 — 用 Agent 自己的端口身份撤除共享入口分流器

**What to build:** 面板判定某个入口端口不该再运行分流器时（入口 Agent 版本不足、规则全部停用或删除），该端口上的监听真的停下来，而不是被 Agent 当作过期动作跳过。撤除动作携带的规则身份，取自 Agent 本次心跳上报的本地运行时状态，而不是面板侧算出来的代表规则。

**Blocked by:** None — can start immediately。02 的最后一条验收与 08 的发布检查都在等它。

**Status:** claimed

## 背景：两侧的身份维度对不上

共享入口端口之前，一个入口端口上只有一条规则，「面板认为谁占着这个端口」和「Agent 本地记着谁占着这个端口」必然是同一条，从不分叉。跨转发链共用入口端口之后：

- 面板发撤除动作时，用的是该端口上**编号最小的代表规则**
- Agent 记录端口归属时，按「端口 + 协议」做键，**一个端口只保留最后写入的那条**

同一个端口上有六条规则时，面板说编号 `101`，Agent 本地记的是 `311`。Agent 的端口保护条件比对两者不相等，判定这是一条指向已被重新分配端口的过期撤除，于是跳过——监听继续跑，面板却以为已经停了。

这与端口占用检测那次的根因同形：**一份数据被两侧各自按不同维度取身份**。修法也同形：不让面板去猜 Agent 记的是谁，直接用 Agent 报上来的那个。

## 为什么必须在面板侧修

这条路径要处理的场景，按定义就是**入口 Agent 版本偏低**。任何需要发新版 Agent 才能生效的修法都够不着它。Agent 每次心跳本来就上报了本地每个端口对应的运行时状态，面板在生成撤除动作的同一处就能读到，不必新增上报字段，也不必改动 Agent。

## 验收

- [ ] 入口分流器的撤除动作，其规则身份取自 Agent 本次心跳上报的该端口本地运行时状态
- [ ] 面板不再凭代表规则凭空构造一份本地运行时状态来发撤除
- [ ] 同一入口端口上存在多条来自不同转发链的 SNI 分流规则时，撤除动作被 Agent 执行，该端口的分流器监听停止
- [ ] 原代表规则被删除、代表规则改为另一条之后，撤除仍然生效
- [ ] Agent 未上报该端口的本地运行时状态时，撤除动作仍然发出，不因为缺少本地记录而沉默跳过
- [ ] 同一端口上同时存在多条本地运行时记录时，每一条都得到对应的撤除动作
- [ ] 入口 Agent 版本恢复到最低要求之后，启用中的规则重新生成入口分流器配置，监听恢复
- [ ] 撤除只作用于该入口端口，同一台主机上的普通转发规则、单机端口转发配置和其它端口的监听不受影响
- [ ] 出口分流器、端口转发资源与隧道的撤除路径行为完全不变
- [ ] 心跳测试先复现失败（异常版本下该端口的监听未被撤除），再验证修正后撤除成立
- [ ] 心跳测试覆盖：代表规则变更后的撤除、Agent 未上报本地状态、同端口多条本地记录、版本恢复后的重新下发

## 不在本单范围

- **Agent 端口归属按「端口 + 协议」只保留一条的记账方式不动。** 改它要发新版 Agent，而本单要处理的恰恰是老版本 Agent；只要面板按 Agent 报上来的身份发撤除，这套记账就够用。
- 真实 Linux 主机上的首次升级切换与长连接验证，仍由 08 的部署验证覆盖。

3. **缺少本地记录时改用规则编号为 0 的端口级分流器撤除动作**，替换原先回退到代表规则的做法。

第 3 条的理由不止于「换一种回退」：面板把**全部**动作喂进一个端口级动作记录，条件是「规则编号大于 0 或状态类型为 rule」；孤儿清扫循环遇到已在该记录中的端口会直接跳过。原先回退到代表规则会把端口标记住，使清扫循环无法补发本地编号的撤除——兜底被自己堵死。规则编号 0 不满足该条件，等于把这条后路还回来。

**实现约束：该端口级撤除动作不得带状态类型 `rule`**，否则仍会进入端口级动作记录，改动失效。

Agent 侧两项前提已核实：过期撤除保护对规则编号小于等于 0 直接放行；分流器的运行时身份函数跳过规则编号，按角色、隧道与监听端口解析，编号 0 仍能定位到进程。

同端口发出多条撤除是安全的：不匹配的由 Agent 记日志跳过，匹配的执行；首条命中后本地端口记录被清除，其余看到无本地记录直接放行，结果幂等。

2026-09-17 更正：上一条验收原文为「孤儿清扫不会对同一端口重复补发撤除」，措辞有误，按字面执行只能靠抑制清扫来满足，已改写为上文形式。

发现的 P2 与其根因：入口版本异常分支把本地撤除的协议重写为 `tcp`，而孤儿清扫使用本地记录原本的协议算键。本地记录为 `both`、编号为 0 时，端口动作键 `<端口>:tcp` 与清扫的 `<端口>:both` 不相等，且编号 0 使规则身份键为空串，于是清扫补发第二条撤除。

**不采用「登记本轮已处理的本地记录供清扫跳过」的方案。** 内核转发的清理命令按协议逐条生成，把协议窄化为 `tcp` 会使 `both` 记录的 UDP 侧内核规则不被删除；当前正是清扫补发的那条 `both` 动作在收尾。抑制它会把一处装饰性重复变成真实泄漏。同时，在端口动作记录之外再加一套「已处理」登记，等于为同一个问题引入第三套身份机制，与本单的核心教训相悖。

**采用的修正：取消入口版本异常分支对本地撤除协议的重写，直接沿用本地记录自身的协议。** 动作协议与本地记录一致后，端口动作键与清扫算出的键天然重合，清扫自行跳过，无需新增登记；清理命令覆盖完整，不留 UDP 尾巴。本地记录缺少协议时两侧都归一化为 `both`，仍然重合。已核实：Agent 的过期撤除保护按协议重合判定，`both` 对 `both` 通过；撤除动作内 fxp 子对象的协议单独固定为 `tcp`，不受动作级协议影响，分流器行为不变。
