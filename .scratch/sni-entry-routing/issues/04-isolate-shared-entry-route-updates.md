# 04 — 让共享入口分流表更新只影响变更规则

**What to build:** 共享入口分流器以入口主机和入口端口作为稳定身份。新增、修改、停用或删除某条 SNI 分流规则时，分流表通过现有热更新机制变化，连接影响限定在实际发生变化的规则。

**Blocked by:** 03 — 允许多条转发链共用一个入口端口

**Status:** resolved

- [x] 入口分流器的运行时身份只由入口主机和入口端口决定，不取自组内任意一条规则
- [x] 删除编号最小的规则后，受管运行时身份、监听端口和静态配置保持不变，动态分流表只删除对应路由
- [x] 新增一条域名路由时不关闭该入口端口上的任何既有连接，包括属于其它转发链的连接
- [x] 停用或删除一条规则时只关闭命中该规则的既有连接，其它域名连接保持
- [x] 修改落地机地址或端口时，入口分流表和入口运行时保持不变，出口分流器只关闭对应规则的既有连接
- [x] 分流表版本保持单调递增，热更新不重建监听 socket，也不重启分流器进程
- [x] 新配置校验失败时继续使用上一份有效配置，并向面板报告失败原因
- [x] Agent 心跳测试覆盖新增路由、删除首条规则、删除其它组内 SNI 规则、目标变化及配置失败后的有效版本保持

## Comments

2026-09-17 实施摘要：核对稳定入口身份及既有分流器热更新机制。心跳测试验证新增路由和删除首条规则时静态配置保持相同；补充经规则接口修改落地机后入口配置保持相同的检查，以及配置失败后有效版本仍为 `2`、域名仍生效、错误为 `invalid route table` 的检查。SNI 心跳测试与既有 Go 热更新、连接保持和无效配置测试通过；真实部署长连接验证仍须在 Linux 主机执行。
