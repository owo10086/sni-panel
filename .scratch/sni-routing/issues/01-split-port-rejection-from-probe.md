# 01 — 分离端口占用的「拒绝」与「探测」两种语义

**What to build:** 纯重构，对外零行为变化。目前判断端口是否被占用的那条路径同时服务两种完全不同的问题——「管理员显式指定了这个端口，能不能用」和「我要自动分配一个端口，这个候选空不空」。这两者现在共用同一个答案，但在引入 SNI 分流后必须分道扬镳：拒绝路径要允许多条 SNI 分流规则共用同一入口端口，而分配探测路径必须保持保守，把已被分流组占用的端口继续视为不可用，否则自动分配会把这个端口发给别的规则或隧道出口。

先把这个区分显式化，后面那张放开端口共用的工单就只需要动拒绝路径，不会误伤分配探测。

**Blocked by:** None — can start immediately

**Status:** ready-for-agent

- [ ] 拒绝路径与分配探测路径在代码上是两个可分别调用的入口，调用者的意图从调用点即可看出
- [ ] 现有全部端口相关测试保持绿，无一处断言需要修改
- [ ] 转发规则、隧道出口端口、转发组的端口分配行为与重构前逐字节一致
- [ ] 重构后新增一处测试，锁定「分配探测把任何已占用端口视为不可用」这条不变式，防止后续放开拒绝路径时被顺手改掉
