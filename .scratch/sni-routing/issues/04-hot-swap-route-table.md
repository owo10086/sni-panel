# 04 — 分流表热更新，变更只影响被改的那条规则

**What to build:** 管理员改动其中一条 SNI 分流规则时，同一端口上其余规则的在线连接完全不受影响。

上百条规则共用一个分流器进程，若沿用「配置变更即重启运行时」的做法，每次加一台落地机或改一个地址都会把这个端口上的全部客户踢下线。因此分流器必须支持在不重建监听、不重启进程的前提下换掉分流表，并且能按规则定向关闭连接。

**Blocked by:** 03（需要多条规则才能验证爆炸半径）

**Status:** ready-for-agent

- [ ] 在持续跑着连接的前提下新增一条规则，**一条既有连接都不断**
- [ ] 改某条规则的落地机地址或端口，**只有该条规则**的既有连接被断开，其余规则无感
- [ ] 客户端重连后立刻走新的落地机地址，不存在「改了看不到效果」
- [ ] 停用或删除某条规则，只断开该条规则的连接
- [ ] 改动其它规则时，本规则的连接不受影响
- [ ] 下发一份校验不通过的配置时，**正在生效的那份保持不变**，业务无感，失败原因回报面板
- [ ] 配置投递不经由「配置内容变化即重启受管服务」的路径
- [ ] 分流表携带单调递增的配置版本号，分流器持有当前生效版本
