# 02 — 撤除创建路径上的主机端口占用校验

**What to build:** 删除转发规则创建、修改、启用与批量导入路径上一切与**主机端口占用**有关的校验与提示，回到只依据面板数据库判断的行为。面板数据库层面的端口唯一性与端口范围校验原样保留。

**Blocked by:** None — 与 01 无代码依赖，可并行；但它删掉 01 的一部分消费者，合并时注意不要互相踩

**Status:** ready-for-agent

## 删除

- [ ] 源端口输入框旁的 可用 / 有占用 / 未核实 标记，及其下方的说明文字与占用者明细
- [ ] 提交时因外部占用而拒绝创建（用户态转发）
- [ ] 提交时因外部占用而要求显式确认（内核转发），以及承载它的确认入参与前端确认弹窗
- [ ] 批量导入中的同类检查，导入结果不再因主机端口占用而改变
- [ ] 随机端口分配对主机已知占用端口的避让
- [ ] 修改规则源端口、启用此前停用的规则时的同类检查
- [ ] 端口校验接口返回值中与主机占用有关的字段，以及为它新增的第三态
- [ ] **确认记忆那套机制整体删除**：`server/rulePortValidation.ts` 里的 `confirmedRuleOwners` 及 `rememberRulePortOwner` / `seedRulePortOwner` / `rulePortOwnerChanged`。它存在的唯一目的是「确认过的警告不要在每次编辑规则时重复弹」，确认流程一删它就是死代码；唯一的决策消费者在 `server/routers/rules.crud.ts` 的更新路径，种子由 `server/rulePortOccupancy.ts` 在处理内核转发规则时播下——两处调用一并清掉

## 保留

- [ ] 面板数据库层面的端口唯一性校验：同一主机同一端口不能建两条规则、隧道端口冲突、SNI 分流规则共用入口端口的既有放行规则（ADR-0002）
- [ ] 端口范围策略与套餐端口范围校验
- [ ] 受管运行时 bind 失败时的规则级错误回报（由 Agent 识别「地址已被占用」并回报，规则卡片显示红色运行失败并点名占用者）

## 不做

- [ ] 不以任何形式（往返问答、按需探测、预热缓存）为创建路径重新引入主机端口探测

## 测试

- [ ] 创建、更新、启用规则以及批量导入**不再因主机端口占用被拒绝或要求确认**，即使该端口上确实存在外部监听
- [ ] 面板数据库层面的端口唯一性校验仍然拒绝重复端口
- [ ] 端口范围与套餐端口范围校验行为不变
- [ ] 随机端口分配仍避开面板已知占用的端口，不再依赖主机上报的数据
- [ ] 与主机占用有关的断言从 `server/rulesPortAvailability.test.ts` 中移除，其余断言保持通过
- [ ] `server/sniRuleRouter.test.ts` 同样直接断言 `occupancy` 的 `unverified` / `blocked` / `free`，必然一起红——与主机占用有关的断言一并移除，SNI 共用入口端口本身的断言保留
