## Problem Statement

本地 sni-panel 已累计兼容上游 v2.3.286，并在其后保留了 SNI 独立分类、入口健康与 DDNS、规则运行和计费收尾等修复。需要累计兼容 v2.3.287 和 v2.3.288 的网页、服务端、Agent 和 FXP 新能力，而不覆盖这些本地行为，也不恢复原生应用或作者赞助入口。不能仅凭上游版本间差异直接覆盖本地快照。

## Solution

以固定 v2.3.288 为唯一目标完成六步。规则页采纳上游完整调整，主机资源告警按上游逐主机设置，整机关机和 BBR 管理作为可选功能纳入；保留本地 SNI 分类与域名、入口判断、权限、计费、品牌及验证治理。普通可兼容改进直接按推荐合入；新发现的真实行为冲突按默认模式记录后等待决定。最终交付经过验证和独立点评的中文本地提交与可用人工验收环境。

## User Stories

1. 作为规则使用者，我希望创建、改名、删除和排序本账号个人分组，以便整理自己的普通和 SNI 根规则。
2. 作为规则使用者，我希望一条规则可属于多个个人组，以便按不同用途筛选。
3. 作为规则使用者，我希望筛选全部分组、指定组或未分组，并批量加入、移出或替换，以便减少重复编辑。
4. 作为管理员，我希望个人组仍按账号隔离，以免猜 ID 读取或修改其他用户的组织信息。
5. 作为规则使用者，我希望表格显示上游分组列、卡片显示标签，以便查看规则归组。
6. 作为规则使用者，我希望按账号保存列显示、顺序、宽度、拖动调整和恢复默认，并使用浮动横向滚动条，以便在长列表查看远端列。
7. 作为规则使用者，我希望采用上游卡片信息和固定控制区，以便窄屏查看与操作；额度图标仍解释独立计量口径。
8. 作为 SNI 使用者，我希望独立分类、域名列、完整异常提示以及整组排序分页继续有效，以免域名被普通规则或列偏好隐藏。
9. 作为规则使用者，我希望延迟来自当前配置及本次请求的真实结果，以免旧报告或测试失败显示成成功。
10. 作为主机管理员，我希望逐主机设置资源告警和收件人，以便按上游方式通知；未配置主机可继续回退旧全局设置。
11. 作为主机所有者，我希望按上游配置收到资源告警，以便处理负载问题；管理员仍收到有效告警。
12. 作为主机管理员，我希望明确选择是否在套餐流量达到阈值时关闭整台主机，以便限制后续用量；旧主机默认关闭。
13. 作为主机管理员，我希望按需安装 BBR 插件并明确保存才更改内核参数，以便检查、应用预设或还原，失败时回滚。
14. 作为主机使用者，我希望查看负载与可选 HTTP/HTTPS URL 探测，以便区别网络连通、服务响应和入口资格。
15. 作为隧道使用者，我希望多入口隧道当前延迟及时刷新且历史写入受节流，以便不把缺样或旧计数当作恢复。
16. 作为运维管理员，我希望按需开启北京时间前一日摘要，并仅通知管理员，以便掌握流量和实际收款。
17. 作为用户，我希望首页及运维汇总更快且按账号隔离，以便缓存不泄露数据、不掩盖权限撤销或余额变化。
18. 作为网页使用者，我希望启动品牌和导航少闪烁、可关闭动画、低高度或窄屏表单可操作，以便顺畅使用网页。
19. 作为运维使用者，我希望查看历史日期、趋势、主机和链路分类数量以及隧道详情，以便识别数据缺口和当前状态。
20. 作为安装管理员，我希望数据库切换后等待服务真正就绪，且看懂 MySQL 版本及授权失败，以便完成安装。
21. 作为 SNI 使用者，我希望落地探测缺失、过期或失败不单独卡住入口和 DDNS，而完整当前分流配置仍必须生效。
22. 作为主机型主备使用者，我希望仅按该类型既定的入口运行与健康选择，并保留故障续算、当前有效副本及发布前复核。
23. 作为计费管理员，我希望规则删除、欠费停用、迁移待结清和历史记录不因查询优化或个人组关系清理而漏算或重复结算。
24. 作为维护者，我希望保留本地安装来源、品牌及统一验证发布协议，跳过原生应用和赞助内容，以便后续维护仍可控。
25. 作为验收者，我希望知道实际检查结果和环境限制，并获得已启动的隔离网页入口，以便实际操作验收。

## Implementation Decisions

1. **固定依据与范围**：本地起点 fac8a27e738dd1992517336e505bccde5ab2f74a；唯一上游目标 v2.3.288，实际 d776443c024f3357477d6b8b23a24b77a5237bb0，标签对象 595f2ddc7d3373c77495282f0029794c32e9edc0；辅助 286 为 aca5d5dfb645393b6925f155ff7258006f46204e，287 为 ca032ef52263c7040d6ff733f087aa4ee4d9de1c。789 项本地与目标直接差异逐项按来源解释；上游累计263项变化不是覆盖全部本地差异的许可。本地独有137项、旧上游独有原生及本地替代资产不盲目删除或补回。
2. **授权与旧工作区**：用户明确调用 sni-flow 已授权本轮六步及中文本地提交，不再索要实施许可。默认模式未切换为执行全部；“同意”本身不新增权限。用户随后询问“可以推送远程发布新版了吗”并指令“开始”，已明确授权main与v3.6.0一并仅推送至sni-panel并发布；禁止向origin推送，不将发布授权扩大为生产部署。禁止工作树，保留开始前115份原有文件和6份已跟踪改动；本轮新增的AGENTS赞助长期约定及CONTEXT两个词条须与原有修改区分暂存。文档最后合并为一次中文提交。
3. **Q1 最终决定**：“采纳上游的调整”覆盖 L1—L4。采用上游统一可配置表头及默认字段：规则、所属用户、资源、个人分组、路由、累计、额度、24H、延迟、开关及操作；实际列枚举以固定目标为准。旧本地仅从展开/更多查看的约束已被这次界面决定替代；已有详情入口可共存。临时原型的名称下标签、保持旧表头和排除卡片只是历史，不作为验收版式。
4. **SNI 显示适配**：保留独立 SNI 页签及普通“全部”排除 SNI 的列表、数量、统计、分页与查询；在统一列布局额外保留 SNI 域名信息及完整异常提示，SNI 分类必须显示域名列，普通表格不引入无意义域名列。排序和分页以完整显示组处理，不能把受管副本或单域名散行当作新根规则。
5. **个人组数据与权限**：按上游三种数据库方言创建账号私有个人组、成员关系和索引。组删除只移除组织信息；根规则单次与批量创建、编辑均校验当前账号自有分组及规则归属，不允许替其他用户设组或操作受管子规则。筛选同时覆盖列表、摘要、地图及缓存键；组编辑器必须能包含普通与 SNI，不改普通 all 的既定语义。任何批处理保留本地批量保存、授权、SNI校验和配额原子约束。c6bf317修复MySQL RR外层事务旧快照，首修复核发现跨账号首次建组/空成员范围的间隙锁死锁后，ff7d892仅允许最外层个人组事务在MySQL1213完整回滚后重试，最多3次尝试，不局部重跑嵌套事务或重试业务/after-commit异常，savedId每次回调初始化。两类真实并发均red→green，数据库升级现24/24零skip；最新独立增量复核无已发现代码阻塞，详见编排进度。
6. **列表与卡片**：接入账号列偏好、正常化、显隐、顺序、宽度、恢复默认和浮动滚动条，保留固定规则/操作位置及可见 SNI 域名，兼容非法旧偏好和动态 colspan。采用上游卡片密度、固定开关/拖动区、路径标签和额度弹层；保留只读管理员规则、授权失效标记和准确字节/计量口径。客户端布局偏好不承担权限。
7. **延迟与状态**：保留本地真实手动测试、批次/请求归属、配置代次和当前运行状态隔离；规则切换/编辑后旧异步结果不得覆盖，未报告或失败不能伪造成功。24H继续按全部真实入口双向统计，不改累计、规则额度和账号套餐之间的口径。
8. **Q2 上游告警**：按主机保存 CPU/内存/磁盘启用、阈值、持续/恢复观察及通知用户。主机配置缺失回退旧全局告警；上游移除全局编辑界面和接口。有效通知管理员加指定用户，未指定则加入主机所有者，去重并遵守有效账号/渠道绑定；接受旧启用告警升级后开始通知所有者的行为。保存与观察状态按上游处理。撤回自拟全局默认/单机覆盖和统一其他通知类型的设计。
9. **Q3 整机关机**：默认关闭，仅管理员写入并向兼容 Linux root Agent 授权。采样有效窗口为当前前120秒至后30秒；按真实主机套餐计数、计量方向和阈值计算，原子一次/周期，保留重置/重新启用布防、迁移保护和非管理员字段过滤。关闭整机，不强制最后结算、不等待主备或DDNS完成；界面说明须准确，不在本轮扩展排空协议。
10. **Q3 BBR**：按需安装上游1.0.1插件及Agent内置Go能力；仅安装/启用不会写内核。管理员明确保存/应用才修改参数；读取、验证、备份、写入核对、失败回滚和恢复必须保留。无内核下载、不重建网卡队列。旧Agent不伪称支持；包内内容与源码和manifest一致。README是清单与测试依赖的必需资产，按统一文档提交规则已精确暂存，最终必须核对提交树包含该文件，并与插件归档一致，不能只依工作区存在判断完成。
11. **数据库与迁移**：纳入个人组、账号列/动画偏好、逐机资源告警/关机、URL配置与浮点负载字段，迁移清单和三方言类型一致。保留本地SNI、占用状态、待结清持久化及无缝迁移保护，旧数据可启动且新功能默认安全。迁移导入若重映射用户ID，主机资源告警JSON中的非空notifyUserId必须按同一次用户映射转换，保持指定收件人的身份；空值继续所有者回退。缺失映射按现有依赖缺失机制明确拒绝，不能沿用旧数字、静默清空或改为所有者。保持ID的快照迁移保留原身份关系。
12. **查询/删除与计费**：纳入按用户索引、授权拓扑和流量scope优化，保留模板/成员/历史归属、SNI去重、账本及失败拒绝。计费用户锁先于数据库事务；不套用上游整段删除事务。必须先完成本地真实停止确认、待结清重试、欠费处理和墓碑，再在必要事务内清理个人组关系与最终物理删除，并复查可删除状态。保持本地返回语义及提交后缓存失效。
13. **缓存与会话**：会话复用限同请求已验证userId/sid/kind；当前用户/角色/撤销仍有效验证。后台摘要按用户和参数隔离，只捕获ID，余额和授权仍读有效状态，有限刷新与失效；本地新增/编辑/删除/收尾及切数据库路径均清理。缓存不变成权限证明。保留迁移暂停与排空。
14. **URL/健康与负载**：纳入可选HTTP/HTTPS完整URL、超时和预期状态配置，旧报告按完整配置隔离；Ping/TCPing继续工作，URL不作入口健康门槛。负载按上游读取和展示，缺失不伪造零。主机通知各类型原边界除Q2外不统一改变。
15. **隧道/历史**：有效多入口样本独立实时刷新，一分钟Agent/三十秒面板节流与历史分开，保留暖机/缺样/手动测试以及本地计数epoch和单调递增。接入历史日期选择/趋势、隧道详情及自动刷新修复，延迟缺口如实显示。
16. **日报**：默认关闭，按北京时间发送前一日全局摘要，仅有效通知管理员；开启不补发历史。按成功收件人持久去重、失败重试；流量与实际收入沿用本地口径，不引入计费动作。保留本地品牌和迁移调度暂停。
17. **网页其他改进**：纳入主机/链路分类数量、主机列设置、个人动画开关、品牌导航防闪烁、移动表单/安全区/低高度弹窗和分页修正。缓存公开外观按账号/角色/来源隔离，不能缓存私密授权；保留sni-panel品牌、图标、文档与升级来源、SNI升级预检、XSS转义和菜单显示不等于功能停用的边界。保留有历史推广账务的用户入口，以及始终可见、不受用户菜单开关控制的管理员推广管理入口。
18. **安装向导**：数据库切换后轮询服务真实就绪，按实际方言选默认，准确提示MySQL版本和授权错误；保留本地备份、安装来源、升级与迁移确认。
19. **Agent/FXP**：纳入V1帧原地解密、同步池化读取及仅PROXY兼容场景预读首包，保留所有SNI独立角色、共享监听、热更新、限制、会话及计量。心跳同时保留本地占用/manifest与上游关机字段，完整和keepalive都兼容，迁移优先级不变。
20. **ADR-0006/0008**：SNI落地检测缺失、过期或失败，不得单独阻止入口选择、阻塞DDNS或触发整组切换；仍要求在线、当前完整分流配置、已开启入口检测及观察等待。仅host+failover普通规则按入口运行与健康，不恢复目标门槛；保留同成员/规则/副本故障计时续算、跳过待删旧副本、当前规则运行及发布前复核。其他组、端口资源、多入口、链等不扩大这条政策。
21. **验证治理/依赖**：只接实际网页/服务端需要的测试脚本增量；CI保持本地复用入口、固定Ubuntu24.04/Node22.23.3/pnpm10.28.1/Go1.23.12及SNI/DNS/race/namespace/真实二进制门槛。上游没有共同依赖变化，保留本地锁文件。新增压测为手动隔离工具，不代替SNI批量性能门槛。
22. **源码版本与后续发布**：既有版本规则要求Agent改动时面板/Agent升小版本、补丁归零且Agent=FXP。本轮源码统一3.6.0，保持原生版本不变；更新中英文当前变更说明。最初范围仅本地合并、不创建标签和发布；用户后续已明确授权发布，待独立点评和交付资料核对后将main与v3.6.0一并仅推送至sni-panel，沿用固定Linux、同提交产物及发布核对门槛。发布完成只按实际远程结果记录，生产部署另行授权。
23. **Q4**：本轮及以后跳过作者赞助/捐赠按钮、专属组件、测试、收款地址和专属翻译；许可证、来源、致谢保留。长期约定已追加，不新增ADR。
