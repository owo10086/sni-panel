# 02 — 回归验证：旧规则迁移与换 IP 后的真实转发

**What to build:** 证明新配置不再建立来源名单、升级可以清理旧规则，并且面板仍保存 A 时，B 发来的匹配 SNI 请求已经可用。复用真实 Express + 临时 SQLite 的期望状态测试，以及现有分流器真实 socket 测试；实际防火墙清理在 Linux 环境验证。

**Blocked by:** 01

**Status:** ready-for-human（自动回归和受控 Linux 验证完成，目标环境补充验收待 03）

- [x] 在 `server/sniDesiredState.test.ts` 中验证两跳、多跳、入口组、隧道和单机端口转发的 SNI 配置均不生成来源名单；兼容名单为空、清理命令存在。
- [x] 替换现有“入口换 IP 后名单跟随”的断言：入口地址改变前后均无自动来源限制，不能再期待生成新 IPv4 / IPv6 放行项。
- [x] 覆盖旧非空名单、本地名单字段缺失、空元数据但仍有旧规则的升级场景；首次升级能清理，完成后相同心跳稳定收敛。
- [ ] 保留运行中的分流器，应用清理动作并确认旧 Agent 执行成功；空名单不会被当成缺少合法来源而报错。
- [x] 在 Linux 分别预置 nftables、iptables / ip6tables 的真实旧规则，含允许项和丢弃项；清理后 SNI 标记规则消失，普通规则、计数与无关标记保留。只检查生成的命令文本不能替代此项。
- [x] 验证旧的停用/删除端口的名单残留清理；重复清理安全，不启动已退役监听器。
- [ ] 注入清理失败，确认失败可见、不会提前记录完成；恢复执行条件后，由后续正常心跳或配置重试自动清理，无需人工刷新或修改规则。清理确认后，重复心跳稳定收敛。面板 / Agent 重启和已有配置恢复后不重新建立名单。
- [x] 使用两个真实来源 A、B 发起 TCP / TLS 请求（测试主机或 Linux 网络命名空间均可）。面板数据库始终保存 A，B 的有效 SNI 请求仍到达正确目标，期间无需地址上报或配置刷新。
- [x] 使用未登记来源 C 直接连接出口，匹配域名可以转发；无 SNI、未匹配域名仍按原行为拒绝。不得用 HTTP 转发头代替实际数据流来源变化。
- [ ] 覆盖 IPv4 / IPv6 可用环境，并验证最后一跳来源变化不再被旧名单拦住；原有地址族选择策略不属于本轮修改。
- [x] 运行相关 SNI 路由、热更新、限速、连接数与计量回归；普通隧道认证和其他来源限制不受影响。
- [x] 若本机无法运行真实 Linux 防火墙验证，在验证记录中列明未执行项并于任务 03 的目标环境补齐，不将面板测试通过等同于数据流验收通过。

参考：[规格](../spec.md)。测试只对外部可观察结果作断言，不断言内部调用次数或固定日志文案。


## 已验证与待补充

真实 Express + 临时 SQLite 测试覆盖各承载资源、空/缺失/非空来源元数据、失败与迟到回报、正常心跳重试、稳定收敛及 Agent 会话变化。现有 Agent 测试确认清空来源元数据保持分流器运行。隔离 Linux 环境验证了当前/退役端口、IPv4/IPv6、iptables nft/legacy 共存、无关规则保留、删除和读取失败、重复清理以及 FXP 实际重启。

真实 TLS 验收使用分配给 Linux 回环接口的不同源地址，并导入心跳测试产出的配置和真实面板数据库；清理后 B/C 成功，数据库保持 A。尚未在目标主机上运行整套 Agent 升级动作，也未实际重启目标面板/Agent 或复现多主机转发链最后一跳公网换 IP；相关未勾选项由 03 补齐。详见[验证记录](../验证记录.md)。
