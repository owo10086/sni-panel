# 03 — 就地验证、线上实测与发版

**What to build:** 先部署面板构建产物，确认旧 SNI 名单被清理，再验证入口换 IP 后无需等待面板更新地址即可转发。通过后正规发版，记录直接访问出口的行为变化。

**Blocked by:** 01, 02

**Status:** needs-info（缺少目标主机连接信息及面板容器名称）

- [ ] 验证前记录实际运行镜像 ID / digest、面板与 Agent/runtime 版本、相关 SNI 端口和防火墙标记规则，确认回退依据可用。
- [ ] 确认入口到出口的网络和出口到面板的连通性正常；客户端可使用新入口 B，或用受控解析将请求送往 B，分别记录 DDNS 与客户端 DNS 缓存造成的等待。
- [x] 本地构建服务端，产出 `dist/index.js`；确认未新增镜像缺少的外部运行时依赖。兼容现有 Agent/runtime，不以升级 Agent 作为清理前提。
- [ ] 就地替换容器 `/app/dist/index.js`，sourcemap 同步替换或删除，然后重启容器加载；核对实际产物与登录、心跳状态。
- [ ] 在所有受影响主机上确认 nftables、iptables、ip6tables 的 SNI 来源限制已清理，含历史标记；其他防火墙规则保留。仅面板显示运行中或下发成功不能替代此项。
- [ ] 完成任务 02 尚未执行的 Linux 防火墙验证、清理失败后重试、重启后不复活的检查。
- [ ] 先做受控验收：保持面板入口地址 A 不变，路由和下一跳不变，使用真实来源 B 发出匹配 SNI 的请求，确认请求到达正确目标；该步骤直接证明不依赖新地址上报。
- [ ] 再触发真实换 IP，记录 IP 实际变化、网络恢复、首次从 B 发起请求、首次成功及面板记录更新的时间；记录入口与相关下游的事件通道状态。
- [ ] 迁移完成后，分别验证事件通道正常和断开时，B 的新连接均不因来源名单被拒绝；不要求真实断网场景无条件二十秒恢复。
- [ ] 使用未登记来源直接访问出口：匹配域名可以转发，未知域名仍拒绝；确认出口计量、规则限速和连接数限制正常。
- [ ] 报告真实中断时间与旧实验 5 分 56 秒的差异，说明网络、客户端地址或 DNS 等条件。通过依据是删除来源限制后的可用性，不是面板五秒内显示 B。
- [ ] 回退面板时按预先记录的镜像标识重建容器，丢弃就地替换的可写层；单纯重启容器不能回退。
- [ ] 若回退到旧来源限制行为，另外让旧面板重新下发 SNI 配置并核对主机规则恢复；仅回退面板镜像不会自动恢复已经清理的名单。
- [ ] 正规发版：按改动范围更新版本并提交 → 创建版本标签 → 将 `main` 与该标签一并推送到 `sni-panel` → 等待发布和镜像构建成功 → 拉取对应版本镜像并重建容器。
- [ ] 不向 `origin` 推送代码、标签或发布内容。发版后核对镜像、产物、版本、旧规则清理和新来源实际连通性。
- [ ] 发布说明及用户指南准确说明：SNI 出口不再由面板限制来源，外部直连也可触发有效路由，出口未匹配计数不再单独证明双端不同步。

参考：[规格](../spec.md)。本任务描述未来部署验收步骤，不代表已执行线上改动。
