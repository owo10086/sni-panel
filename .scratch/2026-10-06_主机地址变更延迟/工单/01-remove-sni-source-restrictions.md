# 01 — 取消 SNI 来源限制并清理旧规则

**What to build:** 删除 SNI 分流自动维护的来源 IP 名单，以兼容现有 Agent 的面板改动清理旧防火墙规则。覆盖转发链出口及隧道 SNI 出口的回环名单；保留 SNI 路由、拒绝未知域名、限速和出口计量。

**Blocked by:** None

**Status:** ready-for-human（实现和自动验证完成，待部署验收）

- [x] 移除按上游、上一跳或入口组的公网 / IPv6 地址生成 SNI 名单的路径；隧道 SNI 出口也不再生成回环来源名单。
- [x] 所有 SNI 分流角色下发兼容的 `sourceAllowIps: []`，不安装来源允许项或兜底丢弃项。保留已有协议字段用于旧 Agent 的状态收敛和迁移识别。
- [x] 应用动作携带实际清理命令，不能设成 `commands: []`：现有 Agent 要求 SNI 应用动作有命令。优先复用并完善现有清理能力，无需更改 Agent/runtime 协议。
- [x] 按 SNI 专属标记清理 nftables、iptables、ip6tables 中的旧允许项与丢弃项；同时处理仍在用的端口和历史遗留标记，不清空整张表，不清理其他功能的规则。
- [x] 区分目标规则不存在与删除失败。旧规则仍存在或清理结果无法核实时不能宣告成功，后续动作可以安全重试。
- [x] 旧非空名单即使其他运行状态一致也要触发清理；本地来源字段缺失或为空时，首次升级也有实际清理路径，不能只依赖旧元数据发现残留规则。
- [x] 修正 `localSniRuntimeMatches` 对空期望名单直接返回不匹配的行为。完成清理并确认路由后可以稳定收敛，重复心跳不因空名单一直重发。
- [x] 保留现有路由热更新与运行中进程复用；清理可以重复执行，失败、重连、面板或 Agent 重启后能够继续完成，旧配置不能重新安装名单。
- [x] 主机来源 IP 的变化不再单独导致 SNI 名单相关的防火墙改写；不修改 Agent 地址缓存、存活/心跳/注册地址上报和通用主机地址迁移机制。
- [x] 保留未匹配域名拒绝、按规则限速和连接数限制、出口统一计量。删除的是来源 IP 名单，不是最大来源 IP 数等其他规则限制。
- [x] 更新用户指南与发布说明：出口可被任意网络可达来源直接访问，SNI 域名不是认证；出口未匹配计数也可能来自外部探测。不要移除插件或管理员配置的其他来源限制。

参考：[规格](../spec.md)。旧任务“按请求来源纠正主机地址”已经替代，不再实施。


## 实施结果

已完成面板改动、兼容迁移、指南与未发布说明。规范/规格两轴审查已完成；审查发现的默认 iptables 后端切换后遗漏另一套历史规则的问题已修复，并以同时预置 nft 与 legacy 规则的真实 Linux 验证覆盖。详见[验证记录](../验证记录.md)。线上是否清理完成仍须由工单 03 核对实际主机规则。
