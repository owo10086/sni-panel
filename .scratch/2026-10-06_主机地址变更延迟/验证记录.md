## 实施结果

- 转发链出口、隧道 SNI 出口、入口分流器和单机端口转发均下发 `sourceAllowIps: []`；已删除按上游地址生成名单及安装允许/丢弃规则的业务路径。
- 每次分流器应用包含实际的按端口清理命令，兼容现有 Agent 对非空命令的要求。生产 Agent 和 FXP runtime 无改动，Agent 仅修改回归测试。
- 首次心跳增加独立的全主机清理动作，扫描 SNI 专属标记，包括没有运行时元数据的退役端口。覆盖原生 nftables 和 iptables/ip6tables 的当前、nft、legacy 入口，防止切换默认后端后遗漏另一套规则。
- 命令读取失败或目标规则仍存在时返回失败。只有与当前迁移动作时间戳相符的成功回报才能完成本轮清理；失败通过正常下发重试，Agent 会话变化和面板重启后重新核实。
- 空/缺失来源元数据在清理确认后可以匹配运行状态，不因空名单永久重发。主机地址变化不会单独产生新的 SNI 来源规则。
- 指南与 CHANGELOG 的未发布说明已记录出口可直接访问、SNI 域名不提供认证、外部探测也可增加出口未匹配计数等行为变化。

## 真实 Linux 防火墙与数据流验证

使用 Docker 隔离网络容器，授予容器 `NET_ADMIN`；未操作宿主机或线上防火墙。环境为 Debian 12、Linux/arm64、Go 1.23.12、nftables 1.0.6、iptables/ip6tables 1.8.9、Node 18.20.4。验证使用 `scripts/verify-sni-source-cleanup.mjs`，输入来自真实心跳接口导出的 `desired.json` 和临时面板 SQLite，不手写期望配置替代接口输出。

五项检查全部通过：

1. 预置原生 nftables 与 iptables-nft/ip6tables-nft 的允许项和丢弃项。按端口清理仅删除对应端口；全主机迁移再清除退役端口 29999 的残留。普通规则、计数、插件风格标记及管理员相似标记均保留，重复清理安全。
2. 在 iptables-legacy/ip6tables-legacy 后端重复上述检查，通过。
3. 在同一主机同时预置 nft 和 legacy 后端的 IPv4/IPv6 旧规则，默认命令指向 nft 时两套仍全部清理；无关规则保留。此项先复现了审查发现的漏清理，再验证修复。
4. 注入 nft 删除失败，确认动作失败且目标规则仍可查见；恢复工具后重试成功。注入读取失败，即使之前规则已清空仍返回失败，不把无法核实视作不存在。
5. 在回环接口配置实际 IPv4 来源 A=`198.51.100.10`、B=`198.51.100.11`、C=`198.51.100.12`，以及三个不同 IPv6 来源。保留真实面板数据库的入口地址 A，分流表与目标均不修改。先安装旧名单，A 完成 TLS、B 被拦截；执行清理后，IPv4/IPv6 的 A、B、C 均完成匹配域名的 TLS 并收到正确目标响应。未知域名和无 SNI 不能完成 TLS。数据库地址仍为 A，数据库文件字节一致；实际 FXP 进程重启后 B 仍成功，旧名单没有恢复。

第五项使用客户端 socket 的 `localAddress` 绑定不同源地址，服务器收到的 TCP 来源真实不同；没有用 HTTP 转发头模拟。测试期间不向面板发送新地址，也不刷新分流表。它证明删除名单后出口接收新来源不依赖面板更新，尚不能代替目标环境多主机转发链和真实公网换 IP 的完整验收。

## 复现方法

在仓库根目录导出心跳配置与测试数据库：

```sh
FORWARDX_SNI_VERIFY_OUTPUT=/tmp/forwardx-sni-verification \
  node --import tsx --test --test-name-pattern='SNI forward-chain desired state sends' server/sniDesiredState.test.ts
```

准备隔离 Linux 镜像，安装真实工具：

```dockerfile
FROM golang:1.23-bookworm
RUN apt-get update -qq && apt-get install -y -qq nftables iptables iproute2 python3 nodejs openssl
```

将该镜像命名为 `forwardx-sni-test`。构建与容器架构相符的 FXP 测试二进制；本次容器为 arm64，因此在 `forwardx-fxp/` 执行：

```sh
GOCACHE=/tmp/forwardx-sni-go-cache GOOS=linux GOARCH=arm64 \
  go build -o /tmp/forwardx-sni-verification/forwardx-fxp .
```

amd64 容器应将 `GOARCH` 改为 `amd64`。这是验证用二进制，不是正式发布资产。回到仓库根目录执行：

```sh
docker run --rm --cap-add NET_ADMIN \
  -v /tmp/forwardx-sni-verification:/verification:ro \
  -v "$PWD/scripts/verify-sni-source-cleanup.mjs:/verify.mjs:ro" \
  forwardx-sni-test node /verify.mjs /verification
```

脚本会在隔离容器内添加测试防火墙规则和接口地址，应始终按上述方式在临时容器中执行。两轴代码审查均已完成，最终未发现未解决的代码问题；审查发现的混合后端遗漏已修复。
