# Codex CLI 独立审查

第三步需求审查与第六步提交点评分别启动全新只读 Codex CLI。主代理的自查不能冒充独立审查；审查者只返回 Markdown，不修改文件、不提交、不发布、不再次委派。

## 调用

先检查 `codex --version`、`codex exec --help`，以本机实际支持的选项为准。沿用用户当前模型配置，不擅自换模型或修改配置。主代理准备本轮提示词和输出目录，填入真实绝对路径：

```bash
codex exec --ephemeral --sandbox read-only \
  -C "$repo_root" \
  -o "$round_dir/审查/需求审查.md" \
  - < "$round_dir/审查/需求审查提示词.md" \
  > "$round_dir/审查/需求审查运行.log" 2>&1
```

第六步改用 `提交点评提示词.md`、`提交点评.md`、`提交点评运行.log`。不创建工作树，不使用跳过权限保护的参数。

检查退出状态、实际报告及覆盖范围。失败时保存日志、排查调用原因并报告实际阻塞；缺少报告不能写为审查通过。较长任务定期说明进度。

## 两次提示词都应提供

- 仓库、本轮目录、执行模式、第一步选定的源需求路径和版本依据、整理后的规格、相关项目规则及 ADR。
- 本轮范围、本地比较依据、已有无关修改，以及用户决定或主代理在“执行全部”模式下按推荐作出的决定。只读实际原文和代码，不只采信主代理摘要。
- 每个发现写清严重程度、位置、证据、用户影响及推荐处理。区分阻塞和普通建议；无发现时明确说明，并列出范围与限制。
- 冲突或功能取舍交由主代理按执行模式处理。**源需求缺失、多个最新候选或选错来源不属于可自动决定的功能取舍，必须回到第一步由用户确认，“执行全部”也不能替用户选需求。**
- 只审本轮需求，不附带无关功能或重构。按当前项目自己的决定判断，不默认套用 SNI 或其他项目的规则。

## 第三步：需求审查

提供源需求全文、整理后的规格、本地代码依据和相关决定，核对：

1. 是否有真实、唯一且版本明确的需求来源，是否误将日志、旧交付、工单或代理自行补造的内容当成源需求。
2. 规格是否忠实承接源需求，有无遗漏、扩大、矛盾、无法观察的验收或未定决定。
3. 本地行为、项目约定及相关 ADR 的保留条件是否准确，推荐处理是否被冒充为用户原话。
4. 需求是否足够拆单，依赖和异常结果是否清楚，检查入口是否可用，未验证事项是否如实记录。

## 第六步：提交点评

再提供全部工单、实施前提交、本轮完整提交清单、需求审查处理及实际验证记录，核对：

1. 覆盖全部本轮提交及最终代码状态，不能只点评最后一笔或纳入无关提交；说明实施前提交、被点评的提交编号及最终提交。
2. 对照源需求、规格和工单检查漏项、误改、范围外改动、本地保护退化及可核对的实际缺陷。
3. 核对是否漏交本轮代码，未提交内容不算在已点评提交内；无关旧修改按实施前记录排除。归属不清写明材料缺口，不自行提交或猜测。
4. 检查报告是否记录真实运行的验证及其覆盖；只读审查不另启会写文件或访问生产的验证。
5. 结论为“存在阻塞”“无已发现阻塞”或“证据不足”，明确对应提交和限制。修补的新提交需要补充独立复核；不宣布已推送、部署或人工验收通过。
