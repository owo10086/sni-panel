## Problem Statement

本地已经完成284，需要继续取得上游285的普通多入口、ny导入、支付核验、分页账单、运维看板、管理设置和网页改进。比较起点包含本地独有的SNI、批量操作、计费和安全修复；直接覆盖上游文件会有退回已有行为的风险。

用户还希望SNI规则也能通过入口组直接转发落地。当前本地端口SNI资源只允许单台主机，普通多入口并不能自动满足SNI的分流、完整运行确认、DDNS与累计用量要求。需要补齐整条使用过程，并坚持不逐条等待SNI落地探测的本地规则。

## Solution

以固定的本地已完成284状态为起点，对照固定上游285，逐项合入范围内改进并兼容本地保护。普通多入口沿用上游操作；SNI由每台入口直接连接规则固定落地，逐入口核对完整配置、分别取得DDNS资格，各入口执行限制、用量统一累计。

| 事项 | 本轮决定 |
| --- | --- |
| 普通端口转发多入口 | 纳入，沿用上游在链路资源中选择入口组、统一管理成员的操作方式 |
| SNI 多入口直连 | 纳入，端口转发资源引用入口组，每台入口直接连接规则自己的落地 |
| SNI 限制和用量 | 每台入口分别执行每条规则的限速和最大连接数；实际用量、费用统一归到原规则和用户 |
| 入口组 DDNS | A／AAAA 发布所有合格入口，逐入口确认完整配置、在线、已开启的国内检测和观察等待 |
| SNI 健康判断 | 延续 ADR-0006，落地探测缺失、过期或失败不能单独卡住入口、DDNS 或触发整组切换 |
| ny／Nyanpass 导入 | 纳入实验导入，接本地整批保存，沿用上游支持格式和拒绝范围 |
| V3 | 纳入底层改进；网页及创建、切换接口暂不开放 V3 |
| 支付、账单、运维、管理和网页 | 按本文规定纳入，并保护本地已有功能 |
| 原生应用 | 按长期约定排除 Android、iOS／iPadOS 等独立应用及专属内容 |
| 对外版本 | 面板保持 `3.3.8`，Agent／FXP 保持 `3.3.0` |
| 既有规则迁移 | 不做。用户确认目前没有使用入口组转发，无需迁移 |

用户明确要求：“其他按推荐，不要扩大问题范围。”本轮不安排旧规则拓扑迁移、自动改造已有链路、全组实时总限速、SNI 来源 IP 精确采集，也不重新讨论已确认的本地规则。

## Implementation Decisions

下列决定沿用已确认的讨论和ADR。具体代码位置由配套实施计划和对照清单保存，本节只说明行为、职责和取舍。

### 普通端口转发引用入口组

在已保存的端口转发资源中选择入口组，普通规则由组中各启用成员同时转发。保留单主机资源；不自动把已有单主机、转发组、隧道或转发链转换成新模式。

沿用上游的入口组卡片、列表、独立节点详情弹窗、各入口状态与错误提示。新增入口失败只影响该入口，不把已正常工作的入口一起停掉。资源流量和引用规则数按原规则去重，成员副本不能算成多条用户规则。

成员撤除仍须遵守本地已有停止确认、待结算与重试保护，不能为了跟上上游的同步步骤而提前删记录、丢用量或跳过欠费停用重试。

### SNI 新模式：每台入口直接连接每条规则的落地

#### 使用方式和连接路径

沿用上游入口组操作方式，在端口转发资源中引用入口组，再把 SNI 规则保存到该资源。不增加一套平行的入口配置，也不要求额外指定公共出口。

例如入口组 G 包含 A、B，端口转发资源引用 G：

| SNI 规则 | 客户连接的入口 | 实际路径 |
| --- | --- | --- |
| a.example / 443 → X:443 | A:443 | A 直接连接 X:443 |
| a.example / 443 → X:443 | B:443 | B 直接连接 X:443 |
| b.example / 443 → Y:8443 | A:443 或 B:443 | 实际接到连接的入口直接连接 Y:8443 |

“单落地”指**一条规则有一个固定落地**，不是全部域名只能使用同一台落地。一次连接只经过实际选中的一台入口；A、B 之间不串联，也不把最后一个成员当成公共出口。落地不必为了本方案安装 Agent 或 FXP，TLS 握手和业务内容保持原样传递。

#### 共用端口和保存保护

各入口在业务端口运行本地独立分流器，按域名拨该规则的目标。继承已有 SNI 保护：

- 同一实际主机允许合法 SNI 共用端口；域名规范化后在该主机上跨端口、跨资源检查唯一，原规则的合法副本不误判为重复。
- 普通规则不能占用已由 SNI 共享的同一监听；不属于受管分流器的外部端口占用仍须如实报告。
- 没有 SNI、域名未知、不是 TLS、握手超时，一律断开；没有默认落地。
- 权限按每条原规则和资源归属检查，不因入口组共享而放开其他用户的规则。
- 继续使用现有保存顺序和重读保护，避免并发新增、成员变更、修改入口时凭旧名单放行冲突。保存失败保留原配置，延迟清理不能撤销重新使用的有效成员。
- 正常热更新只影响发生变化的域名；删除代表规则不改变其余域名共用的监听身份。撤销无法确认时沿用安全停机保护，不承诺所有失败情况下都不断线。

不能只放开网页和接口的“一台主机”限制。下发、完整运行确认、成员清理、DDNS 和计量必须一起支持新模式，否则保存成功也不能算功能完成。

#### 每入口限制，统一累计

每条 SNI 规则的限速和最大连接数在各入口分别执行。例如规则设为 10 Mbps、100 个连接：A 最多 10 Mbps／100 个，B 也最多 10 Mbps／100 个；A、B 同时使用时，合计可能达到 20 Mbps／200 个。本轮不新增跨入口协调的全组实时总上限。

A 报告 30 GB，B 报告 20 GB，原规则累计应为 50 GB，用量和费用归属同一个用户，不能显示成两条无关规则，也不能重复扣费。沿用现有去重、结算、额度停用和失败重试；上报与下发存在正常间隔，不把统一累计描述为逐字节实时统一额度。

上游普通规则的每来源 IP 连接限制，继续排除所有 SNI 规则及其成员副本。SNI 原有每条规则最大连接数仍保留。

#### 逐入口准备好，逐入口加入 DDNS

每台入口分别核对：

1. 主机和 Agent 在线，能实际执行该功能；同一版本号不能代替能力和实际运行确认。
2. 当前应运行的**完整分流配置**已经生效：所有相关资源的域名、目标、端口、限速和连接数一致，没有应撤销却仍在运行的旧内容。
3. 确认报告当前有效；离线、重启、修改目标、报告过期后，按现有规则重新确认。
4. 已开启的国内检测通过，完成设置中的故障、恢复观察等待。未开启的国内检测不额外开启。

入口组被多个 SNI 资源引用时，应核对该入口上所有应运行的相关 SNI 配置，不能只找其中一条代表规则，或只看某一个资源。

| 场景 | 预期结果 |
| --- | --- |
| A 完整配置已确认且观察满足；B 少一个域名 | A 可以发布，B 等待自己的配置补齐，不拖住 A |
| A、B 均满足条件 | A／AAAA 分别发布所有对应的合格地址 |
| B 离线、确认过期或仍运行旧目标 | 按设置中的有效报告和观察规则取消或等待 B 的资格，A 独立判断 |
| 12 个域名完整配置生效，只有一条有落地检测记录 | 不等待其余 11 条落地记录，按入口本身条件判断 |
| 某条 SNI 落地检测失败、过期或缺失 | 仅凭这件事不能挡入口、卡 DDNS 或切换整个组 |
| 同一资源另有普通规则 | 普通部分仍执行原有目标健康要求，不因存在 SNI 而跳过 |

**缺落地探测记录，与缺实际分流配置，是两回事。** `a.example` 的落地 X 故障，不应让仍能正确处理 `b.example → Y` 的入口一起失去资格。反过来，入口还在把 `a.example` 发往旧目标，即使端口监听正常，也没有准备好。

新入口组是并行使用多个入口，不套用旧主备转发组“仅有一个当前入口”的规则。旧主备转发组继续保留自己的优先级、当前入口和回切方式。A／AAAA 支持多地址；CNAME 仍只使用单个目标，不扩展多 CNAME。

#### 没有合格入口时的边界

新入口从未确认完整配置时，不得因“保底”首次发布。已发布入口出现普通健康故障后，故障／恢复观察等待及“全部失效保留一条解析”的既有行为保留；页面必须显示不可用、等待恢复，不能把保留地址算成合格入口。保底只限仍启用、未移除、未因额度退出的原成员；没有这种成员时，不得重新发布已移除、停用或额度退出的地址。自动解析关闭时不向服务商写入，页面说明建议与人工处理要求。恢复后重新核对当前完整配置和观察时间。

#### 页面状态和成员撤除

页面分别展示每台入口的最新配置确认及原因；准备不齐的入口显示等待或故障，不能因为另一台入口正常就把它显示成已运行。资源可有部分合格入口，不要求所有入口同时准备好后才允许任何入口接流量。

新增成员的配置失败与已健康成员隔离。移除成员要确认停止，保留历史用量、费用收尾和失败重试；待清理记录不能重新获得转发或 DDNS 资格。原有转发链和直接隧道的运行确认方式按各自形态保留，不套成新模式。

成员保存冲突与主机执行失败分开：域名、权限等保存检查失败时，整体保留修改前的成员和规则；合法成员保存后，某入口安装工具或应用配置失败，只使该入口等待／故障。外部端口占用仍按 ADR-0004 不在创建时检查，实际占用由运行报告体现。

### ny／Nyanpass 实验导入

纳入上游解析和预览，沿用其格式限制；不新增 ny 的 TLS 入站、共享端口或 SNI 子规则支持。不支持的内容明确拒绝，不能静默删字段后生成不同含义的规则。

导入接入本地整批保存入口 `createBatch`，继续保留普通、SNI 和混合文本导入的既有能力及逐条结果。不能用上游网页六路并发单条创建替换本地整批流程。ny 规则初始关闭、不覆盖旧规则；指定端口冲突如实报错，不自行换号。

### 支付和账单

纳入易支付签名与相对支付链接、支付宝请求时间、密钥兼容、微信配置校验、响应验签和商户身份核对。付款展示区分等待付款、正在核对、已入账和异常，补齐中英文提示，不凭页面跳转或未经验证的回调加余额。

支付宝、微信、易支付支持主动查单。订单到期后七天宽限内，核实真实付款可恢复入账；重复通知和重试仍只能入账一次。不要把这项能力扩展成 Stripe／USDT 同样主动查单、自动退款或自动打款。

七天从订单到期时刻起算；缺到期时刻的历史订单沿用创建时刻。截止时刻仍可核实，超过截止不自动入账，保留管理员对账提示。已过期、取消或失败的订单仅在同一完整核验通过后恢复；金额、币种、商户、订单归属不匹配均不得入账。

支付订单统一在账单与兑换中查看，账单、余额流水使用服务端分页；保留支付流水和异常原因。外部收款、余额消费与不同币种分开，不能把充值和消费重复当收入，也不能把不同币种直接相加。
