# Codex CLI 独立审查

仅在流程第三步或第六步读取本文件。两步分别启动新的 Codex CLI 会话，不能由主代理写一份报告冒充独立审查，也不能用同一个已实施代码的会话给自己背书。

## 调用方式

先检查本机 `codex exec --help`，以实际支持的选项为准。使用用户当前配置的模型，不擅自指定另一个模型或修改配置。子代理只读仓库，不改代码、文档或工单，不提交、不联网发布、不再委派子代理。

主代理创建本轮 `审查/` 目录和具体的提示词文件，替换下面的路径变量后调用。路径必须是本轮实际绝对路径；主代理负责保存 CLI 输出，子代理只返回 Markdown。

```bash
codex exec --ephemeral --sandbox read-only \
  -C "$repo_root" \
  -o "$round_dir/审查/需求审查.md" \
  - < "$round_dir/审查/需求审查提示词.md" \
  > "$round_dir/审查/需求审查运行.log" 2>&1
```

提交点评改用 `提交点评提示词.md`、`提交点评.md`、`提交点评运行.log`。不使用创建工作树或跳过权限保护的参数。不通过忽略仓库约定来让审查继续。

调用结束后核对退出状态、报告是否生成、报告实际读过的范围，以及报告是否针对本轮目标与当前材料。失败时保留日志并说明原因；只修复调用本身的问题，不通过扩大写权限或伪造报告补齐。较长任务定期说明仍在审查，不把暂无输出当作通过。

## 提示词必须包含的共同信息

主代理填入本轮真实值，不把占位说明原样发给子代理：

- 你是独立审查者，只读；所有建议以 Markdown 返回，禁止修改、提交、发布和再次委派。最终报告由调用方保存。
- 仓库根目录、目标标签及提交、本地比较提交、本轮目录、本轮执行模式；已有未提交修改的清单及本轮修改范围，避免把他人工作归到本轮。
- 必读材料的实际路径：适用 `AGENTS.md`、规格、差异证据、用户决定或主代理按推荐作出的决定、相关 ADR；第六步再加全部工单、实施前提交、本轮完整提交清单、需求审查处理和真实验证记录。
- 第六步在第五步本地提交之后进行，替代 `/implement` 默认的 `/code-review`。点评明确列出的本轮全部提交及其最终代码状态，不能只看最后一笔或夹带无关提交。另核对工作区是否遗漏本轮代码；未提交内容不计入已点评提交的结论。材料无法区分时说明缺口，由主代理补充依据，子代理不擅自提交或猜测归属。
- 只审查本轮目标范围。原生应用按长期约定排除，面板网页继续纳入。不要把排除项变成阻塞，也不要提无关重构。
- 特别核对 ADR-0006、ADR-0008 的全部条件和边界，不把逐条业务目标检测加回主机型主备组，不取消完整配置、规则运行、入口检测和观察等待等条件。
- 独立核对原文和代码，不能只认可主代理总结；证据不足就写未确认。
- 每个发现写：严重程度、位置、证据、用户能遇到的后果、建议处理；区分必须先解决的问题与普通建议。没有发现就明确说明，并写检查范围和限制。
- 发现冲突或功能取舍时写明证据、影响和推荐办法，标注需主代理按本轮执行模式处理。默认模式由主代理等用户；“执行全部”模式由主代理按推荐落实，不等待用户。子代理本身只审查，不修改、不提交，也不把建议冒充用户原话。

## 第三步：需求审查重点

判断这份规格能否直接拆单：

1. 本地当前代码与指定上游目标是否都被纳入依据，有没有漏掉本地独有保护或把以前未验收内容当作已交付。
2. 纳入、兼容、保留、排除是否清楚，是否符合用户决定，有没有悄悄扩大版本或功能范围。
3. 行为、依赖、异常情况和验收是否足够具体，有没有自相矛盾、未定功能取舍或无法执行的要求。
4. 是否正确区分缺少业务目标探测与入口没有准备好，并保留 SNI／主机型主备组各自边界。
5. 是否正确区分调用技能默认授权六步、默认遇冲突等待、“执行全部”按推荐连续处理，以及“同意”本身不新增权限或切换模式。

## 第六步：提交点评重点

判断当前结果能否交给用户审阅：

1. 对照规格与工单检查第五步已完成的全部本轮提交，列出漏合、误合、范围外变化和未承接的需求；注明实施前提交、实际点评的提交编号及最终提交。
2. 核对 SNI、DDNS、主机型主备组、本地计费／安全等受影响保护，尤其是同文件兼容处理和原生应用排除。
3. 检查潜在缺陷和边界问题，结合实际代码给出可核对的证据，不提出无关美化建议。
4. 核对报告中的验证是否真的运行、覆盖哪些行为、还缺什么；先读记录，只读审查阶段不自行启动会写文件或访问生产的检查。
5. 结论写明“存在阻塞”“无已发现阻塞”或“证据不足”，并交代对应的已提交代码状态及未提交残留。修补后的新提交需要补充独立复核；不要用旧结论覆盖新提交，也不要宣布已推送、已部署或人工验收通过。
