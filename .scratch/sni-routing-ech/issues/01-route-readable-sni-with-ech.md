# 01 — 带 ECH 扩展的连接按可读明文 SNI 分流

**What to build:** 分流器只依据 ClientHello 中是否存在可解析的明文 SNI 决定是否查询分流表。带 GREASE ECH 或真实 ECH 外层扩展的连接，只要明文 SNI 命中 SNI 分流规则，就能到达对应目标服务；分流器保持握手字节完整，并继续执行所属规则的流量统计、限速、连接数限制、来源白名单和分流表热更新。

**Blocked by:** None — can start immediately

**Status:** resolved

- [x] 带 ECH 扩展且明文 SNI 命中分流表时，连接成功到达对应目标服务；GREASE ECH 与真实 ECH 外层扩展采用相同判定方式
- [x] 分流器只使用外层明文 SNI，不解密 ECH，也不尝试取得内层域名
- [x] 目标服务收到的 ClientHello 与客户端发送内容逐字节一致
- [x] ECH 扩展位于扩展列表开头、中间或末尾时，分流结果一致
- [x] 带 ECH 扩展的 ClientHello 经多个 TCP 分段发送时，仍能完成解析和转发
- [x] 多域名分流表按照明文 SNI 选择正确规则，并将连接数和流量计入对应规则
- [x] 带 ECH 扩展的连接继续受对应规则的限速、连接数限制、来源白名单和分流表热更新约束
- [x] 完全缺少 SNI、域名未命中、非 TLS 流量以及读取时间内未完成的握手继续断开，未匹配连接数只统计这些真正未匹配的连接
- [x] 既有拒绝测试中的 ECH 用例改为成功转发测试，真实套接字测试覆盖握手字节完整性、扩展位置、TCP 分段、多域名匹配和既有拒绝行为
- [x] 原始 SNI 分流规格、原始实施工单和用户文档统一采用“明文 SNI 可读即可分流”的描述
- [x] `forwardx-fxp` 的测试与静态检查全部通过
