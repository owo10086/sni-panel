# 01：建立可重复的 SNI 导入对照并保存旧版记录

**What to build：** 完整走一遍与网页相同的逐条域名检查和规则创建流程，让后续优化能从相同起点重复导入、准确查看各入口收到的配置和通知，并有真实的修改前耗时可比较。

**Blocked by：** 无工单依赖。

**Status:** resolved

- [x] 在临时环境中按网页实际内容明确发送零限速、零流量限额、空到期时间，最多同时处理 6 条；保留管理员为自己创建时不发送限额字段的对照，确认两种输入的托管属性和通知行为不同。
- [x] 每台启用入口均在导入前接通消息接收；保留完整通知，按主机、刷新原因和是否紧急分别统计，并确认已收到检查位置之前的全部消息。
- [x] 12 条小规模导入全部成功，主规则及成员副本完整，各入口获得的域名、落地机地址和端口正确；保存成功与实际配置生效分别记录。
- [x] 三台入口、56 条规则的主要测速覆盖空组，以及固定已有 56 条规则时继续新增 56 条；每轮恢复同一起始样本，入口在线时间有效，主机运行状态、导入内容及环境保持一致。
- [x] 在两处业务优化之前，每个场景完成至少 3 轮，保存各轮耗时、中位数、通知次数、代码版本和样本说明。批次等待上限覆盖原约 230 秒并留余量，失败与超时不计为提速。
- [x] 计时只覆盖整批检查和创建调用，不包含环境准备；测速不加入修改后才成立的通知次数要求，数字必须能从执行结果中取得。
