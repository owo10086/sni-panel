# 04：安全地新增、停用和更换入口成员

Status: resolved
Blocked by: 03

**当前阶段：** 已完成本地实施与验收，详见下方完成记录。

**交付内容：** 管理员在承载多个 SNI 域名的转发组中新增、停用、移除、恢复或更换成员，新入口自动取得现有规则并在准备好后参与切换。更换中途失败时原有成员和业务完整保留；保存成功但机器暂未更新时，仍能区分已保存与待同步。

**前置工单：** 03 — 按最新配置和实际连接完成主备切换。

**验收条件：**

- [x] 新增或重新启用成员时，对该成员承载的所有应运行规则检查端口、域名冲突、Agent 能力和归属用户权限；不能只检查第一条规则。
- [x] 成员变更将相关组设置、成员和受管规则作为整套配置处理，保存成功后才通知机器更新；中途失败完整保留操作前的配置，未成功的变更不成为切换或解析更新依据。
- [x] 组内规则使用 443 和 8443，更换为 C 时 C 的 443 可用而 8443 已被占用，操作失败后旧成员和整套规则保持完整，C 没有部分新配置，旧业务继续运行。
- [x] 另覆盖开始写入部分配置后才发生的失败，证明失败恢复保证不只依赖前置检查；机器不会提前收到本次失败操作的更新或撤除。
- [x] 新成员自动取得各端口的完整分流规则，最新配置生效且健康条件通过后才参与新选择或切回；优先级调整仍按现有调度处理。
- [x] 停用或移除成员后，仅清理它在该转发组中的受管规则及不再需要的监听，其他启用成员和其他域名继续按现有方式工作。
- [x] 整套保存成功后某成员离线或应用失败，保留已保存的完整配置，页面显示待同步或失败，其他已就绪入口继续工作；恢复后通过已有下发方式取得最新规则再恢复资格。
- [x] 转发组停用与重新启用、规则停用与重新启用、后台同步均遵守相同成员保护和准备要求；不允许成员规则被单独改成与根规则不同的业务配置。
- [x] 新增、移除、恢复成员和失败恢复不重置根规则累计用量，不绕过用户授权、额度、有效期及既有托管保护。
- [x] 通过现有转发组管理、规则管理和心跳入口验收成功与失败结果；连接新旧入口验证规则准备及撤除，保留原有普通转发组成员管理检查。

## Answer

成员设置和整套受管规则一起保存；第二个端口被占用及写入中途故障都保留原组、原成员和全部旧规则。C 取得两个业务端口的实际心跳配置，确认生效后再参与准备判断；隔离环境由真实 Agent 执行新增动作，两个端口均到达各自落地机，停用后两监听均拒绝连接。撤除按闲置端口处理，避免代表规则编号不同让旧 Agent 跳过停止；A、B 的原业务及普通成员管理由回归检查覆盖。

**验收证据：** [本轮验收记录](../验收记录.md)，其中逐单表对应本单编号，并区分管理接口、真实 Agent 执行与连接验证。后续授权的面板 `v3.3.1` 推送和发布已完成，见 [发布记录](../发布记录.md)。生产部署另行处理。
