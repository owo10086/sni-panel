# 02：共用入口端口并隔离单域名变更

Status: resolved
Blocked by: 01

**当前阶段：** 已完成本地实施与验收，详见下方完成记录。

**交付内容：** 管理员在同一主机型转发组中添加两条不同域名的规则，共用一个入口端口，各入口分别把域名送到自己的落地机。新增、修改、停用或删除其中一个域名时，其他域名的正常连接继续工作。

**前置工单：** 01 — 在主机型转发组上跑通一条 SNI 规则。

**验收条件：**

- [x] 两条不同域名的规则可以在同组、同成员、同入口端口上保存并运行；每台成员仅使用一个共享分流器，各域名到达各自落地机。
- [x] 页面域名预检、保存、重新启用和后台同步使用一致的共享范围；组内合法的成员副本不会误报为重复规则。
- [x] 同一入口主机上的重复域名继续跨端口、跨承载资源拒绝，并指出冲突规则；普通规则与 SNI 规则仍双向互斥占用端口，不增加跨转发组或跨承载资源的共享范围。
- [x] 共享分流器的身份由成员主机、入口端口和既有角色确定；删除编号最小的规则或调整排序，不更换其余规则使用的分流器身份。
- [x] 新增域名保留已有连接；修改域名、目标或限制设置时，按既有热更新方式只影响变化的域名；停用、删除和重新启用也只调整相关域名。
- [x] 删除第一条规则后，其余规则仍可连接；删除最后一条有效规则时才移除不再需要的共享监听，不留下受管占用。
- [x] 修改入口端口后，各成员正确准备新端口，并清理旧端口上仅属于该规则的配置；同一旧端口仍有其他规则时保留它们的监听及连接。
- [x] 失败修改遵守整套保存保证，保留原规则及各成员配置；正常更新不能清零已累计的根规则用量。
- [x] 复用现有管理和心跳检查验证两域名配置、冲突、删除第一条规则及反复同步；使用持续的真实连接证明未变化域名没有中断，不以内部调用次数代替结果。

## Answer

已实现同成员同端口的稳定共享身份，域名预检和保存采用相同冲突范围。A、B 的真实分流器均验证两域名分开到达落地机；通过真实 Agent 执行正常撤除后，另一域名的持续 TLS 连接仍可回显。删除第一条规则留下的旧恢复文件只清理文件，不误停安全监听；最后一条有效路由消失时清理监听和恢复文件。
