# 01：在主机型转发组上跑通一条 SNI 规则

Status: resolved
Blocked by: None

**当前阶段：** 已完成本地实施与验收，详见下方完成记录。

**交付内容：** 管理员在已有主机型转发组中创建一条 SNI 分流规则，主入口和备用入口提前取得完整配置；分别连接两个入口，都能通过同一个业务域名到达规则保存的落地机。页面操作、规则保存、各成员配置和真实连接检查形成一个可以独立验收的完整场景。

**前置工单：** 无。

**验收条件：**

- [x] 管理员选择已保存的主机型转发组后，可以使用现有 SNI 开关；隧道型转发组、入口组和出口组继续按原范围限制，普通用户权限不放宽。
- [x] 打开开关默认使用 443，协议为 TCP，仍可按现有方式修改入口端口；编辑已有非 443 规则时保留原端口。规则里的出站故障转移保持现有 SNI 处理。
- [x] 对所有启用成员检查域名格式、规范化后的重复域名、普通规则端口占用、业务端口范围及 Agent 能力；未上报、无法识别或低于现有最低版本时，错误说明成员及所需版本。
- [x] 管理员代建采用所选归属用户的资源权限、端口要求和配额；根规则、成员规则归属一致，成员规则继续由根规则统一管理。
- [x] 一次规则创建或修改作为整套配置保存：保存中途失败保留原规则，失败创建不留下根规则或部分成员规则，整套成功后才通知机器更新。
- [x] 主入口和备用入口都收到该规则；每台成员使用既有独立分流器直接到达落地机，业务监听就是保存的入口端口，不新增回环端口或公共出口。
- [x] 分流配置保留根规则的限速、连接数及其他现有限制；不因新增承载方式清空限制或增加 SNI 来源地址名单。
- [x] 页面能够区分已保存与等待各入口生效；首次准备不能只凭共享端口已监听或动作已下发就宣称规则运行，未确认生效的成员不能被新选为当前入口。
- [x] 通过现有规则管理和 Agent 心跳入口检查两台成员实际收到的配置；把真实配置交给受管分流器，分别连接两台入口，确认匹配域名到达落地机、握手原样转交，未知域名或无 SNI 请求保持拒绝。
- [x] 本单涉及的现有普通转发组、转发链 SNI、单机端口转发 SNI 和单出口隧道 SNI 检查继续通过。

## Answer

已接通主机型转发组的 SNI 表单、所有启用成员检查、管理员代建和整套保存。真实心跳为 A、B 下发业务端口上的独立分流器；两个隔离入口均能按保存域名到达落地机，未知域名和无 SNI 请求被拒绝。默认 443、已有非 443 端口、普通用户权限及原有承载方式由表单、规则管理和完整回归检查覆盖。

**验收证据：** [本轮验收记录](../验收记录.md)，其中逐单表对应本单编号，并区分管理接口、真实 Agent 执行与连接验证。生产部署、推送和发版另行处理。
