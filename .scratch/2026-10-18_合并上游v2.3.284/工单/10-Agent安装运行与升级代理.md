## 完成标准

- [ ] 支持明确配置的 HTTP／HTTPS／SOCKS 及认证，SOCKS 域名交代理解析；无配置默认直连，空配置不继承宿主 HTTP_PROXY／ALL_PROXY 等系统代理。
- [ ] 代理只覆盖注册、心跳、流量上报、事件长连接和安装升级下载；业务转发、隧道、主机公网 IP 发现、Ping／TCP／iperf 等探测保持原路径。
- [ ] 代理格式错误或失效时明确失败，不自动回退直连、不静默报告安装或升级成功；凭据不出现在普通状态、错误、公开日志或诊断资料。
- [ ] 面板生成的安装脚本、独立入口及升级下载继续使用本地仓库和资产，保留版本、安装目录、面板地址、Token 及原有参数。
- [ ] 升级默认保留已明确填写的代理，允许按上游指定代理或关闭代理；仅修改对应字段，配置写入失败不重启、不损坏原配置。
- [ ] 入口脚本下载和后续下载分别按约定设置代理，不能只让后半段有代理；系统包管理器及 SOCKS 支持不足的边界在说明和反馈中准确呈现。
- [ ] 修改代理后 Agent 重启沿用现有进程身份和重新确认；重启前旧报告、迟到回复或仅在线不能认定 SNI 当前完整配置已生效。
- [ ] 保留 SNI 运行上报、普通每来源 IP 限制排除全部 SNI、精确计数及现有受管运行程序恢复；设置代理不主动重启独立分流进程，不承诺所有异常与升级不断线。
- [ ] 代理断开时管理通信如实失败，既有业务不因管理配置错误被清空；恢复后按当前完整配置确认，不把旧心跳拼成新的生效记录。
- [ ] 通过真实隔离代理验证注册、心跳、事件、上报和下载去向，以及业务／探测未代理；新旧 Agent 分开记录实际身份，旧 Agent 不因同版本被认定支持新字段。
- [ ] 运行代理、生成安装脚本、资产来源、升级及受影响 SNI 确认检查，隔离环境验证新装、保留配置升级、直连切换和失败保留，未覆盖的包管理器与网络条件单列。

## 验证方式

使用现有生成安装脚本及隔离 Linux 安装／升级入口，配合可记录请求的真实 HTTP／SOCKS 测试代理，观察实际管理请求与下载。用独立可见目标证明探测和业务未走代理。SNI 保持两域名共享连接，重启或断开代理后核对生效确认、实际运行和用量；只读配置检查不能代替真实网络结果。

向 11 提供已可用的代理配置、下载及安装行为，避免菜单另做一套代理规则。向 14 留下真实网络、旧配置保留、来源和 SNI 重启确认的证据。
