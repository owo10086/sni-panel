## 完成标准

- [ ] 转发组已有活动成员时，测试从该成员的真实副本发出，核对主规则、组、成员、实际主机和隧道关系；不能取到另一条共端口域名或其他用户的副本。
- [ ] 主入口 A 恢复、当前 B 承接且不自动回切时，点击测试仍从 B 发出；转发链保持链成员原顺序，不把活动成员插到链首。
- [ ] 无可测试活动入口时按上游给出明确结果；无 DDNS、无已选成员而按上游选可用成员的情形，不能显示成已选定新的 SNI 主入口。
- [ ] 点击时固定执行主机、成员副本、目标地址、端口和方法。排队后改目标或切成员，旧任务不变，新任务使用新配置；结果显示本次实际来源，不用现在的成员冒充。
- [ ] 保留本地普通测试的点击时快照及校验，与新增组测试同时可用；两类结果都写到正确任务和历史，不丢原有普通测试记录。
- [ ] 权限在创建和读取前检查，上报核对任务实际执行主机；普通用户不能借规则编号测试或读取他人资源，合法共享 443 不放宽这些检查。
- [ ] SNI 测试说明准确：仅表示选定主机到保存目标的 TCP 可达，Ping 只表示对应探测；不宣称完成指定域名的 TLS 分流或业务握手。
- [ ] 手动测试成功、目标可达和 Agent 在线不能替代完整分流配置生效或报告新鲜度，不改变现有 SNI DDNS、观察等待或自动回切结果。
- [ ] 保留根规则手动结果与成员自动曲线各自的读取口径，不为让样本出现在曲线里重复写入或改变自动健康判断。
- [ ] 网页中英文和手机展示能分清来源、目标、排队、成功或失败，保留原有单机、隧道和转发链测试。
- [ ] 运行现有派发、手动批次、来源展示以及新增活动成员检查；提供点击后切换、改目标、无权限、重复或迟到回报的实际结果。

## 验证方式

从测试创建业务接口到实际任务派发和回报观察结果，复用现有手动测试、批次、结果身份与来源展示检查；网页核对点击前后来源。用两个域名共用 443 的例子证明目标测试和真实域名分流是不同验证，不新增 SNI 检测产品功能。

向 03 留下主规则手动结果与成员自动记录的来源说明；向 14 提供原普通测试仍可用、任务快照稳定及手测不改变 SNI 入口资格的证据。
