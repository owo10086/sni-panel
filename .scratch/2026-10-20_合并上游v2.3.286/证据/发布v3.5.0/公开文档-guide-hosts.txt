data-v-cb09c906><!--[--><!--]--><main class="main" data-v-cb09c906><div style="position:relative;" class="vp-doc _sni-panel_guide_hosts" data-v-cb09c906><div><h1 id="主机管理" tabindex="-1">主机管理 <a class="header-anchor" href="#主机管理" aria-label="Permalink to &quot;主机管理&quot;">​</a></h1><p>主机管理用于查看和维护所有已接入的 Agent 主机。</p><h2 id="主机列表" tabindex="-1">主机列表 <a class="header-anchor" href="#主机列表" aria-label="Permalink to &quot;主机列表&quot;">​</a></h2><p>主机列表展示每台主机的实时状态，包括：</p><ul><li><strong>在线/离线状态</strong> — 绿色表示在线，红色表示离线。</li><li><strong>延迟</strong> — 面板与 Agent 之间的往返延迟，反映连接质量。</li><li><strong>Agent 版本</strong> — 当前运行的 Agent 版本号。</li><li><strong>CPU、内存、磁盘占用</strong> — 主机资源使用情况。</li><li><strong>系统负载</strong> — 系统平均负载。</li><li><strong>公网 IPv4 / IPv6</strong> — Agent 检测到的公网地址。</li><li><strong>内网 IP</strong> — 主机内网地址。</li><li><strong>网卡信息</strong> — 网络接口列表。</li><li><strong>转发状态</strong> — 当前转发规则的运行情况。</li><li><strong>流量数据</strong> — 累计上下行流量统计。</li></ul><p><img src="/sni-panel/assets/hosts-overview.Bq5UPipa.png" alt="主机列表集中展示在线状态、上报地址、运行时间和资源占用"></p><h2 id="多-ip-与主地址选择" tabindex="-1">多 IP 与主地址选择 <a class="header-anchor" href="#多-ip-与主地址选择" aria-label="Permalink to &quot;多 IP 与主地址选择&quot;">​</a></h2><p>更新 Agent 后，在「编辑主机 → 基本信息 → Agent 检测 IP」分别选择 <strong>IPv4 主 IP</strong> 和 <strong>IPv6 主 IP</strong>。同一主机的多个公网 IPv4、IPv6 会各自汇总为下拉选项；默认自动选择，也可分别固定一个地址。</p><ul><li>Agent 检测已启用网卡上绑定的公网地址，并保留公网出口探测，约每分钟刷新缓存。过滤私网、回环、链路本地地址；系统支持读取地址状态时优先使用稳定 IPv6，忽略网卡的临时/废弃 IPv6，没有稳定地址时仍可回退到公网出口探测。</li><li>已选地址仍在检测列表时，后续上报不会覆盖选择；地址消失则回退到可用地址，重新检测到原地址后自动恢复原选择。</li><li>主 IP 用于面板中的默认入口与关联链路地址，不会修改操作系统网卡、默认路由或出站源地址。手动填写的入口/隧道入口地址仍优先。</li><li>商家只做 NAT 映射、没有绑定到系统的额外公网 IP 无法可靠自动发现；系统已绑定的公网别名地址可自动发现。旧 Agent 仍可上报单地址，多地址发现需升级 Agent。</li><li>管理员和主机所有者可以修改主地址，单纯获得资源使用授权的用户不能修改。</li></ul><p>DDNS 可选择仅同步两类主 IP，或同步对应协议的全部检测地址，详见 <a href="./ddns#主机多-ip-与双栈">DDNS 配置</a>。</p><h2 id="在线与离线" tabindex="-1">在线与离线 <a class="header-anchor" href="#在线与离线" aria-label="Permalink to &quot;在线与离线&quot;">​</a></h2><p>绿色表示在线，红色表示离线。</p><p>如果主机离线，常见原因：</p><ul><li>Agent 服务没有运行。</li><li>Agent 配置中的面板地址不对。</li><li>面板域名、端口或反向代理不可访问。</li><li>服务器防火墙阻止连接。</li><li>面板公开地址修改后，Agent 还在使用旧地址。</li></ul><p>在 Agent 主机上可以查看日志排查：</p><div class="language-bash vp-adaptive-theme"><button title="Copy Code" class="copy"></button><span class="lang">bash</span><pre class="shiki shiki-themes github-light github-dark vp-code" tabindex="0"><code><span class="line"><span style="--shiki-light:#6F42C1;--shiki-dark:#B392F0;">journalctl</span><span style="--shiki-light:#005CC5;--shiki-dark:#79B8FF;"> -u</span><span style="--shiki-light:#032F62;--shiki-dark:#9ECBFF;"> forwardx-agent</span><span style="--shiki-light:#005CC5;--shiki-dark:#79B8FF;"> -n</span><span style="--shiki-light:#005CC5;--shiki-dark:#79B8FF;"> 300</span><span style="--shiki-light:#005CC5;--shiki-dark:#79B8FF;"> --no-pager</span></span></code></pre></div><p>Agent 配置文件位于 <code>/etc/forwardx/agent/config.json</code>，日志目录位于 <code>/var/log/forwardx-agent/</code>。</p><h3 id="上下线通知" tabindex="-1">上下线通知 <a class="header-anchor" href="#上下线通知" aria-label="Permalink to &quot;上下线通知&quot;">​</a></h3><p>管理员可在「编辑主机 → 其他配置」设置「上下线通知」，新建主机和已有主机默认开启。实际推送仍需在系统设置启用所选通知渠道（Telegram / Discord）及主机上下线通知，并由管理员绑定对应账号。</p><p>关闭期间不再推送该主机的上线、离线消息，发送前也会检查开关以屏蔽排队中的离线提醒；不影响在线状态、离线历史、故障转移及流量/续费提醒。重新开启不会主动补发已跳过的消息。</p><p><img src="/sni-panel/assets/host-notifications.KifBtrOr.png" alt="编辑主机的其他配置中提供独立的上下线通知开关"></p><p><em>上游开发演示：上下线通知已开启；流量故障转移和流量耗尽提醒为不同设置。</em></p><h2 id="主机信息维护" tabindex="-1">主机信息维护 <a class="header-anchor" href="#主机信息维护" aria-label="Permalink to &quot;主机信息维护&quot;">​</a></h2><p>建议给每台主机填写清晰的名称，例如：</p><div class="language-text vp-adaptive-theme"><button title="Copy Code" class="copy"></button><span class="lang">text</span><pre class="shiki shiki-themes github-light github-dark vp-code" tabindex="0"><code><span class="line"><span>香港入口-1</span></span>
<span class="line"><span>日本落地-1</span></span>
<span class="line"><span>美国中转-1</span></span></code></pre></div><p>也可以设置：</p><ul><li><strong>备注</strong> — 记录主机用途或额外说明。</li><li><strong>手动入口 IP 或域名</strong> — 覆盖自动检测的公网地址。</li><li><strong>DDNS 域名</strong> — 绑定动态域名，支持 DDNS 故障转移。</li><li><strong>网卡名称</strong> — 指定流量统计所使用的网卡。</li></ul><p>主机名越清楚，后续创建转发规则、隧道和链路时越不容易选错。</p><h2 id="用户授权与主机可见性" tabindex="-1">用户授权与主机可见性 <a class="header-anchor" href="#用户授权与主机可见性" aria-label="Permalink to &quot;用户授权与主机可见性&quot;">​</a></h2><p>在「用户管理 → 授权」分别配置端口转发、转发链/转发组和隧道的使用权限，不以是否分配成员主机代替资源授权。普通用户可能通过有效套餐或按量计费产品获得使用权限，不一定需要逐台手动授权。</p><p>网络测试的主机列表另外受主机权限控制：用户自有、通过主机授权或有效套餐授权获得的主机可见；仅有链路使用权限，不会让其成员主机单独出现在网络测试中。管理员可管理全部主机。</p><p>完整操作及撤销授权后的规则行为见 <a href="./users-billing#权限分配">用户、套餐和权限</a>。</p><h2 id="国内健康检测与自动换-ip" tabindex="-1">国内健康检测与自动换 IP <a class="header-anchor" href="#国内健康检测与自动换-ip" aria-label="Permalink to &quot;国内健康检测与自动换 IP&quot;">​</a></h2><p>入口：管理员进入「主机管理 → 服务 → 添加/编辑服务」，在顶部左右选项中选择「常规探测」或「国内健康检测」，默认常规探测。国内健康检测每项只选择一台主机，目标填写稳定的国内<strong>固定公网 IP</strong>，方法可选 TCPing（需端口）或 Ping（ICMP）。选中后显示专属的异常判定、通知和自动换 IP 配置，不再使用底部开关切换模式。检测由所选主机发起，不是由面板服务器发起。</p><p>默认同时满足「连续失败 3 次」和「失败持续 120 秒」才判定异常，连续成功 2 次恢复。采样中断后重新积累失败次数；服务暂停或删除后不再触发新动作。检测间隔须为 5–300 秒。</p><div class="warning custom-block"><p class="custom-block-title">检测结论</p><p>探测失败也可能是目标维护、禁止 ICMP、端口关闭、路由故障等原因，不能单凭一次出站探测确认 IP 被墙。界面显示“疑似国内连通异常”，达到设定条件后仍会直接执行你开启的后续操作，<strong>不等待人工或 AI 回复确认</strong>。请选择可靠目标并合理设置判定时长，避免误触发付费换 IP。</p></div><h3 id="通知与商家接口" tabindex="-1">通知与商家接口 <a class="header-anchor" href="#通知与商家接口" aria-label="Permalink to &quot;通知与商家接口&quot;">​</a></h3><ul><li>「通知用户」默认开启，可指定接收用户；默认通知主机所有者，同时通知服务创建者。使用已配置的 Telegram / Discord 通道，接收人需绑定账号。</li><li>「自动切换 IP」默认关闭。启用前核实商家费用、重启影响和接口是否允许从该主机访问。</li><li>必须同步更新目标主机的 Agent；不支持该功能或近期没有有效心跳时，面板提示不可用，不会改由面板代发请求。</li></ul><p>商家给每台 VDS 提供内网管理通道时，例如：</p><div class="language-text vp-adaptive-theme"><button title="Copy Code" class="copy"></button><span class="lang">text</span><pre class="shiki shiki-themes github-light github-dark vp-code" tabindex="0"><code><span class="line"><span>http://10.0.0.1/api/changeip?token=你的商家令牌</span></span></code></pre></div><p>在接口地址填写商家提供的<strong>实际内网地址</strong>，请求方法选择 <code>GET</code>，无需安装或执行 curl 脚本。任务仅通过加密通讯发给被检测主机的 Agent，由该 Agent 原生发送 HTTP 请求。支持 HTTP / HTTPS、GET / POST / PUT、自定义请求头和请求体；HTTP 只建议用于可信内网，公网请用 HTTPS。禁止跳转、环境代理及本机环回、链路本地/云元数据等受限目标；内网私有管理地址可用。</p><p>可用占位符：<code></code>、<code></code>、<code></code>、<code></code>。其中 <code>ip</code> 为主机当前入口地址；令牌不要放到通知文案或公开截图中。</p><p>接口结果可选两种判断方式：</p><ul><li><strong>HTTP 2xx：请求已接收</strong>：适合只有一条 GET 请求、暂未提供响应结构的商家。仅记录接口接收请求，不声称已经换好 IP，实际结果以后续探测和商家状态为准。</li><li><strong>JSON 字段严格匹配</strong>：有响应文档时推荐。例如返回 <code>{&quot;success&quot;:true,&quot;data&quot;:{&quot;ip&quot;:&quot;新公网 IP&quot;}}</code>，成功字段填 <code>success</code>，预期值填 <code>true</code>。布尔值 <code>true</code> 与字符串 <code>&quot;true&quot;</code> 不等价。</li></ul><p>如需同步面板地址，填写新 IP 的 JSON 路径（上例为 <code>data.ip</code>），选择更新主机入口或同时更新隧道入口；只接受与旧地址不同的有效公网 IP，并刷新关联链路。异步换 IP 接口不自动轮询商家任务：未返回新 IP 时选择“不修改面板地址”。<strong>未手动指定入口地址</strong>的主机可等待 Agent 重新上报；手动指定过的地址仍需自行更新。不要把更新主机入口误认为会更改商家网络或其他服务的出口配置。入口地址同步后先刷新相关配置，再按现有入口健康、观察等待和发布前复核重新评估组解析；涉及 SNI 分流内容变化时，旧报告不能证明新配置生效，须重新取得完整确认。主机自身 DDNS 仍使用 Agent 实际报告的主 IP，手动入口地址不会直接替代该值。</p><h3 id="自动执行保护与排查" tabindex="-1">自动执行保护与排查 <a class="header-anchor" href="#自动执行保护与排查" aria-label="Permalink to &quot;自动执行保护与排查&quot;">​</a></h3><p>同一异常最多请求一次；默认每台主机换 IP 冷却 1 小时、滚动 24 小时最多 3 次，多项服务共用该主机的请求历史。面板先保存请求意图，Agent 在本地持久化防重复标记，再调用商家。超时、断联或面板/Agent 重启后不会自动重发可能收费的请求。</p><p>接口结果不明确时停止该主机后续自动换 IP，管理员核对商家任务是否结束后，可在服务编辑窗口使用「已核对商家结果」解除保护；按钮至少等待 150 秒才可用。此操作<strong>仅处理异常结果，不是正常执行前的审批</strong>，也不会重发原请求。同一主机另一项服务也可查看和解除遗留保护，删除服务不会抹掉请求历史。</p><p>Agent 日志搜索 <code>IP switch task=</code>，可看到固定的结果分类和 HTTP 状态；面板日志搜索 <code>[ChinaHealth]</code>。日志不记录接口令牌、请求体或商家原始响应。接口凭据加密保存、编辑时不回显；只更改检测参数会保留原凭据，替换接口需重新填写完整配置。数据库迁移合并不自动移植这类自动操作配置；更换 JWT 密钥后也需重新填写接口，避免误用旧凭据。</p><h2 id="nat-主机与可用端口" tabindex="-1">NAT 主机与可用端口 <a class="header-anchor" href="#nat-主机与可用端口" aria-label="Permalink to &quot;NAT 主机与可用端口&quot;">​</a></h2><p>NAT 主机应在主机配置中填写供应商实际映射的可用端口范围，TCP / UDP 分别按供应商能力放行。范围配置只限制面板分配，不会替你创建供应商的 NAT 映射或修改安全组。</p><p>业务入口、隧道承载监听与部分模式的规则出口监听可能是不同端口。需要规则独立出口端口的模式会占用额外端口；不要把“隧道测试通”当作业务端口已经映射。Nginx Stream 隧道规则复用该隧道的监听端口；变更模式后检查实际规则端口与运行状态。</p><h2 id="流量故障转移" tabindex="-1">流量故障转移 <a class="header-anchor" href="#流量故障转移" aria-label="Permalink to &quot;流量故障转移&quot;">​</a></h2><p>在主机编辑的「其他配置」设置大于 0 的套餐流量、计量方式，再开启「流量故障转移」并设置阈值（1%–100%）。达到阈值后，主机暂停参与转发组、入口组和出口组调度，不删除组成员，也不改变 Agent 在线状态。</p><p>计量按当前周期的主机流量与所选方式计算，见 <a href="./traffic-latency">流量口径</a>。重置流量、提高额度使其低于阈值，或关闭开关后重新参与调度；恢复依赖面板重新计算与 Agent 同步。没有可用备用成员时，排除主机并不保证业务可继续，需提前配置备用路径。</p><p>此开关不是单条规则额度或账户额度，也不是主机断电开关；不要用它代替 <a href="./rules#单条规则限额与有效期">单规则限额</a>。</p><h2 id="用量修正" tabindex="-1">用量修正 <a class="header-anchor" href="#用量修正" aria-label="Permalink to &quot;用量修正&quot;">​</a></h2><p>管理员在主机操作菜单选择「用量修正」，弹窗默认填入当前统计的已用流量。核对主机和当前计量方式，输入修正后的总用量（GB，不能小于 0），点击「保存修正」。输入的是新的累计值，不是本次增减量。</p><p>后续上报在修正后的用量上继续累计。此操作只修正面板的主机累计用量，不修改 Agent 系统累计流量，也不替代用户流量重置或账务退款。若开启了流量故障转移，修正后还应核对是否达到调度阈值。</p><h2 id="安全移除主机" tabindex="-1">安全移除主机 <a class="header-anchor" href="#安全移除主机" aria-label="Permalink to &quot;安全移除主机&quot;">​</a></h2><p>先从转发组、转发链、入口组 / 出口组与隧道中移除对应成员。保存成员变更会同步模板引用，未改变的健康成员规则保留；仍有真实依赖时，删除弹窗会列出关联资源及处理入口。</p><p>在线主机需等 Agent 完成清理；离线清理必须明确确认，不会绕过真实依赖。移除面板记录不会停止离线主机上的程序，需要自行停止或卸载 Agent。预览只显示有权查看的名称，其他人的关联配置由管理员处理；最终删除会再次检查当前引用、归属与在线状态。若只修改了业务目标而未移除资源成员，仍不能直接删除主机。</p><h2 id="主机排序" tabindex="-1">主机排序 <a class="header-anchor" href="#主机排序" aria-label="Permalink to &quot;主机排序&quot;">​</a></h2><p>主机管理中的排序通过拖动完成，不需要手动填写排序数字。</p><ul><li><strong>无分组时</strong> — 在主机列表中直接拖动调整顺序。</li><li><strong>有分组时</strong> — 「全部」视图按分组顺序汇总展示，不支持直接拖动。切换到具体分组后，只调整该分组内的主机顺序。</li><li>主机分组、Agent Token 和主机探测服务也支持拖动排序。</li></ul><h2 id="mimic-环境检测" tabindex="-1">mimic 环境检测 <a class="header-anchor" href="#mimic-环境检测" aria-label="Permalink to &quot;mimic 环境检测&quot;">​</a></h2><p>mimic 是基于 eBPF 的 UDP 混淆方案（来自 <a href="https://github.com/hack3ric/mimic" target="_blank" rel="noreferrer">hack3ric/mimic</a>，GPL-2.0-only，当前版本 v0.7.1），需要满足特定的内核与权限条件。面板会自动检测每台主机的 mimic 运行环境，并在主机列表中显示检测结果：</p><table tabindex="0"><thead><tr><th>状态</th><th>含义</th></tr></thead><tbody><tr><td>支持</td><td>内核版本 ≥ 6.1，XDP 入站和 TC 出站 eBPF 钩子可用，可正常使用 mimic</td></tr><tr><td>内核版本不足</td><td>当前内核版本低于 6.1，不支持所需的 eBPF 特性</td></tr><tr><td>eBPF 不可用</td><td>系统未加载必要的 eBPF 模块或缺少相应权限</td></tr><tr><td>未检测</td><td>Agent 版本过旧或检测尚未完成</td></tr></tbody></table><p>如果需要使用 mimic UDP 混淆功能，请确保主机内核版本不低于 Linux 6.1，并确认 XDP 入站和 TC 出站 eBPF 功能可用。Agent 会在 XDP <code>native</code> 与 <code>skb</code> 模式之间自动回退，无需在面板手动切换。</p><h2 id="ipv6-检测" tabindex="-1">IPv6 检测 <a class="header-anchor" href="#ipv6-检测" aria-label="Permalink to &quot;IPv6 检测&quot;">​</a></h2><p>如果 IPv6 地址检测不到，先确认服务器自身是否有可用 IPv6：</p><div class="language-bash vp-adaptive-theme"><button title="Copy Code" class="copy"></button><span class="lang">bash</span><pre aria-label="Permalink to &quot;流量故障转移&quot;">​</a></h2><p>主机设置中可以启用“流量故障转移”，并设置 1—100% 的阈值，默认关闭、默认阈值为 100%。只有开启且主机流量限额大于零时才生效，使用主机已有的上下行、出站或较大方向计量口径。</p><p>达到阈值后，该主机暂时退出转发组、故障转移和隧道入口/出口组。保存的成员、端口和启用配置保留；流量重置或关闭开关后重新参与，仍须满足其他健康和权限条件。固定链的必要中继或出口不可用时，相关链暂停，面板不会绕过固定节点。</p><h2 id="从组中移除后删除主机" tabindex="-1">从组中移除后删除主机 <a class="header-anchor" href="#从组中移除后删除主机" aria-label="Permalink to &quot;从组中移除后删除主机&quot;">​</a></h2><p>保存成员列表后，系统会解除已移除主机在该组中的规则引用，并通知旧主机清理对应配置。原有业务规则和用量记录继续保留。</p><p>例如，入口组由 A、B 改为只保留 B，引用它的转发链会改用 B；如果 A 没有其他用途，就可以正常删除。若 A 还被其他组使用，或仍是某条独立隧道的入口、中继、出口，需要先解除那项引用。</p><p>旧主机离线时，面板中的引用可以先释放，实际配置撤除需要等它重新连接。成员保存成功也不代表 DNS 和业务连接已经切换完成，应分别查看健康状态和解析结果。</p><p>详见<a href="./groups#成员管理">转发组和入口组的成员管理</a>。</p></div></div></main><footer
