tabindex="-1">网络诊断、资源告警与 MCP <a class="header-anchor" href="#网络诊断、资源告警与-mcp" aria-label="Permalink to &quot;网络诊断、资源告警与 MCP&quot;">​</a></h1><p>本页介绍新增的诊断、告警及外部 AI 查询功能。它们复用当前账户权限，不会因为使用 AI 而获得额外资源访问权。</p><h2 id="网络测试" tabindex="-1">网络测试 <a class="header-anchor" href="#网络测试" aria-label="Permalink to &quot;网络测试&quot;">​</a></h2><p>进入「网络测试」，按原有流程选择 Agent、测试类型及目标。</p><ul><li>Ping 结束后，已识别的输出会展示丢包率、平均/最大延迟及延迟标准差。</li><li>Traceroute / MTR 展示逐跳结果，保留超时节点；原始输出仍可查看和复制。</li><li>中间路由器可能不回应 ICMP，单跳超时或 100% 丢包不能直接解释为业务丢包，应结合末跳、TCP 和实际业务判断。</li><li>无法识别的输出只展示原文，不推算数值；执行中不展示上一轮摘要。</li></ul><p>页面下方「网络配置体检 → 开始检查」检查所选主机的 Agent 绑定、近期通讯和资源采样。复制排查报告后可发给管理员；报告不含认证密钥，但资源名称可能包含个人信息，请先检查再转发。</p><p>AI / MCP 的 <code>network.diagnose</code> 还可指定 <code>ruleId</code>，检查规则开关、运行上报、授权、有效期、所属账户和目标配置。<code>hostId</code> / <code>ruleId</code> 必须二选一。规则存在不代表用户可以查看所有内部节点详情。</p><p>配置体检不发起网络探测，不能证明目标业务连接成功，也不替代流量额度、目标服务和防火墙的进一步排查。</p><h2 id="运维看板" tabindex="-1">运维看板 <a class="header-anchor" href="#运维看板" aria-label="Permalink to &quot;运维看板&quot;">​</a></h2><p>管理员进入「运维看板 → 资源、安全与告警」。这个区域展示全局状态，不随流量区域的用户和日期筛选变化。</p><ul><li>展示最多 10 台有采样主机的近期 CPU、内存、磁盘使用率，优先展示新鲜且高负载的数据。</li><li>超过 120 秒没有新采样时标记过期，不用旧数据冒充当前状态。</li><li>基础安全检查包括管理员 2FA 覆盖、公开地址 HTTPS 配置和开放注册状态；不扫描进程、不进行入侵检测，也不验证实际证书链。</li><li>展示最多 50 条当前告警及最近 30 天的分页事件记录。</li></ul><h3 id="开启资源告警" tabindex="-1">开启资源告警 <a class="header-anchor" href="#开启资源告警" aria-label="Permalink to &quot;开启资源告警&quot;">​</a></h3><p>点击右上角「告警设置」：</p><ol><li>打开「启用持续资源告警」，默认关闭。</li><li>分别设置 CPU、内存、磁盘阈值，默认 90%；设为 0 不监控该项。</li><li>设置连续超限时长，默认 300 秒。</li><li>设置恢复观察时长，默认 60 秒。下降至阈值减 5 个百分点或更低，并持续达到恢复时长后，才记录恢复。</li><li>按需开启「发送到通知渠道」，使用现有 Telegram / Discord 渠道及管理员个人通知偏好。</li></ol><p>每台主机最多每 30 秒处理一次资源样本。采样间隔超过 120 秒会重新计算待触发/待恢复的连续时长，不因断联而自动判定恢复。已触发的告警会保留并标记采样中断。</p><p>同一状态只在触发和恢复时记录事件、发送通知，不每次心跳重复通知。修改设置会重新开始观察，不补发虚构恢复事件。此功能不会杀进程、修改防火墙或重启机器；主机上下线通知仍由原有开关独立控制。</p><h2 id="ai-精确查询" tabindex="-1">AI 精确查询 <a class="header-anchor" href="#ai-精确查询" aria-label="Permalink to &quot;AI 精确查询&quot;">​</a></h2><p>在已配置的机器人中可以询问：</p><div class="language-text vp-adaptive-theme"><button title="Copy Code" class="copy"></button><span class="lang">text</span><pre class="shiki shiki-themes github-light github-dark vp-code" tabindex="0"><code><span class="line"><span>/ask 当前有几个用户</span></span>
<span class="line"><span>/ask 普通用户有多少个</span></span>
<span class="line"><span>/ask 当前流量排行前三个</span></span>
<span class="line"><span>/ask 昨天主机流量前五个</span></span>

Origin，只允许与系统设置的面板公开地址同源。</p><h3 id="能力和边界" tabindex="-1">能力和边界 <a class="header-anchor" href="#能力和边界" aria-label="Permalink to &quot;能力和边界&quot;">​</a></h3><ul><li>只开放现有只读工具：精确用户统计/搜索、流量排行、可见规则/主机/隧道、仪表盘、订阅、网络配置体检等。</li><li>管理员另可查询资源告警、安全配置、账务及白名单内的系统设置，不返回密码、密钥或任意系统设置。</li><li>令牌管理和 MCP 请求均在服务端校验管理员身份，普通用户不能创建、列出、撤销令牌或调用接口。管理员令牌权限较大，谨慎交给第三方模型。即使不含密钥，业务数据、IP 和资源名称也可能敏感。</li><li>不提供任意 SQL、命令执行、任意 HTTP 代理或写操作。修改仍在面板或机器人确认流程中完成。</li><li>单次 JSON 请求上限 64 KiB；每 IP 每分钟最多 120 个请求，每账户每分钟最多 30 次工具查询，超限返回 429。</li><li><code>401</code> 检查 Bearer 请求头、有效期和账户状态；<code>403</code> 检查管理员身份、Origin 与公开地址；<code>405</code> 检查传输是否使用 POST；<code>413</code> 缩小请求；<code>429</code> 降低频率。</li></ul><p>完整数据库备份可能包含令牌哈希及告警历史，仍需妥善保管；完整恢复后未过期令牌可能继续有效。核心配置合并迁移不迁移这些新增表，迁移后需重新创建令牌并重新观察告警。</p><h2 id="中转建连失败切换" tabindex="-1">中转建连失败切换 <a class="header-anchor" href="#中转建连失败切换" aria-label="Permalink to &quot;中转建连失败切换&quot;">​</a></h2><p>FXP 在已有多候选节点配置下，建连/认证或发送初始 hello 失败时，会关闭失败连接并尝试其他候选节点；同一次建立过程对每个候选最多尝试一次。修正了同端口不同 IP 时故障节点识别可能混淆的问题。</p><p>这是<strong>业务数据发送前的建连失败切换</strong>，不是连接建立后的断点续传。已传输业务数据的 TCP 连接不会跨中转盲目重放，避免重复提交或数据乱序；也没有新增并行中转组或序号/ACK/重组协议。</p><h2 id="后续验证" tabindex="-1">后续验证 <a class="header-anchor" href="#后续验证" aria-label="Permalink to &quot;后续验证&quot;">​</a></h2><ul><li>已建立连接的跨中转恢复/重传协议尚未实现，需要另行设计与联调。</li><li>新增统计和告警数据库路径已做 SQLite 集成测试，仍需 MySQL / PostgreSQL 实库验证。</li><li>仍需 Linux 多节点断网、丢包与长时间负载验证，以及手机/桌面浏览器视觉验收。</li><li>Windows 上部分现有 V3 会话测试在修改前也会失败，应单独跟踪，不视为本次新增测试通过。</li></ul></div></div></main><footer class="VPDocFooter" data-v-cb09c906 data-v-2a865e41><!--[--><!--]--><div
