# 01 — 给场景测试加普通规则主机型转发组

**What to build:** 前置准备，对外零行为变化。SNI 转发组健康测试已有一套高层场景测试：独立进程、真实 SQLite、通过管理接口改组、通过真实 Agent 心跳上报运行状态、webhook 接收 DDNS、模拟时钟。这套测试目前只初始化 SNI 组。本单在同一套做法里增加一个与 tj2 同类的普通规则主机型转发组（`groupType=host`、`groupMode=failover`，两个以上成员，多条普通规则，可配置故障时间与恢复时间），并提供上报普通规则运行状态、带运行诊断的失败报告、推进时间、读取 DDNS 请求和 Agent 期望配置的辅助手段。后续工单都在这个组上写行为测试。

只写当前已有、并且本 spec 不会改变的行为作为基线，避免后续工单改写本单的断言。

**Blocked by:** None — can start immediately

**Status:** completed

- [x] 普通规则组可通过管理接口建组、加规则、改成员，Agent 通过真实心跳接口收到期望配置并上报运行
- [x] 基线场景：新建组后首个成员规则运行，组域名经 webhook 发布到该成员地址
- [x] 基线场景：当前入口 Agent 离线超过故障时间后切到备用成员；原入口恢复后仍须等满恢复时间才可回切
- [x] 基线场景：普通业务目标检测失败或缺失不阻止选入口、不阻塞 DDNS（ADR-0008）
- [x] 测试可读取某台入口在任一时刻的期望配置中是否仍含该组规则，供后续先接后断断言使用
- [x] SNI 转发组健康测试与主备组回归测试原有场景全部保持通过，无断言修改
