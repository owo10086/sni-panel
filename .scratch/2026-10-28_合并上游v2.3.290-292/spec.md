# 累计合入上游 v2.3.290–v2.3.292：规格

**Status:** completed（本地实施与隔离验收完成，未发布）

**Decision date:** 2026-10-28

**确认与授权：** 用户已确认累计合入范围，选择保留套餐、按量管理的卡片／表格双视图，并调用 `$to-spec`、回复“同意”保存本规格，随后明确要求使用 Codex CLI 子代理审查并补齐。规格与拆单审查完成后，用户通过 `$implement 开始实施，如果可以并行就调用 Codex CLI` 明确授权本轮代码实施、隔离测试和当前分支中文本地提交。未授权推送、标签、部署或生产变更。实施起点为 `532f9cb5eae7fac700f8f619e826ea4ed48b6fbc`（本地 3.8.0）；已提交的独立交接修复作为必须保留的基线，既有其他任务未提交文件继续保护。

## Problem Statement

本地 sni-panel 已发布 v3.8.0，累计兼容上游 v2.3.289。上游随后发布 v2.3.290、v2.3.291 和 v2.3.292，带来批量规则管理与后台队列、Agent 换机接管、连接数展示、受限 LXC 流量统计、数据库与鉴权优化、登录签名密钥加固及请求接收保护等变化。维护者希望用一轮任务累计兼容这些增量，同时保留本地 SNI 分流、入口健康与 DDNS、Docker 共存、权限及计费行为。

本地长期采用功能兼容移植，上游近期提交没有直接成为本地提交的祖先。直接普通合并会混入早期历史差异；仅复制上游完整文件又会覆盖本地能力。讨论中确认的一项实际功能取舍是：上游 290 移除了套餐和按量管理的表格视图，而用户选择继续保留本地卡片／表格切换。

用户另行核查了分页选择和“转发组调整后立即切换解析”：290–292 没有补齐通用批量弹窗的分页勾选，也没有实现管理员调整免恢复观察、先接后断、DDNS 切换后按 TTL 撤销等要求。这些不能被误记为本轮上游已经提供的功能。

## Solution

以已兼容的上游 v2.3.289 为比较起点，一轮累计纳入 v2.3.290、v2.3.291、v2.3.292 的网页、服务端、Agent 和 FXP 有效增量，统一完成后续验证和本地交付。三个版本按递增关系核对，最终覆盖到已核实的 292 提交；不是只处理 291 到 292 的变化，也不要求拆成三轮独立发布。

套餐与按量管理保留卡片／表格双视图及既有偏好，同时兼容上游卡片改进。原生客户端和作者赞助入口按长期约定排除。本地入口健康、SNI 完整分流确认、权限、配额、计费与 Docker 共存逻辑继续保留。

今日两项转发组修复继续由各自议题处理，通用批量分页选择不额外扩展。本轮后续实施的交付终点为本地兼容实现、验证和中文提交；已在当前分支完成本地实施、隔离验证和中文提交，未执行远程发布。

## User Stories

1. As a 面板维护者, I want 一轮累计合入 290、291、292 的有效增量, so that 不遗漏中间版本的新增与修复。
2. As a 面板维护者, I want 按已核实的提交比较上游变化, so that 合入范围明确且后续可以复核。
3. As a 面板维护者, I want 保留实施开始时已有的本地成果, so that 上游升级不会回退其他任务的修复。
4. As a 套餐管理员, I want 继续切换套餐管理的卡片和表格视图, so that 可以选择适合浏览或集中对比的展示方式。
5. As a 按量资源管理员, I want 继续切换按量管理的卡片和表格视图, so that 已有管理方式不因上游删表格而消失。
6. As a 管理员, I want 两种视图保留已有偏好及编辑、删除和排序能力, so that 界面兼容不影响管理操作。
7. As a 卡片视图用户, I want 获得上游布局和窄屏改进, so that 保留表格不会阻止卡片体验更新。
8. As a 规则用户, I want 使用分类下拉和分步弹窗进行批量管理, so that 操作入口清晰且确认范围可见。
9. As a 规则用户, I want 批量启用、暂停、重启和删除规则, so that 不必重复进行同类操作。
10. As a 规则用户, I want 批量重启保留暂停状态和统计, so that 重启不会误启用暂停规则或清空用量。
11. As a 规则用户, I want 查看逐项失败原因并只重试已确认失败的项目, so that 不必对已经成功或结果未知的项目重复操作。
12. As a 个人分组用户, I want 按加入、移出及目标分组筛选可以变更的规则, so that 分组调整范围准确。
13. As a 个人分组用户, I want 继续分页勾选并保留跨页选择, so that 已有分组整理能力不回退。
14. As a 规则用户, I want 保留本地规则主列表的全选本页及翻页清空行为, so that 批量选择范围保持可预期。
15. As a 批量导入用户, I want 导入端口范围、端口列表及逐行监听端口和目标, so that 支持上游新增输入方式。
16. As a 规则导出用户, I want TXT 导出可以重新导入并保留监听端口, so that 规则转移不必重新整理文本。
17. As a SNI 导入用户, I want 继续整批保存、集中整理配置并保留原始行号和逐项结果, so that 后台队列不会使批量导入退回逐条反复下发。
18. As a 混合导入用户, I want 普通和 SNI 规则继续按既有顺序竞争额度与端口, so that 新队列不改变导入结果的既定语义。
19. As a 批量操作用户, I want 服务端后台执行并展示数量、百分比和逐项结果, so that 可以知道操作进度和实际完成情况。
20. As a 批量操作用户, I want 切换页面后任务继续执行并可查看进度, so that 不必一直停留在原页面。
21. As a 批量操作用户, I want 停止尚未开始的剩余任务并防止重复提交, so that 能控制后续执行范围。
22. As a 账号所有者, I want 后台任务继续受当前会话、归属用户和资源权限约束, so that 排队不会绕过撤权或跨账号访问限制。

## Implementation Decisions

1. **累计范围与比较对象。** 本地调查时 HEAD 为 `9dea220de5bf4dc8bd1289214e8a2a37ba948617`，已发布 v3.8.0；功能兼容基线为上游 v2.3.289，提交 `e73e01b0c3e57da8190c22bbe490170184d50d2e`。本轮累计核对 290、291、292 以及其间的修复提交，最终覆盖到 `80c0ed25dbb7bec20971eae816073b6c315262a8`。调查时上游 main 与 292 相同；后续新版本不自动进入本轮。
2. **一轮累计兼容。** 以 289 至 292 的完整增量作为范围，按版本辨认变化、按功能适配本地模块，统一验证交付。不要求依次制作三个本地发布，不漏掉 290、291，也不因本地历史未包含上游提交而重复覆盖已经兼容的旧能力。
3. **处理方式与清单。** 延续功能兼容移植，对每项上游有效变化确定纳入、按本地约定适配或长期排除的归属。预演冲突数量仅用于定位，不能替代完整增量核对。无需使用普通整分支合并建立上游祖先关系，不创建工作树。
4. **涉及模块。** 覆盖规则管理和导入导出、个人分组、后台批量任务、Agent 安装身份与同步、Agent／FXP 运行时、主机指标和统计、端口转发资源展示流量、AI 模型选择、服务告警、数据库与鉴权、登录签名密钥、请求接收与解析、日志、网页布局、验证与交付流程。沿用现有模块与管理接口，不引入无关架构重构。
5. **双视图明确保留。** 用户选择 A：套餐管理和按量管理保留卡片／表格切换及既有偏好、编辑、删除和排序能力，同时合入上游卡片布局与窄屏改进。不能直接采用上游只留卡片的删减。服务端产品、库存和计费语义保持两种视图一致。
6. **批量管理与导入导出。** 纳入分类下拉、分步操作、个人分组筛选、批量启停／重启／删除、失败重试、端口范围／列表及逐行监听端口输入、TXT 重导入。沿用本地 SNI 分类、域名校验、预览、归属用户授权、共享监听及原有输入兼容，不把普通文本解析器覆盖到 SNI 分流规则。
7. **保留集中保存。** 依据 ADR-0005，普通、SNI 及混合导入继续整批事务保存与集中整理配置，逐项保存点隔离可归属错误，公共保存失败不虚报成功，保存完成与入口生效分别确认。一个既有集中导入请求作为一个保存单元，保留其最多 500 条限制，不静默拆批削弱原事务和顺序，也不能改成逐项普通创建；混合文件按既有顺序竞争额度与端口。停止只取消尚未开始的单元，已开始的批次继续按原事务完成或回滚，不撤销已提交成果。进度按逻辑输入行计数并保留原始索引／行号，区分准备中、保存中与已提交成功，不把准备成功或保存成功显示为部署生效；公共回滚后清除暂计成功，保留确定的逐项错误，其余准确标为未保存，最终各类逐项结果合计与输入总数一致，提交后仍集中下发。
8. **后台批量任务。** 纳入上游服务端内存队列、数量／百分比进度、逐项结果、切页继续、停止剩余任务与重复提交保护，并保留有界任务数量、载荷和排队容量；队列上限不能放宽既有批量保存限制。继续使用现有规则管理权限、写入事务和运行下发边界；排队不构成授权凭证，执行仍按当前会话、角色、归属用户与资源权限处理。任务和恢复线索按面板及用户隔离，切换账号不能读取原账号结果。入队响应丢失时仅按原请求标识查询，同一归属、标识和载荷在当前进程保留记录期间去重，相同标识不同载荷拒绝；查询失败、记录过期、实例变化或提交结果未知时显示待核对，提示先核对规则，不虚报成功／失败，不自动另建任务或重放业务写入。浏览器同标签页恢复线索不等于持久化服务端任务，也不承诺永久恰好执行一次；不扩展面板重启续做或跨重启结果找回。
9. **批量重启。** 纳入上游新增重启操作，保留暂停规则的暂停状态和现有统计；只对允许重启的有效项目重新下发。兼容本地 SNI 运行确认与规则限制，不能借重启绕过授权、恢复已删除规则或重置计量。
10. **分页边界。** 保留本地已有规则主列表的每页数量、分页、全选本页及换页／筛选清空选择行为；保留个人分组每页 20 条和跨页暂存选择，兼容上游分组筛选及底栏改进。普通批量复制、编辑和导出弹窗仍按全部匹配列表处理，本轮不新增通用跨页勾选或分页弹窗。独立的全站每页条数选择需求不并入本轮；其已实施成果按实际基线保护。
11. **同 Token 换机接管。** 纳入上游安装身份机制：有效 Token 下的新安装身份可以接管，即使旧实例仍在线；已有身份的普通升级保留身份，显式重新安装产生新身份。仅升级面板且主机尚未绑定身份时，无身份旧 Agent 仍可按既有方式工作；首次升级到支持身份的 Agent 时生成、持久保存身份并首次绑定同一主机，不一概视为换到新机器。绑定后，缺失、不匹配或已退役身份不得更新当前主机状态、流量或获得 SSE 同步，退役身份不能凭重启抢回。面板隔离旧版本请求与新版 Agent 收到接管信号后主动停止同步分别验收；旧版本不承诺主动停止请求。旧实例已有转发按上游保留，没有自动撤销期限。不增加自动清理旧机服务的行为，不修改实际 Token 或替用户执行换机。
12. **身份与运行确认兼容。** 首次建立身份或新实例接管后均重新确认当前运行证据，不能沿用旧成功报告；同机首次升级不因此套用真实换机结论。保留本地可信上报时钟、完整规则清单和空清单判断、当前 SNI 分流确认及过期报告拒绝。真实换机、重启或重连须按既有确认及观察规则处理，不能套用管理员调整豁免。
13. **Agent／FXP 兼容。** 纳入目标地址校验、队列与资源占用优化、GOST 配置元数据比较及接管配套变化。明确仅升级面板、首次升级 Agent、后续保留身份升级及配套 Agent／FXP 的能力边界，新接管和运行能力须由支持该协议的组合提供，不要求旧版本具备新行为。元数据大小写归一和冲突值识别须与本地逻辑并存。维持现有隧道协议兼容和本地独立分流器角色，不据此开放未在面板启用的协议模式。
14. **连接数与受限环境统计。** 纳入主机 TCP／UDP 连接数上报、展示和相应指标处理；纳入受限 LXC 的 GOST 与已有 Guard 统计回退及配套面板配置。回退需和既有计数归属、重启计数和多入口去重兼容，不把同一流量按不同来源重复累计。
15. **展示流量与自测。** 仅管理员可重置指定端口转发资源（groupMode=port）的北京时间当日及累计展示流量，对所有用户视图生效；普通用户、其他资源类型、缺失或无效资源标识均拒绝。重置只更新展示基线，不改变实际计数、规则额度、套餐用量、计费记录、历史或运行状态，不影响关联入口组及其他端口资源；空资源不得误重置全部规则。基线持久保存，重置后新增流量正常累加，重复重置替换基线而不叠加扣减，前一天的日基线不扣减次日流量；保留原子回滚、展示缓存失效及资源删除后基线清理。自测结果按到达顺序显示，未完成项继续等待；遵守 ADR-0009 的证据语义，目标连通不能冒充外部经入口业务端口转发成功。
16. **网页与管理变化。** 纳入 AI 模型搜索／刷新／自定义输入和模型列表修复、按服务配置资源告警与管理员通知范围、网页侧边栏手势、弹窗安全区、工具栏、图表与地球视图等改进。遵守本地双语、动画偏好、品牌、来源和内容渲染边界；网页窄屏适配正常合入，不与原生客户端排除混淆。
17. **数据库繁忙与认证。** 纳入鉴权查询合并、有界积压和刷新退避，临时数据库排队或查询失败不误清凭证；真实会话失效和撤权继续生效，不用展示缓存证明用户已认证。界面恢复验证须与本地登录及升级预检流程兼容。纳入上游签名密钥校验：保留符合要求的强配置值，替换过短、占位或单字符重复等弱值；优先复用已有有效持久密钥，否则安全生成随机值并持久保存，限制文件权限并处理并发初始化。部署模板不再提供公共占位密钥；存储可写时重启保持同一密钥，不可持久化时明确警告并退回随机进程内密钥，不退回公共弱值，也不承诺重启会话持续。弱密钥替换或临时密钥变化导致的必要重新登录须与数据库繁忙引起的误退出区分，提示与日志不得泄露密钥值。
18. **查询和计费优化。** 纳入指标索引读取、批量加载套餐与附加流量、资源 ID 权限查询、批量保存设置、主机分组聚合和规则流量查询优化。维持当前账号隔离、写入前后缓存失效及实时余额、库存、配额、健康、DDNS 判断。记账用户锁、有限回滚重试须与本地嵌套事务、延后提交回调和完整回滚边界兼容，不局部重跑不可重入结算，不重复执行提交后动作。
19. **数据兼容。** 上游安装身份、展示流量基线、连接指标及其他必要数据变化按现有数据库抽象接入，支持 SQLite、MySQL、PostgreSQL 的新建与升级。保留已有安装、账户、库存、计费及历史数据；与独立任务正在新增的表结构协调，不覆盖、不重命名复用其专属状态。
20. **日志。** 采用上游按各运行环境时区保留今天、昨天、前天的策略，面板和 Agent 主日志按日归档、启动及维护时清理。保留既有目录配置与 Agent 容量保护，面板查看、筛选、分页和导出覆盖保留文件。Docker 输出、系统 journal 和安装器重定向输出继续由部署环境管理，不由应用删除。本规格描述产品日志能力，不授权当前讨论产生额外执行日志。
21. **转发组同步。** 纳入 290 批量读取成员主机、配置相等时减少重复写入等优化，保留配置变化、在线但未运行及恢复在线后的必要下发。比较范围须同时保留本地 SNI、分流器端口、限速、连接限制与上游新增字段；同步资源参数须和本地共享端口及链端口预留能力并存，不因通用比较遗漏本地字段而漏部署。
22. **入口健康与 DDNS。** 遵守 ADR-0006、ADR-0007、ADR-0008，按 ADR-0010 已确认的边界兼容独立任务成果。SNI 落地检测缺失、过期或失败不单独影响入口资格和 DDNS，当前完整分流配置仍须有效确认。仅主机型主备组的普通规则按入口自身运行与健康选择，保留流量政策、已开启的入口健康检测、真实故障计时、当前有效副本及发布前复核。主机探测服务中的国内健康检测与组入口健康检测分别定义。入口组等其他类型继续各自策略。
23. **独立修复边界。** 管理员调整免恢复观察、手动排序延迟接管、先接后断、有效切换后 TTL 撤销及重启接续由既有独立规格实施；周期性单条规则重下发问题继续按其议题调查。本轮不代为实现、关闭或宣告验收完成。若独立任务成果在合入前已经落地，须视为本地现有行为兼容保留，不回退；290 减少重复写入不能冒充这些修复。
24. **Docker 共存与端口边界。** 保留 ADR-0009 的精确 DOCKER-USER 放行、管理员拒绝优先、各防火墙前端分别判断、就地收敛与严格本机就绪。按 ADR-0003 保留裁剪与覆盖声明一致；按 ADR-0004 保留运行诊断和占用警告优先级，不恢复创建前的主机监听占用门槛。
25. **长期排除与来源。** 原生 Android、iOS／iPadOS 工程、专属版本、依赖及锁文件、更新入口、打包和发布变化按长期约定排除。网页与服务端共用文件按需要部分兼容。作者赞助／捐赠按钮及专属文案、收款信息和组件排除，许可证、开源来源与致谢保留。
26. **版本、验证流程与本地交付。** 沿用 sni-panel 独立版本序列及面板、Agent、FXP 版本一致约定，后续实施时按实际基线递增，不把上游三个发布号直接用作三次本地标签。上游必要回归接入已有验证和发布准备流程，不覆盖本地可复用验证、升级预检或恢复发布机制。获得实施授权后按功能拆中文代码提交，本轮文档核对完成后统一一次中文文档提交。
27. **工作区与权限。** 实施前重新核对 HEAD、工作区及独立任务状态，以当时实际代码作为本地基线。保留既有未提交内容，不擅自暂存、提交或清理其他任务，不创建工作树。本次仅保存这一份规格，不另建审查报告、提示词、执行总结或日志；未来远程操作只允许在用户授权范围内使用 sni-panel，禁止向 origin 推送。
28. **安装命令复制确认。** 每次复制安装命令前重新查询当前用户有权使用的 Token 及绑定主机；已绑定时展示主机名称、在线状态和新安装将接管的影响，确认后才写入剪贴板，取消不复制。不能仅使用打开弹窗时的缓存绑定状态，打开后绑定变化也须反映在本次复制确认中。复制不等于执行安装；安装命令保留 sni-panel 来源，不改回上游仓库或触发真实换机。
29. **请求接收保护。** 纳入 JSON／表单在完整缓冲与解析前的大小、总并发／单 IP 容量、大请求预算及读取超时保护，压缩和分块传输不能绕过限制。对超大、繁忙、超时和无效载荷分别明确返回 413、429（含重试提示）、408 和 400；响应结束、中断和断连均正确释放容量，大型已解析请求的预算保留至响应结束。保留合法插件归档上传和小型 Agent 请求的正常使用，不扩大为新的通用抗攻击系统，也不把所有内部阈值固化为产品要求。

## Testing Decisions

以下为本轮实施的验证要求；完成证据在本规格末尾统一更新，未完成项不记为通过。测试优先验证用户可观察的结果、权限、计费与运行证据，不直接断言队列实现、私有窗口函数或内部调用次数；已有可测边界能够覆盖时不新增测试专用接口。

主要使用现有带账号上下文的管理接口作为保存与批量执行入口，结合真实测试数据库、Agent 注册／心跳和期望状态、受控 DDNS 提供方。网页验证补足后台接口无法证明的视图、进度和窄屏行为；真实 Agent／FXP 与隔离客户端验证数据面。沿用既有测试先例，不另建一套业务 API 或验证框架。
