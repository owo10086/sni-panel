# 11: 同 Token 接管、旧 Agent 迁移与当前运行确认

**What to build:** 有效 Token 的新安装实例可接管管理并恢复规则，旧版 Agent 渐进升级有清晰边界，旧报告不能冒充当前实例运行成功。

**Blocked by:** None（实施授权已获得）。

**Status:** completed（本地实施与隔离验收完成，未发布）

**依据：** [本轮规格](../spec.md)，用户故事 24、25、26、27、43、44、45、46、56；实施决定 11、12、13、19、22、23。

**实施边界：** 用户已通过 `$implement 开始实施` 授权本地代码实施、隔离验证与当前分支中文提交。按本轮固定累计范围兼容，遵守长期约定与排除项，保护实际基线及独立任务成果；不创建工作树、不操作生产、不推送或发布。

- [x] 贯通安装身份生成与持久化、面板绑定／历史、注册、心跳、状态／流量报告及 SSE，同 Token 新安装可在旧机在线时接管，退役身份重启不能抢回。
- [x] 仅升级面板时未绑定主机仍接受无身份旧 Agent；首次升级到支持身份的 Agent 时生成并保存身份、绑定同一主机，不一概判为真实换机；后续普通升级保留身份，显式重装产生新身份。
- [x] 绑定后缺失、不匹配和退役身份不能更新当前状态或流量、不能获得同步；分别验证面板隔离旧版请求与新版 Agent 主动停止同步，不承诺旧版主动停请求。
- [x] 旧实例已有转发按上游保留，无自动撤销期限，不自动清理旧服务；仅在隔离环境验证接管，不操作真实 Token 或主机。
- [x] 首次绑定／接管后重建当前规则与完整 SNI 分流配置证据；保留可信上报时钟、完整／空清单、过期报告拒绝及实际运行确认，不沿用旧成功，不套用管理员调整豁免。
- [x] 安装身份相关新建与升级支持 SQLite、MySQL、PostgreSQL，保留既有主机数据及独立任务交接状态，不覆盖其专属迁移或表结构。
- [x] 接管所需的 Agent／FXP 配套协议变化在本单形成完整可验证路径，明确面板单升级、旧／新 Agent 与配套 FXP 的能力矩阵；通用目标校验和资源优化由 13 处理。
- [x] 通过注册／加密心跳／期望状态、真实测试数据库及隔离 Agent／FXP 验证迁移、在线接管、旧身份隔离与重启；SNI／主机型主备组仍遵守本地入口健康和独立修复成果。


**实施与验证记录：** 已落地的功能、测试入口、真实数据库／浏览器／网络证据及环境限制，统一见[正式规格中的本轮实施与验收记录](../spec.md#本轮实施与验收记录)。勾选按实际验证范围更新；不将默认跳过或生产未部署记为自动通过。
