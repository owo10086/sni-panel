# 24: 转发组同步优化并保留本地入口健康与 DDNS

**What to build:** 转发组维护减少重复读取和写入，配置变化或恢复在线仍正确下发，本地 SNI、入口健康、DDNS 及独立任务成果保持有效。

**Blocked by:** None（实施授权已获得）。

**Status:** completed（本地实施与隔离验收完成，未发布）

**依据：** [本轮规格](../spec.md)，用户故事 3、43、44、45、46、47、49；实施决定 21、22、23、24。

**实施边界：** 用户已通过 `$implement 开始实施` 授权本地代码实施、隔离验证与当前分支中文提交。按本轮固定累计范围兼容，遵守长期约定与排除项，保护实际基线及独立任务成果；不创建工作树、不操作生产、不推送或发布。

- [x] 纳入批量读取成员主机、配置相等时减少重复写入；真实配置变化、在线但未运行和恢复在线后的必要下发继续发生。
- [x] 配置比较同时覆盖本地 SNI、分流器端口、限速、连接限制及上游新增字段，资源参数兼容共享监听和链端口预留，不遗漏字段而漏部署。
- [x] 遵守 ADR-0006／0007／0008：SNI 业务目标失败、缺失或过期不单独阻塞入口／DDNS，完整当前分流配置仍须确认；仅主机型主备组普通规则按入口自身运行与健康选择，其他类型保持各自策略。
- [x] 保留流量政策、已启用的入口健康检测、真实故障续算、恢复观察、当前有效副本、旧副本排除和发布前复核；国内健康检测不混作入口健康检测。
- [x] 以实施时实际代码保护管理员调整免恢复观察、先接后断、延迟接管、TTL 撤销及重启接续等已落地成果；不在本单另行实现、关闭或宣告独立议题验收，不把上游减少写入称为其修复。
- [x] 保留 ADR-0009 Docker 精确放行和严格本机就绪，Agent 接管／重启／重连继续按真实确认边界处理，不误套管理员调整豁免。
- [x] 通过现有转发组管理接口、可信心跳、完整 SNI 状态、受控 DDNS 与隔离转发验证不变／变化配置、恢复在线、目标异常、真实故障及独立任务既有场景；不只检查写入次数。


**实施与验证记录：** 已落地的功能、测试入口、真实数据库／浏览器／网络证据及环境限制，统一见[正式规格中的本轮实施与验收记录](../spec.md#本轮实施与验收记录)。勾选按实际验证范围更新；不将默认跳过或生产未部署记为自动通过。
