# 19: 按服务配置资源告警及管理员通知范围

**What to build:** 管理员在服务管理的独立页签按服务设置 CPU、内存或磁盘告警，并选择全部、指定或排除主机，通知对象准确。

**Blocked by:** None（实施授权已获得）。

**Status:** completed（本地实施与隔离验收完成，未发布）

**依据：** [本轮规格](../spec.md)，用户故事 34、36；实施决定 16。

**实施边界：** 用户已通过 `$implement 开始实施` 授权本地代码实施、隔离验证与当前分支中文提交。按本轮固定累计范围兼容，遵守长期约定与排除项，保护实际基线及独立任务成果；不创建工作树、不操作生产、不推送或发布。

- [x] 从服务配置到保存、指标判断和管理员通知形成闭环，设置入口按上游移入服务管理独立页签，旧配置按现有兼容边界保留。
- [x] 每项服务可选择 CPU、内存或磁盘，全部／指定／排除主机范围准确，编辑后立即按新配置生效且不串用其他服务范围。
- [x] 仅通知有权的管理员，不扩大到普通用户；沿用现有通知开关和发送机制，测试使用受控通知接收方，不向真实他人发送消息。
- [x] 入口健康检测与主机探测服务中的国内健康检测分别定义，不能把告警或国内连通异常改成转发组入口资格／DDNS 门槛。
- [x] 保存、重载、中英文和窄屏交互可用；通过管理接口、受控指标和通知替身验证范围、权限、关闭、恢复和旧设置兼容。
