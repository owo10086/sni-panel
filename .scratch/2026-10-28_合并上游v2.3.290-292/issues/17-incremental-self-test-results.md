# 17: 自测结果按到达顺序呈现并保留真实证据

**What to build:** 多入口自测先显示已完成结果，未完成部分继续等待，用户能够区分目标连通与外部经入口的实际转发证据。

**Blocked by:** None（实施授权已获得）。

**Status:** completed（本地实施与隔离验收完成，未发布）

**依据：** [本轮规格](../spec.md)，用户故事 31、32、47；实施决定 15、24。

**实施边界：** 用户已通过 `$implement 开始实施` 授权本地代码实施、隔离验证与当前分支中文提交。按本轮固定累计范围兼容，遵守长期约定与排除项，保护实际基线及独立任务成果；不创建工作树、不操作生产、不推送或发布。

- [x] 自测调度到界面逐项呈现形成完整路径，结果按到达顺序出现，不等待最慢项目后一次展示；未完成项继续等待并准确收尾。
- [x] 继续区分目标连接、入口本机就绪和外部经业务端口转发；未验证路径不显示为成功，不把计数或目标可达当作数据面成功。
- [x] 保留既有权限、超时、失败和取消语义，多个入口的结果归属准确，不重复或串用旧轮次结果。
- [x] 桌面／窄屏和中英文结果反馈清晰，遵守 ADR-0009 与现有运行证据要求。
- [x] 通过受控快慢／成功／失败入口、自测调用方和必要的独立客户端连接验证顺序、等待、收尾与证据标签，不以静态数据替代真实转发结论。


**实施与验证记录：** 已落地的功能、测试入口、真实数据库／浏览器／网络证据及环境限制，统一见[正式规格中的本轮实施与验收记录](../spec.md#本轮实施与验收记录)。勾选按实际验证范围更新；不将默认跳过或生产未部署记为自动通过。

**专项验证说明：** 实际自测组件＋真实自测接口／临时 SQLite 的浏览器中英、1280／390px 四场景通过，快结果先显示、慢结果等待、成功／失败收尾和证据标签正确；发现并修复英文生成目标标签未翻译。Agent 报告为受控输入，真实外部转发由规格中的独立 Linux 网络验收提供，该 harness 未挂载完整 Rules 页面。
