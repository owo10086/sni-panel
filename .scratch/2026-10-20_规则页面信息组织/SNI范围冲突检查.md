## 本轮适用范围

用户已明确：这次只调整 SNI 规则显示，其他转发规则显示不同。

- 已讨论的移除用户、链路、24H 列，所属资源展开详情，累计“数值＋详细”，紧凑组头，更多四项，以及点击延迟直接重测，都只用于 SNI 对应的显示区域。
- 普通端口转发、普通隧道、普通转发链、普通转发组规则保留各自原来的列、内容、操作与检测入口。
- 同一个转发组、同一种资源类别，既可能有 SNI 规则，也可能有普通规则。判断对象必须是具体规则，不能只看“属于转发组”或“这个页面出现了 SNI”。
- 当前示意图是主机型主备 SNI 的样例，不能代表普通规则，也不能把其他 SNI 承载方式统一写成主备或 nftables。

## 发现的冲突与修正要求

| 检查项 | 发现的问题 | 本轮方案需要采用的边界 |
| --- | --- | --- |
| 表头、列宽和列数 | SNI 与普通规则现在共用一张表格。全局删列会一起改变普通规则，只给 SNI 少画几个格子又会错位 | SNI 使用自己的表头、列宽与行；普通规则继续原表。不能把公共列数统一减三 |
| 混合显示 | 同一分类、同一组里都可能同时有 SNI 与普通规则 | 沿用现有 SNI 识别与分组，按原项目顺序显示各自区块；不按“当前页有 SNI”切换整页模式，也不把普通规则挪到新位置 |
| 所属资源展开详情 | 当前资源格子属于共用规则行 | 新增的文字详情只接入 SNI 行；普通规则的所属资源显示继续原样 |
| 累计与额度详情 | 额度说明同时用于普通规则、SNI、标准卡片和紧凑卡片 | SNI 单独选择“累计数字＋详细”；共用额度组件不整体改成新版样式 |
| 流量单位 | 页面流量格式化还用于普通规则、顶部总览和地球视图 | MB／GB 等名称仅在本轮 SNI 显示及其详情统一；不全局改共用格式，也不改变流量计数与额度计算 |
| 更多菜单 | 现有操作区服务所有规则和多种卡片 | 仅 SNI 操作区采用四项更多菜单；普通规则原有按钮、权限及不支持协议时的操作保留 |
| 行内重测 | 当前延迟展示也被其他规则、卡片共用 | 仅给 SNI 增加直接开始／重新测试的点击入口；普通规则的展示和弹窗入口继续原来行为 |
| 重测后取得新结果 | SNI 主备手动测试写在父规则，列表延迟却可能读当前入口的子规则。只触发测试再刷新列表，仍可能显示旧延迟 | SNI 行要等待这次测试完成，接收对应结果；不为了显示新值而全局重写普通主备组的延迟汇总 |
| “24小时流量”入口 | 原波形按钮打开的是延迟和探测统计，没有流量统计 | SNI 新菜单实际接入最近 24 小时入向、出向流量；不能把原延迟弹窗仅改个名称。原有延迟历史可在 SNI 对应详情内继续保留 |
| 只读用户 | 现有页面对普通用户的管理员自定义规则只允许查看，后端启动测试的检查与该页面限制并不完全相同 | 新的延迟按钮、更多菜单继续服从原页面权限，不能因为后台接受请求就额外开放操作；用户信息也只按原可见范围展示 |
| 手机与其他显示方式 | 手机强制用卡片；SNI 卡片与普通卡片也有共用内容 | 不整体改共用卡片。桌面列变化仅用于 SNI 桌面区域；SNI 小屏只做必要兼容，紧凑卡片原本没有延迟时不顺便增加新区域 |
| 状态与入口选择 | SNI 配置生效、目标连接检测与组入口资格是不同判断 | 复用现有 SNI 状态，不让点击测出的某条目标失败改写组入口资格；ADR-0006、ADR-0008 的边界继续执行 |

## 混合列表怎样避免冲突

例如，同一主备组里有 `a.example`、`b.example` 两条 SNI 规则，还有一条普通 TCP 规则：

- 两条 SNI 使用本轮紧凑表格，用户和链路在点击“所属资源”后查看，24 小时流量从更多进入。
- 普通 TCP 继续显示原来的用户、链路、24H、延迟及操作。
- 两者各有符合自身内容的表头。原分类、搜索、分页、勾选范围和排序单位继续执行，不能为了画新表格重新排一次数据。

建议按原显示项目输出独立区块：连续的普通规则沿用原表格，SNI 显示组使用自己的小表格。SNI 在哪里出现，就在哪里显示，不额外把 SNI 或普通规则聚拢到列表另一端。

把 SNI 小表格塞进旧表的一整行也能避免格子错位，但外层仍被旧表最低宽度限制，上方旧表头也不对应 SNI 新列。这种做法不能同时宣称已经实现 SNI 独立缩窄，因此不作为当前推荐方案。

## 延迟测试需要补齐的实际衔接

本轮可以沿用已有测试能力，但“换成可点击文字”本身不足以完成需求。

1. 点击具体 SNI 行的“未测”或已有延迟后，立即提交该条规则的现有测试请求。
2. 按规则和本次返回的测试编号跟踪进度，只把对应的有效完成结果放到这条 SNI 行；不能拿更早记录当作本次完成。
3. 超时、失败、下发失败与完成成功分别显示，结束后恢复点击；同一条规则正在测试时防止重复提交。不同规则的测试状态分别记录。
4. 结果显示需要兼顾后续列表刷新，避免刚收到本次结果又被较旧的子规则记录盖回去。规则目标、当前入口或配置发生变化时，也不能让旧结果冒充新配置的结果。
5. 转发链和隧道承载的 SNI，仍按原来的分段、批次、入口与出口处理结果，不能都简化成一次从固定主机发起的测试。
6. “更多 → 链路自测”继续先打开原自测弹窗，不因为增加行内点击而让打开弹窗自动发起测试。

对截图中的主机型主备 SNI，现有测试主要反映所选入口到业务目标端口的连接延迟。它没有携带域名验证完整分流过程，不能据此宣称已经验证证书、客户端到入口的整条路径或所有备用入口。此处是在明确已有能力，不新增另一套测试服务。

## 识别、权限与数据边界

- 复用 `getSniRuleGroupKey` 与 `groupSniRulesForDisplay` 的现有识别路径：有效 SNI 域名、资源及入口端口组成 SNI 显示组；普通项目继续进入普通路径。
- 不用资源类别 `group`、`forwardGroupId`、是否主备或某页是否出现 SNI 代替这一判断。端口资源、隧道和转发链也可能承载 SNI。
- 管理员与普通用户原表列数不同，拖动列还会改变列数；SNI 与普通区域各自计算自己的跨列数，不能统一套用示意图的列数。
- SNI 整个显示组仍是原来的排序单位，普通规则仍各自是排序单位。重排界面结构时，拖动容器也必须匹配，不能把原表格行的包装直接套在普通区块上。
- 24H 只是从 SNI 主表移入更多，不意味着删除公共流量数据查询；普通规则展示、状态准备和新菜单仍可能需要这些数据。
- 只移动显示位置，不更改用户归属、资源引用、目标地址、流量计数、额度政策、现有测试方法或 DDNS 判断。

## 后续实施必须覆盖的样例

这些是后续检查要求，本轮尚未运行：

- 纯普通规则列表：原列、24H、用户可见范围、操作和延迟展示均保持原来行为。
- 纯 SNI 列表：本轮新排版、资源详情、累计详细信息与更多四项能正确对应各行。
- 同一页或同一主备组混合 SNI 与普通规则：各用自身显示，表头不串列，普通规则不被套入 SNI 样式。
- 管理员／普通用户，允许操作／仅查看，支持／不支持当前协议：沿用原权限和原错误提示。
- 开启／关闭拖动、翻页、搜索、折叠及批量勾选：保留原项目身份、范围与顺序。
- SNI 主备、多入口、端口资源、隧道和转发链：显示真实资源名称与实际入口出口，不硬套样例的主备标签或 nftables。
- 未测、已有延迟、多次重测、失败、超时、旧记录晚到、列表刷新：显示本次有效结果，不能测完又退回旧值。
- 手机卡片及其他既有显示方式：没有因修改共用内容而改变非 SNI 规则。
- 单条目标失败仍不单独触发相应 SNI 主备组的入口切换或阻塞 DDNS。
