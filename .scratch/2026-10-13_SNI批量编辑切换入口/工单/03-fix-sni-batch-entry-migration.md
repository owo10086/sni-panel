## 完成后怎么检查

- [x] 四类入口各准备 7 条不同域名的规则，批量从资源 A 切换到资源 B，最多同时提交 6 条，业务端口固定 443；每类重复 10 次，每次批量阶段在 5 秒内完成。全部合法编号成功返回，保存内容与输入一致，后续独立读写正常。
- [x] 分别向空目标资源、已有合法共享规则的目标资源迁入。两种情况下都能完成，目标原有域名及其端口不被覆盖。
- [x] 主机型转发组与直接隧道可以双向转换；旧成员配置撤除，新入口和出口配置正确，隧道端口对应关系正确，继续使用指定业务端口。
- [x] 涉及多个主机的 A 到 B、B 到 A 同时迁移都能结束，不互相等住；每条规则最后所属的资源、成员、域名和目标正确。
- [x] 一次迁移纳入旧、新路线实际涉及的主机，包括需要撤除旧配置的成员。多入口、入口组引用、不同转发链和不同资源共用主机时，旧新入口及出口的配置都正确。
- [x] 只迁出一部分规则时，旧入口仅移除已迁出的域名；没选中的域名、限制和成员配置保持正确，新入口收到完整期望状态。
- [x] 共享监听还有其他域名时继续保留；最后一个域名迁出或删除后才清理。迁走或删除第一条规则不会改变其他域名共用监听的身份。
- [x] 已有合法共享的直接隧道出口端口在迁移和重复整理后保持稳定，不额外产生错误分配，也不与自己的临时占位冲突。
- [x] 预先放入已知未结算用量，迁移后核对余额、实际用量和结算记录；重复整理不会漏结算或重复扣费，余额不足时仍按原规定停用。
- [x] 保存成功但入口尚未确认时，不显示成最新配置已运行；旧运行报告不能让新配置冒充运行中，最新有效报告到达后才按原有规则更新状态。
- [x] 每条操作继续单独返回结果，成功项保留；原有权限、资源使用限制和真实占用检查继续有效，不把 443 自动改成随机端口。
- [x] 使用临时数据库和真实规则操作完成检查，通过现有 Agent 心跳处理核对旧新入口期望状态并提交模拟运行报告；新增检查纳入服务端正式检查，记录本单的真实结果。

## 共同边界

本单依赖 02 提供的统一协调办法，不另外建立一套迁移专用队伍。继续遵守先主机、后资源保存位置、最终重新读取再保存的次序，以及失败释放、提交后结算、DNS 等待前释放位置的要求。规则等待期间路线变化的完整处理和重复检查由 04 完成，不能将这些尚未验收的情形标成通过。

不改网页批量提交数量、接口或数据库结构，不增加依赖，不扩大 SNI 支持范围，不重写删除或资源编辑功能。只在隔离环境检查，模拟报告不能宣称生产实际域名连接已验收。禁止创建工作树；本轮按 `implement` 技能本地提交；推送、发布、生产升级和补改生产规则另行安排。原生客户端按长期约定排除。
