## 来源与本单范围

总范围见[修复规格](../spec.md)，原始任务见[总工单 01](01-fix-sni-batch-entry-edit.md)。当前拆分和推进顺序见[工单索引](../工单索引.md)。

本单覆盖主机型转发组、端口转发、转发链、当前已支持 SNI 的直接隧道。先把同一入口上的日常维护做完整，包括多个入口成员、入口组引用、不同资源共用实际主机，以及直接隧道已有共享出口端口的情况。四类入口共用一套协调办法。

本单内先做必要的小范围整理，再完成修复和真实操作检查，不另开只搭架子或只写测试的工单。切换到另一资源和资源类型转换由 03 完成；等待中路线变化、保存失败和外部更新缓慢的完整检查由 04 完成。这里的分工不允许破坏规格已经规定的保存、费用、释放和运行确认规则。

对应规格验收：A01、A02 的同入口部分、A04、A05、A08、A09、A10、A11、A12、A21。A02 的迁移部分由 03 完成，最后由 04 汇总确认整项通过。

## 完成后怎么检查

- [x] 先用真实规则操作记录旧代码下两条不同域名同时编辑的端口误判，再确认修复后两条都成功，保留前后对照。
- [x] 四类入口各准备 7 条规则，固定使用 443，最多同时提交 6 条；每类重复 10 次，每次批量阶段在 5 秒内完成。全部合法编号都有成功结果，保存的目标、端口、限速和连接数与输入一致，后续独立读写可以继续。适用的多入口场景不能缩成单台主机。
- [x] 同一资源内同时创建和编辑，包括使用现有导入方式创建时，后面的操作能识别前面刚保存的合法共享域名，根规则和成员配置没有遗漏。
- [x] 主机型转发组的启用成员、转发链的入口和中间成员及出口、直接隧道的主入口和入口组成员及出口均正确参与处理；不同转发链或不同资源实际使用同一主机时，也不会互相误报占用。
- [x] 直接隧道已有合法共享出口端口时，重复编辑和一起编辑均保持端口稳定；内部重新申请端口时不会与自己的临时占位冲突。
- [x] 同一主机同端口、不同端口的重复域名继续被拒绝，包含创建和编辑同时发生的情况；同一根规则的合法成员副本不会被当成另一条冲突规则。
- [x] 普通规则混用端口、资源不允许共用以及模拟已识别的真实占用仍被拒绝；不覆盖原有规则，不把指定的 443 自动改成其他端口。
- [x] 混入无权限、资源不可用和不存在编号的操作时，每条都有准确结果；合法项正常保存，失败项不保存，也不撤回其他成功项。
- [x] 编辑和启停同时发生，以及编辑时打开或关闭 SNI，最后的启用状态、域名和配置符合实际操作结果；编辑前后任一状态含 SNI 时都得到保护。
- [x] 使用完全不同主机的日常操作可以各自完成，不被放进同一条总队伍。有人故意等待时的独立性检查留给 04 的 A19。
- [x] 使用临时数据库、合成账号主机和真实规则操作完成检查，通过现有心跳处理核对入口期望状态。检查保存内容和实际结果，不用某个内部排队名称或调用次数代替验收。
- [x] 将新增检查纳入服务端正式检查，并记录本单的通过、失败和未执行项；不把本单完成写成整个修复或生产访问已验收。

## 共同边界

沿用规格规定的单规则保护和按实际主机协调顺序，先取得主机位置、再取得相关资源已有的保存位置，最终重新读取后才检查、预留和保存；完成或失败都释放位置，进入 DNS 外部等待前释放保存所需的位置。不同主机不使用全局队列，费用继续在数据库提交并释放后处理。
