## 完成后怎么检查

- [x] 分别在等待主机位置、已取得主机位置但仍等待相关资源保存位置时改变成员或路线。取得相关资源保存位置后、预留和写入前，必须再读取最新规则、资源、成员和允许共享的域名，再完成检查。
- [x] 目标入口从 A 换成 B 时，先退出本轮保存，释放本轮已取得的资源保存位置和主机位置，再按 B 重新排队；不能沿用 A 的队伍直接写入 B，也不能占着旧位置等新主机。
- [x] 最后一次确认路线到保存完成之间，持续使用与相关成员或路线调整共用的已有保存保护。主机型转发组、端口转发、转发链、直接隧道及入口组引用均覆盖，不能只补一种资源。
- [x] 主机集合没变、路线或共享名单内容变了时，也按最新内容重新检查。等待期间规则被删除、标记待删除，或权限及资源条件变化时，按原规定拒绝，不恢复旧规则、不扩大权限。
- [x] 等待主机位置与等待资源保存位置共用最多重试 3 次的上限；超过上限返回“入口配置已变化，请刷新后重试”。失败没有提前预留或部分保存，后续合法操作仍能完成。
- [x] 故意让保存阶段失败，再发起合法编辑和端口分配：原配置保留，未提交配置不通知入口，临时占位和处理位置均释放，后续操作成功，数据库能够继续读写。
- [x] 暂缓计量时，另一个独立数据库写入仍能完成，证明数据库已经提交并释放；费用处理继续发生在提交之后，不重新引入此前删除修复过的等待关系。
- [x] 暂缓 DNS 更新时，同组另一条规则已经可以保存，数据库仍可写；第一条请求不必先完整返回。DNS 随后返回时，晚到的旧判断不能覆盖后来的编辑；DNS 失败也不擅自撤回已提交规则。
- [x] 两批操作使用完全不同的主机，其中一批故意停在等待阶段时，另一批仍能保存；不能用“第一批最终结束后第二批才成功”代替这一检查。
- [x] 编辑与删除同时发生时，两边都能结束；等待期间已删除或待删除的规则不会被编辑恢复，没选中的规则保留，后续数据库写入正常。保留已有单规则保护，不重写删除流程。
- [x] 新的等待、重试和失败处理使用一致的进入、退出顺序，在数据库之外取得处理位置，已有保存流程不重复等待自己已经取得的位置；成功和失败都不会留下后续任务无法继续的占位。
- [x] 用临时数据库、真实规则操作和现有心跳处理完成检查；必要的失败和延迟只在既有数据库、计量或本地 DNS 检查边界制造，不增加生产接口，不连接生产 Agent 或真实 DNS 服务商。
- [x] 重跑前两张工单的相关检查，逐项汇总 A01—A24 的真实结果。A02 的四类入口、7 条规则、最多同时提交 6 条、固定 443、各重复 10 次和每次批量阶段 5 秒要求完整保留；不能只汇总单次成功。
- [x] 完成规格要求的类型检查、服务端完整测试和面板构建，保留既有删除、费用、SNI 运行确认及 DNS 等待期间并发保存检查；记录通过、失败和未执行项，只有 A01—A24 全部满足才标记整个修复完成。

## 共同边界

保存成功仍只表示面板已经保存，继续按入口和出口的最新有效确认判断运行状态。临时诊断成功和模拟运行报告不能替代正式回归检查，也不能证明生产实际域名连接已验收。

沿用规格全部业务边界：不改网页提交数量、接口、数据库结构、共享资格、费用政策和 SNI 支持范围，不增加依赖，不重写删除、资源成员编辑、隧道路线编辑或 DNS 服务商配置功能。禁止创建工作树；本轮按 `implement` 技能本地提交；推送、发布、生产升级和补改生产规则另行安排。原生客户端按长期约定排除。
