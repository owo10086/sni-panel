## 问题与交付内容

批量编辑不同域名的 SNI 分流规则、更换入口时，合法共用 443 的请求会互相误报端口占用。已确认两个原因：临时端口预留互相排斥，以及保存前使用了过时的允许共用名单。

统一修复主机型转发组、端口转发、转发链、直接隧道的 SNI 规则写入协调，覆盖创建及导入、编辑与转换、启停。合法批量操作能完成，真正冲突和权限限制继续拒绝，旧新入口配置、费用、后续任务均正确。

完整要求见[规格](../spec.md)，实际排查事实见[排查记录](../排查记录.md)。本单独立于此前批量删除修复；该修复的计量顺序和回归检查必须保留。

## 已确定的处理办法

- 按旧、新路线实际涉及的主机统一协调，不只按组或隧道编号。同主机跨端口也协调；主机编号去重并按固定顺序取得位置，无关主机不进同一队列。
- 保留单规则排队，在数据库事务外先取得主机位置，再取得相关资源已有的保存位置；上述等待全部结束后、预留和写入前，最终重读规则、资源、成员和共享名单，再检查、预留和保存。
- 等待主机位置或资源保存位置期间，主机集合变化时先退出本轮保存，释放已取得的资源保存位置和主机位置，再按最新路线重新排队；两段等待共用最多重试 3 次的上限，仍变化则明确报错，不提前预留或部分保存。主机集合不变也须按最新路线内容检查。
- 最后一次路线确认到保存完成期间，持续使用与成员、路线调整共用的已有保存保护；不能在按 A 服务器排队后，因成员变化直接保存到未取得主机位置的 B 服务器。直接隧道和入口组引用的路线同样覆盖。
- 完成根规则、成员配置及隧道端口映射整理后释放临时预留、相关资源保存位置和主机位置，再进行原有故障判断、DDNS 和后续刷新。
- 所有入口保持先主机、后资源保存位置的一致进入次序；重新排队前释放旧位置，已有保存流程不重复申请自己已取得的位置，避免互相等待。数据库提交后结算和通知的顺序不变；DNS 外部等待前释放新增占位。
- 保留既有共享、域名唯一、权限、占用、费用和运行确认规则；不改 API、数据库结构或网页提交数量，不更改用户指定的 443。
- 保存失败保留原配置、释放占位，不发送未提交配置；成功项不整批回滚。删除流程不重写，但验证编辑与删除同时发生。

### 第一步：补齐能复现问题的检查

- [ ] 使用临时 SQLite、合成账号主机和真实规则接口，建立四类入口的统一行为检查。
- [ ] 确认 2 条最小同时编辑在旧代码失败，并记录相同误判的证据。
- [ ] 补齐 7 条、最多同时提交 6 条、固定 443 的批量场景；每类重复 10 次，批量阶段检查期限为 5 秒。
- [ ] 通过真实心跳处理查看期望状态并提交模拟运行报告；不连接生产 Agent 或真实 DNS 服务商。

### 第二步：统一修复服务端协调顺序

- [ ] 建立小型内部主机协调模块，复用现有排队工具，不增加依赖。
- [ ] 接入四类入口的创建及导入、编辑、启停；编辑前后任一状态包含 SNI 都覆盖。
- [ ] 纳入旧新路线的入口、成员、出口及入口组相关主机；在主机位置和相关资源保存位置均已取得后、预留和写入前，最终重读最新内容，并保持到保存完成的路线保护。
- [ ] 覆盖等待资源保存位置时入口又变化的情况；退出并释放本轮位置后按新路线重新排队，与等待主机位置的变化共用最多重试 3 次的上限。
- [ ] 完成失败释放和隧道内部重新预留的处理，已有保存流程不重复申请自己已取得的位置。
- [ ] 保留原有组内保存、提交后结算、共享端口及费用保护；新增占位在 DDNS 等待前释放。

### 第三步：完成全部验收并记录结果

- [ ] 检查目标已有共享规则、同组批量编辑、创建与编辑同时发生、资源转换及双向迁移。
- [ ] 检查入口组、多入口、不同资源共用主机、跨端口重复域名和真正占用。
- [ ] 检查无权限、不存在编号、保存失败、重试上限及后续合法操作。
- [ ] 按 A20 分别制造等待主机位置、等待资源保存位置时的入口变化；确认从 A 换到 B 后重新排队，最终配置不会写到尚未取得主机位置的入口，主机集合不变时也使用最新路线内容。

- [ ] 检查实际用量不遗漏、不重复扣费及欠费停用。
- [ ] 检查计量暂缓时数据库可写、DNS 暂缓时同组其他规则可保存、无关主机可继续。
