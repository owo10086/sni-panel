# 05: 将真实本机就绪结果接入主备验收并保留 DDNS 与观察等待约定

**What to build:** 主机型主备转发组消费新的本机就绪结果后，入口自身配置故障按既有故障等待参与主备处理，修复后按既有恢复观察及优先级恢复。单条业务目标失败、缺失或过期仍只反映该业务状态，健康入口继续可以维持组域名解析。

本单完成真实 Agent 状态进入面板、入口资格、观察计时及本地 DDNS 提供方的纵向验收；仅在新状态接入存在缺口时作必要适配，保留 ADR-0008 和 ADR-0006，不重写既有主备策略。它依赖本机就绪结论的交付，不依赖目标结果网页或动态目标生命周期工单。

**Blocked by:** 02：识别本机转发条件缺失并消除 Agent 就绪误报

**Status:** ready-for-agent

- [x] 使用前置工单的真实本机状态回报形成入口配置故障，经过设置中的故障等待后，面板按原有主备规则选择合格成员，并核对本地 DDNS 提供方收到的实际更新。
- [x] 入口配置修复后遵守既有恢复观察、优先级和自动回切设置；不能借业务目标、入口健康检测或其他规则的健康时间提前回切。
- [x] 同一成员、同一规则、同一当前副本的持续故障在面板重启后接续原计时；更换规则或副本形成新故障时不借用旧时间。
- [x] 业务目标失败、没有记录及记录过期时，只要入口自身合格，主机型主备转发组仍可选择入口及发布解析，不因目标失败触发整组切换。
- [x] 关闭入口健康检测只跳过该项；入口在线、流量政策、应运行副本已准备及既有观察条件继续有效。
- [x] 普通规则移组再移回后，当前有效副本参与资格判断，待删除旧副本不遮挡；本单不放松 SNI 当前完整分流配置及撤除确认。
- [x] 发布 DDNS 前继续复核当前入口资格及恢复观察；SNI 业务目标失败不能取代或阻塞完整分流配置确认。
- [x] 隧道型主备、入口组及其他资源类型继续各自既有判断，不把主机型主备约定扩展到不适用范围。
- [x] 复用现有主备组、时间控制和本地 DDNS 替身验收方式；不把命令生成测试通过或目标延迟正常视为主备链路验收完成。
- [x] 明确面板与 Agent 需要的版本能力，区分已验证的修复范围与另行失败的 12 个目标端点；本单不执行生产防火墙修改、升级、重启或部署。

## Comments

2026-10-25 已实施并验证（验收为主，未改主备策略）。

- 新场景：真实本机就绪失败 → 面板子规则未运行 → 故障等待 → 切到备用并由本地 DDNS 提供方替身收到更新 → 修复 → 恢复观察 → 回切；业务目标失败不切换；主备成员安装失败的原因保存在运行诊断。
- 面板重启后的故障计时接续、移组再移回、隧道型主备、多入口组等沿用 `server/forwardGroupFailover.test.ts` 等既有回归，全部通过。
