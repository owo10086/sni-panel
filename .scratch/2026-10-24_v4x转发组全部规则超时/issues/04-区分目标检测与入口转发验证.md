# 04: 让自测接口与网页区分目标连接成功和入口转发已验证

**What to build:** 用户查看自测结果、延迟及历史时，能够看清实际执行的是业务目标连接检测，还是已经验证外部经入口的转发路径。只有目标连接成功时继续展示目标延迟，但不得将未执行的外部路径验证显示为成功，也不能把“未验证”误报为“已确认失败”。

本单独立贯通检测结果处理、持久结果读取及面板网页，不依赖 Docker 兼容放行或就绪规则的实现。使用现有自测契约和可用的结果表达方式；若确实需要改变字段语义或存储契约，先更新正式规格再同步所有读取方。

**Blocked by:** None (can start immediately).

**Status:** ready-for-agent

- [x] 目标直连成功、外部经入口连接失败或未执行的对照中，接口和网页保留正确的目标连接结果及延迟，不声称外部转发已验证成功。
- [x] “目标连接成功”“目标连接失败”“外部路径未验证”在结果及文案上可区分；未验证不以失败或成功冒充。
- [x] 自测上报、结果存储、查询、规则详情及历史等相关消费方对同一结果给出一致含义，不保留仍无条件将目标成功视为外部转发成功的读取路径。
- [x] 既有记录和旧 Agent 结果按实际证据解释，不为缺失的外部路径证据补写已验证成功；不使旧版本请求失去基本兼容。
- [x] 入口健康检测、业务目标检测和本机转发就绪的含义分别保留；不新增业务目标门槛，不改变任何资源既有入口选择策略。
- [x] 复用现有自测接口、隔离数据库和网页测试方式，覆盖目标成功但路径未验证、目标失败、旧记录及旧 Agent 对照，不仅检查文案字符串。
- [x] 保留主备成员切换后的实际自测执行来源及运行规则身份，不把测试排队后的配置变化静默当成原测试已经验证。
- [x] 不新建常驻公网探测服务、生产调试接口或全面重写自测体系；需要另行建设的外部路径探测保持范围外。
