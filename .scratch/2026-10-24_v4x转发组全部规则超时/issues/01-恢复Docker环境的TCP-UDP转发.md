# 01: 恢复 Docker FORWARD DROP 环境下的原生 nftables TCP／UDP 转发

**What to build:** 管理员在运行 Docker、活动 nft 后端的 FORWARD 默认策略为 DROP 的入口上创建原生 nftables 转发规则后，外部客户端能够通过入口完成 TCP 与 UDP 应用往返。Docker 默认 DROP、管理员显式拒绝、现有访问限制及非受管流量继续遵守原有策略。

本单交付最小但完整的创建、重复应用、停用／删除路径，以及基本的真实 Agent 应用和状态回报。后续工单扩展运行中缺失检测和动态配置生命周期；本单不能以“稍后补清理”为由遗留受管放行。

**Blocked by:** None (can start immediately).

**Status:** ready-for-agent

- [x] 隔离环境通过面板现有心跳取得真实期望状态，由真实 Agent 动作处理安装规则；独立客户端经入口完成 TCP 双向应用数据及 UDP 请求／响应验证，测试不手写替代生产命令。
- [x] 活动 nft 后端存在 Docker 风格 FORWARD 默认 DROP 时业务往返成功；同时 legacy 后端显示 ACCEPT 的对照不会误导活动后端识别。
- [x] 兼容放行限定到受管规则、原始入口端口、协议、转换目标及相应返回连接，不把共享目标上的任意其他转发流量一并放行。
- [x] Docker 默认 DROP、Docker 既有网络、管理员规则、规则访问限制保持；非匹配端口／目标仍被过滤，显式拒绝不被兼容规则绕过。
- [x] 无 Docker 的既有场景继续通过；不依靠改变全局 FORWARD 策略、清空规则集或调整自身基础链优先级来掩盖另一条基础链的 DROP。
- [x] 同一规则反复应用保持可用，受管放行不无限重复；停用或删除后清理本单建立的受管状态，其他规则及非受管状态保留。
- [x] 不能安装必要兼容配置时，Agent 动作和面板状态给出失败信息，不吞错后报告应用成功；基本成功路径有对应真实状态回报。
- [x] 保留按原始入口端口及协议区分的流量归属，不增加重复计量路径。
- [x] 相关回归在临时容器／网络命名空间完成，不修改开发机或生产防火墙，不连接生产目标。
