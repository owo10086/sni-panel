# 02: 识别本机转发条件缺失并消除 Agent 就绪误报

**What to build:** 规则曾经应用成功、DNAT 仍在或 Agent 重启接管旧配置时，面板看到的运行状态仍与当前本机转发必要条件一致。支持范围内的兼容放行、IP 转发或源地址转换条件缺失应被识别，正常收敛后状态恢复；业务目标自身失败与本机配置缺失分别表达。

本单基于前置工单确立的受管兼容规则归属及安装结果，贯通动作完成、旧动作接管、本地状态核实与面板状态消费，避免首次应用正确而后续持续误报。

**Blocked by:** 01：恢复 Docker FORWARD DROP 环境下的原生 nftables TCP／UDP 转发

**Status:** ready-for-agent

- [x] 使用同一隔离网络场景保留 DNAT、移除必要兼容放行，确认实际业务不能通过时，正常核实周期内面板不再持续显示该本机配置已就绪。
- [x] IP 转发关闭、必要的受管源地址转换或转发配置缺失均有独立故障对照；核实实际活动后端，而非只看 legacy 策略或 DNAT 存在。
- [x] 动作完成、已应用动作接管和本地运行状态使用一致的必要条件；旧修订号、历史成功和 Agent 重启不能替代当前核实。
- [x] 补齐或按既有重试流程重建配置后，真实 TCP／UDP 往返与面板状态恢复；故障对照确实能使测试失败。
- [x] 权限不足、工具不可用及本次支持的 Docker 过滤结构无法兼容时，状态包含可理解原因；不自动绕过用户显式拒绝或宣称可以判定任意防火墙表达式。
- [x] 业务目标服务停止或检测失败，但本机必要配置完整时，不单凭业务目标不可达判定本机未就绪；结果不承诺任意外部网络均可达。
- [x] 新旧 Agent 状态兼容：旧版本缺少新增核实证据时不伪造已完成核实，同时不扩大到其他转发方式的运行判定。
- [x] 复用真实 Agent 和现有状态回报边界，测试不通过提取源码函数或伪造就绪值替代受测链路。

## Comments

2026-10-25 已实施并验证。

- 未就绪的具体原因出现在动作失败或“内核状态不一致”的状态消息里；心跳里的本地状态仍只有 ready 布尔值，没有新增公共字段。
- 旧 Agent 不上报新的核实证据，面板无法区分；版本能力见 ADR-0009：仅升级面板不会让旧 Agent 发现缺失，仅升级 Agent 在旧面板的 Docker 主机上会如实报未就绪。
- 反向验证：把就绪判断临时改回只看 DNAT，5 个故障场景全部失败。
