# SNI 分流转发开关

Status: ready-for-agent

## Problem Statement

规则表单里没有「这是不是一条 SNI 分流规则」的显式入口。是否分流由 **SNI 域名框填没填** 隐式推导，代价有三处：

**域名框对所有人常显。** 只要是管理员且承载资源属于转发链、隧道或主机型端口转发，表单就一直挂着一个「SNI 域名」输入框。绝大多数规则是普通转发，这个框在它们的生命周期里从头到尾都是空的。

**入口端口要手输 443。** SNI 分流规则几乎总是建在 443 上（客户端连的是 TLS 标准端口），但表单不知道这件事，每建一条都要再敲一次 443。

**443 的端口校验只会误报。** 用户先填端口、后填域名，表单在域名还是空的那一刻按**普通规则**去查 443，服务端如实回答「443 已被 SNI 分流规则占用」，红色「不可用」就挂在端口框上。而 SNI 分流的全部意义就是同组多条规则共用这一个端口（ADR-0002），这个占用不是错误。更糟的是 `portStatus !== "available"` 会**阻止保存**，用户要么等误报自己消失，要么被卡住。

## Solution

把隐式推导换成一个显式开关：**SNI 分流转发**。

开关打开，表单立刻进入分流形态——入口端口锁成 443、SNI 域名框出现并变成必填、协议锁 TCP、限速与最大连接数出现、出站故障转移关闭、443 不再做任何端口探测。开关关闭，表单就是一张普通转发规则表，行为与今天完全一致。

开关**不入库**。SNI 规则依旧靠「域名非空」识别，`getSniRuleGroupKey`、分流表推导、期望状态下发、导入导出、占用判定一律不变。开关只是表单的显示状态，打开已有规则时由域名是否非空反推。

## User Stories

1. 作为管理员，我想用一个开关声明「这是 SNI 分流规则」，从而不必靠"域名框填没填"来表达意图。
2. 作为管理员，我想在开关打开时入口端口自动是 443 且锁定，从而不必每建一条都重敲一次 443。
3. 作为管理员，我想在开关打开时不再看到 443 的端口占用探测，从而不被一个在分流语义下根本不成立的「不可用」挡住保存。
4. 作为管理员，我想在开关关闭时看不到 SNI 域名框，从而让普通转发规则的表单只剩普通转发用得上的字段。
5. 作为管理员，我想在承载资源不支持分流时看到开关置灰并写明原因，从而在选资源那一刻就知道行不行，而不是填完域名和限速才被服务端拒绝。
6. 作为管理员，我想在少数场景下把分流组建在非 443 上，从而应对主机端口范围不含 443、面板自身占用 443、以及已有的非 443 分流组。
7. 作为管理员，我想在填完域名的当场知道这个域名是否已被别的规则占用，从而连着录入多条时不必点完保存再回头改。

## Decisions

### 开关是纯 UI 状态，不加数据库字段

SNI 规则的真值来源始终是 `sni` 字段非空。加一个 `sniEnabled` 列会制造两个真值来源，且必然出现「声称是 SNI 但没有域名」的规则——分流器无法处理这种规则，因为分流表的键就是域名。代价是开关本身不被记住：打开一条已有规则时，开关由域名是否非空反推。

为了让「开关开着却存成普通规则」不可能发生，**开关打开时 SNI 域名是必填项**，空着保存直接拦下。

### 443 是拨动开关那一刻的动作，不是持续约束

手动把开关从关拨到开 → 源端口设为 443 并锁定。打开一条已存在的、入口端口是 8443 的 SNI 规则 → **原样显示 8443 并锁定，不改写**。

若「开关开着就一律显示 443」，用户只是点开看一眼再保存，这条规则就被从 8443 分流组里拽走了：旧组少一个域名，443 上凭空多出一个新组，且全程无声。

锁定框旁保留一个弱化的折叠入口「修改入口端口」，点开才能改。它服务三种真实存在的情况：主机或资源的端口范围不含 443；面板自身占用了 443（见 `docs/guide/cloudflare-cdn.md`，此时 443 的分流规则起不来）；已有的非 443 分流组要补域名。

### 开关打开时不做端口探测，改做域名校验

端口探测在分流语义下只会误报——同组规则共用入口端口是设计本身。因此开关打开时：不调用 `rules.checkPort`，端口框不出现「不可用」红标，`portStatus` 不再阻断保存。

真正需要前置反馈的是**域名**维度：同一台入口主机上完整域名唯一，跨端口、跨承载资源都算重复。填完域名停顿后查一次，冲突则在域名框下方红字写明是哪条规则占了。域名为空时不发任何请求。

开关关闭时端口探测行为与今天**完全一致**，一个字节都不改。

### 不支持的承载资源置灰并写明原因

前端只复刻它已经拿得到的事实：转发组模式、多出口/负载均衡隧道、非主机型或含多台主机的端口转发资源。出口 Agent 版本不足、额外出口节点这类前端拿不到的，仍由保存时服务端报错。普通用户完全看不到开关（SNI 分流仅管理员）。

多出口为什么不行：分流器跑在出口主机上，面板要推导出唯一出口主机才能预留分流器端口并下发分流表；且限速与连接数上限只能由出口分流器执行（ADR-0001），两台出口会把 `限速 100Mbps` 变成「每台各 100」。

## Out of Scope

- 支持多出口的 SNI 分流（需要先定义限速语义与「部分出口已生效」的状态）。
- 把开关状态持久化。
- 批量导入弹窗的入口端口锁定（只改默认值为 443，仍可改——导入常用于往已有分流组补域名，端口必须能对齐那个组）。
