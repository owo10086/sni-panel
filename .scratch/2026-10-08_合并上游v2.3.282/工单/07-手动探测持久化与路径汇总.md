# 07: 手动探测持久化与完整路径汇总

Status: resolved

**What to build（交付结果）:** 用户发起手动探测后，即使面板重启仍能看到本次任务的完整路径、部分结果、超时及最终汇总；诊断操作与正常转发配置互不误触。

**Blocked by:** None（无前置工单，可立即开始）

## 验收条件

- [x] 探测请求、原始参数、任务结果、批次、汇总状态及首次投递时间持久化；全部任务入库后再统一投递。
- [x] 真实面板进程重启后恢复未完成批次，页面可见已完成部分、缺失部分及后续汇总。
- [x] 多入口、多出口和备用中转按完整可用路径检查，备用节点不被当作额外串行节点。
- [x] 重复报告不重复汇总，旧批次不覆盖新批次；重复投递或重试不延长首次执行超时。
- [x] 自动探测不覆盖未结束的手动任务，部分结果、超时和失效原因保持可见。
- [x] 仅自测保留当前运行状态与配置版本，正常转发不中断；配置变更仍按正常应用路径执行。
- [x] 运行恢复期间待执行任务通过上游快速心跳与就绪机制重试，不通过延长超时掩盖失败。
- [x] 探测消息容量和批次数据结构兼容三种既有数据库，验证重启恢复、完整路径、去重、超时及配置版本行为。
- [x] 手动探测入口与结果在中文、English 和窄屏显示可读，保留本轮实际调度与持久状态证据。

## 实施起点

上游持久批次与完整路径调度已应用，已有本轮分发回归记录可复用。工单验收以真实重启、报告和可见汇总为准，需继续核对自动探测、自测和运行恢复的交互。
