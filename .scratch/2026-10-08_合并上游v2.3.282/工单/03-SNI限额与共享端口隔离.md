# 03: SNI 单规则限制与共享端口隔离

Status: resolved

**What to build（交付结果）:** 同一入口端口上的多个 SNI 域名分别执行单规则限制，出口作为唯一计量与限制位置；某个域名达量或到期只影响该规则，其他域名、共享监听和健康长连接持续可用。

**Blocked by:** 02：单规则限制、用量展示与统计重置

## 验收条件

- [x] 独立 FXP 入口分流器按域名选择转发链下一跳，出口分流器选择落地机；分流表继续由规则推导，不新增替代链路资源或运行架构。
- [x] SNI 流量、限速和最大连接数统一在出口执行；入口报告不重复入账，出口报告汇总到正确逻辑规则，重复报告不重复计数。
- [x] 普通规则的入口限速逻辑不会覆盖 SNI 出口限制或随入口数量放大上限；SNI 能力检查按实际出口与本地已支持能力判断。
- [x] 单规则达量、到期和主机流量排除在生成分流表前共同生效，根规则策略传递到必要入口、出口及派生成员，另一项限制仍存在时不会错误恢复。
- [x] 定位并修复当前恢复验证失败的原因，分别验证管理员重置、提高额度、延长有效期及清除到期限制后的立即可观察状态。
- [x] 保存的启用开关、端口、链路成员和目标在运行限额暂停时保持业务配置；解除限制后的恢复不要求重建规则。
- [x] 用本轮心跳配置和实际 FXP，在隔离 Linux 同一端口设置两个域名，分别触发达量与到期；受限域名停止，健康域名的新 TLS 请求、长连接和共享监听持续正常。
- [x] 管理员重置或修改限制后通过真实 TLS 验证受影响域名恢复；验证出口计量、限速及最大连接数仍有效，保留配置与实际网络证据。
- [x] 规则运行状态按域名是否存在于相关入口和出口有效配置判断，不能仅因共享端口有监听而显示全部规则运行中。
