# 04: SNI 热更新、来源清理与 Agent 升级恢复

Status: resolved

**What to build（交付结果）:** SNI 在规则变化、主机流量排除及 Agent 升级时延续已上线行为，共享监听稳定、影响限于相关域名；自动来源限制保持取消，旧防火墙来源规则可持续清理，退役运行时不会被误认为有效业务。

**Blocked by:** None（无前置工单，可立即开始）

## 验收条件

- [x] 跨转发链 SNI 仍可共用入口端口，入口分流器身份由入口主机和端口稳定确定，删除组内任意规则不改变健康规则的受管运行时身份。
- [x] 新增规则保留既有连接；修改目标只影响该规则；删除或暂停某域名不撤掉其他规则仍需使用的监听，并通过实际连接验证热更新。
- [x] 带可读明文 SNI 的 TLS 请求包括携带 ECH 扩展的请求仍可转发；无 SNI、未知域名、非 TLS 和无效握手继续拒绝，无默认落地机。
- [x] 主机流量排除只调整运行时参与，保存成员和端口不变；入口超量保留健康入口，必要中继或出口超量暂停相关链，共享端口上的其他健康链继续服务。
- [x] 来源名单保持为空，主机地址变化不会恢复自动来源限制；旧 nftables、iptables 和 ip6tables 标记规则按既有约定清理，不误删其他规则。
- [x] 防火墙读取或删除失败可以重试，清理回执确认与稳定收敛继续有效，使用本轮实际心跳产物完成隔离 Linux 故障与网络验证。
- [x] Agent 升级前将实际退役 SNI 快照与面板有效规则核对；确认与本次升级直接相关的缺陷时作最小兼容修正，不扩大为所有历史运行时的重构。
- [x] Agent 重启及升级后核对活跃进程、有效监听和退役端口，分别记录运行时快照与防火墙清理结论；无法实测的情况明确记录。
- [x] 保留端口占用快照的体积上限与准确覆盖，缺失记录不解释为已核实无占用；不恢复创建阶段的真实主机监听拦截。

## 实施起点

本地已有热更新、空来源名单及旧防火墙清理机制，当前合并保留其实现。退役 SNI 持久快照在 Agent 启动恢复阶段是否可能复活仍需结合实际规则与快照核查；来源规则清理的通过证据不能替代此核查。
