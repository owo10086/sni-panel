## 验收条件

- [x] 通知默认 Telegram，渠道二选一；切换保留另一方配置与用户绑定，不自动切换生产现有渠道。
- [x] Discord 使用自己的 Bot 身份、Token 和绑定，不复用 Telegram 凭据；两种渠道的绑定、解绑、公告订阅、查询与一次性网页登录均正常。
- [x] 主机、规则及转发组事件通知按当前渠道发送，本地端口占用等既有通知继续可用；管理员和普通用户接收范围符合权限。
- [x] 私聊限制、消息长度处理、限流、有界队列、Token 校验、发送失败及重连按上游处理，用户可理解常见操作错误。

- [x] 新身份和绑定数据兼容既有数据库，凭据与运行机密不进入浏览器、公开诊断或明文审计。
- [x] 通过渠道切换、绑定交互、通知发送及失败恢复验证网页配置到实际业务入口的完整行为，记录真实平台与隔离 fixtures 各自覆盖。
- [x] 中文和 English 的配置、用户绑定及交互提示清楚一致，提供上游已支持的管理和 AI 入口。
