# 14: 迁移冻结、一致快照与数据库健康保护

Status: resolved

**What to build（交付结果）:** 管理员能按上游前提开始迁移，源业务冻结后得到一致快照并事务导入目标；冻结、数据库故障和失败恢复各自正确生效，目标配置、TLS 与已有运行状态得到保留。

**Blocked by:** None（无前置工单，可立即开始）

## 验收条件

- [x] 开始无缝迁移前校验两端同版本、同数据库类型、单实例、目标无业务数据、旧公开地址正确及全部 Agent 实际具备新增迁移能力。
- [x] 旧本地 Agent 3.2.0 不因版本数值大于上游而错误通过新能力检查；不满足前提时有准确原因。
- [x] 源业务和后台写入冻结，等待已准入的在途操作与数据库操作完成后导出一致快照，保留 ID、Token、端口、计量与运行状态。
- [x] 目标事务导入并校验，初始化管理员由源账号替代；保留目标数据库连接配置和 TLS，不迁移浏览器 Cookie 或覆盖目标证书。
- [x] 冻结和验证阶段不执行普通结构同步或其他未准入写入，迁移状态与接管信息持久化在受限目录，不进入公开日志或诊断。
- [x] SQLite 健康探测保持只读及连接锁保护，冻结和目标验证期间仍能准确探测；迁移业务只读拒绝不改变数据库健康状态。
- [x] 真实数据库存储、初始化、损坏或断连保护继续生效，成功只读探测不会误清存储故障；TLS 缓存权限与日志脱敏保留。
- [x] 数据库与迁移状态共同控制后台任务，取消冻结或恢复数据库不会误清另一项保护，也不会重复启动调度器。
- [x] 事务导入失败可回滚；转交前可取消或按上游冻结时限恢复；进程重启后仍能识别正确阶段与私密信息。
- [x] 通过隔离源目标、健康检查跨间隔运行、导入故障和实际持久状态验证；分别记录 SQLite、MySQL 和 PostgreSQL 的实测及未覆盖范围。

## 实施起点

上游迁移状态与数据库写保护已合入。审查确认 SQLite 健康检查在迁移只读阶段可能被拒绝并误判为数据库不可用，从而阻断迁移或 Agent 报告；这是本工单需优先修复的兼容问题。
