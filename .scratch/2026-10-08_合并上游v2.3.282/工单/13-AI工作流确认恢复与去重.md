# 13: 机器人 AI 工作流确认、恢复与去重

Status: resolved

**What to build（交付结果）:** Telegram 与 Discord 用户可以让 AI 补充缺失信息、预览并逐项确认业务操作，重启或确认过期后继续未完成工作；重复确认不重复执行，失败和不确定结果清楚可见。

**Blocked by:** 11：Telegram 与 Discord 通知及账号交互；12：AI 业务工具复用网页权限与校验

## 验收条件

- [x] 流程按理解目标、按需最小上下文、受控计划、业务校验和逐项预览确认进行，缺少资源、协议或端口时通过动态选择补参。
- [x] 询问、条件描述和未确认意图不会直接变为写操作，单一可选资源也按上游确认规则处理。
- [x] 工作流作用域、步骤、状态和结果持久化，按渠道、用户和会话隔离；不同用户或旧按钮不能操作他人待办。
- [x] 真实进程重启、确认过期后仍能查看并继续未完成步骤，已完成步骤及其结果保持正确。
- [x] 重复确认不重复创建、修改或扣费；结果不确定时停止自动重试，展示已完成、失败及待处理项。
- [x] 旧按钮、权限变化与资源配置变化在执行前重新校验，用户实际执行的是当前有效的预览内容。
- [x] 逐项执行或部分失败保留未修改的配置和授权，重试只针对允许继续的步骤，不重复已成功副作用。
- [x] Telegram 和 Discord 均通过真实业务边界或隔离交互验证补参、过期、重启、重复确认及不确定结果，记录各渠道实际覆盖。
- [x] 流程提示、业务预览和结果在中文及 English 下可读，保留原始用户内容和必要诊断。

上游持久工作流与补参逻辑已应用，本轮已有机器人重启、过期、重复确认及部分执行验证记录。需要在权限工具和两种通知渠道验收后确认最终组合行为。
