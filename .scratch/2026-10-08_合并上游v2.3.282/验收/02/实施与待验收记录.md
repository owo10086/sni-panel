## 实现与修正

- 重置确认按角色说明实际影响：管理员清统计并清零逻辑规则已用额度，达量暂停在账户及其他条件允许时可能恢复，到期规则仍暂停；普通全量跳过托管规则。两种角色均说明账户套餐用量、余额、计费记录及到期时间保持。
- 全量操作覆盖用户范围内全部分页，忽略搜索、链路、分类、勾选；英文作用域名字先翻译再插值。网页补验发现空链路或分类会错误禁用全量按钮，已将范围计数的 `scopeFilter` 排除资源筛选，实际列表与分页仍使用完整筛选。
- 配置默认收起，区分规则流量额度、创建规则与端口配额、账户套餐流量；最大值计量明确为两方向累计值取最大值。同步用量组件、双语文案与指南；修正英文单条确认将重置误写为替换的问题。
- 普通非 SNI 单规则限速仅在实际入口执行，多入口分别执行；共享下游不附加根规则限速。能力检查只校验执行主机，SNI 出口限制保留独立路径。
- `cumulativeRuleTraffic` 共用首次额度基线查询与累计汇总；初始化并发保护和报告增量扣除保留在各入口。
- 真实 HTTP 夹具覆盖鉴权、报告去重、错误主机不入账、升级基线、逻辑计数持久化、事务回滚、用户范围、到期与账户限制叠加以及双入口共享下游。

## 真实网页验收

使用真实 React 页面、真实 appRouter、登录会话和合成用户数据，面板地址为 `http://127.0.0.1:18822`，无生产连接。

- 普通用户拥有 17 条根规则，默认每页 12 条。全量请求 HTTP 200，返回 15 条自建根规则及其派生子规则，跳过达量和到期的两条托管规则，未处理管理员本人规则。见 [中文确认](普通用户全量重置确认.txt)、[实际结果](普通用户全量重置结果.json)。
- 管理员单条重置达量规则，逻辑用量由 600／500 清零为 0／0，达量原因解除，页面显示已用 0 B、剩余 1.00 KiB。见 [确认](管理员单条重置确认.txt)、[页面](管理员单条重置后页面.txt)、[实际结果](管理员单条重置结果.json)。
- 管理员指定用户，同时设置搜索、具体链路、分类和单条勾选后，全量请求仍仅按 userId 2，覆盖该用户全部 17 条根规则及子规则。到期用量清零但理由保持 `expired`，管理员本人的 id 7 不在请求根规则中。见 [确认](管理员指定用户全量确认.txt)、[实际结果](管理员指定用户全量结果.json)。
- 搜索不存在的规则并切至空分类，列表为 0 条，全量按钮仍可用，实际请求覆盖该用户全部 17 条根规则。见 [空列表页面](空搜索与分类仍可全量重置.txt)、[实际结果](空搜索与分类全量重置结果.json)。
- “所有用户”全量请求覆盖全部 18 条根规则，包含管理员本人 id 7。见 [中文确认](管理员所有用户全量确认.txt)、[实际结果](管理员所有用户全量结果.json)。
- English 普通全量确认显示 My Rules，明确跨页与跳过托管；管理员确认显示 All Users，明确规则用量清零、达量可能恢复、到期仍暂停。单条确认已使用正确的 Reset 语义。见 [普通全量](普通用户英文全量确认.txt)、[普通单条](普通用户英文单条确认.txt)、[管理员全量](管理员英文全量确认.txt)。
