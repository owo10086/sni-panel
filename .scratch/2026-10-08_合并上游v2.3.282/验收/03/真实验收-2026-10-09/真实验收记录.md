## 实际限速、连接数与计量

出口运行配置为双向 6250000 B/s（50 Mbps）及 7 个连接上限；同时保持 7 条 API TLS 连接，第 8 条被拒绝，健康域名新 TLS 请求成功。实际日志保留 maxConnections active=7 的拒绝原因。

API 传输 32 MiB 实测 4449 毫秒；同时健康域名传输 512 KiB 实测 4 毫秒。现有 FXP 限速器允许一个秒速率额度的初始突发；32 MiB 在这份配置下扣除初始突发后的理论下界约 4.37 秒，4.449 秒符合该行为。该检查证明单规则限制生效与健康域名独立性，未声称零突发的固定吞吐上限。

实际 FXP 报告到达面板后，API 逻辑用量为 33603308 入／33615228 出；健康 WEB 的持久流量统计为 526414 入／530860 出。未设限健康域名的逻辑额度字段按设计可为空，验收采用 traffic_stats 核实其入账。

重放同一份实际 FXP 报告返回 duplicate=true，API 前后用量一致；入口另报 9999999／9999999 字节也不增加该规则用量。随后将额度设为 67284072 字节，实际 API TLS 流量报告令持久用量达到 33735009／33748419，触发 traffic_limit。通过 FXP 控制 socket 读取实际生效分流表，按当前 Agent localState 格式送入真实心跳；心跳下发仅 WEB 的配置，实际 FXP 热更新撤除 API。管理员重置后用量立即 0／0、原因清空，心跳恢复两域名，实际 API TLS 恢复，健康长连接和进程持续正常。保存的业务字段前后相等。

该闭环使用生产加密中间件与 Agent HTTP 路由；心跳请求由临时夹具携带 FXP 实际运行状态发送。本轮验证本单的隔离运行与面板闭环，生产 Agent 升级和持久快照恢复仍在后续工单范围。
