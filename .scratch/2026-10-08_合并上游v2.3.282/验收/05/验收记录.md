## 本单修正

1. **已有 UDP 配置会让纯新增误走重启。** 真实面板为 UDP 生成 `readBufferSize`、`readQueueSize` 等字段；GOST 从文件读取后在本地接口中返回小写字段名。比较时把大小写误判为已有规则变化，实际新增导致共享进程更换、旧连接断开。现只统一 metadata 字段名的大小写，保留字段值，包括 `false` 和 `0`。失败现场见 [新增失败记录](udp-add-red.log)、[Agent 记录](udp-add-red-agent.log)，修正后的实际过程见 [完整真实验证](agent-real-green.log)。
2. **第二份配置校验失败时会误重启第一份健康服务。** 第一份配置文件已暂存，第二份 JSON 无效，内部回滚恢复第一份文件后又重启服务。现将“文件准备未完成”阶段的回滚限定为恢复文件；成功交出配置事务、开始执行服务命令后的恢复流程继续有效。失败现场见 [校验失败记录](validation-red.log)、[Agent 记录](validation-red-agent.log)。

修改 `agent/gost_additive_sync.go`、`agent/managed_configs.go`，新增可复用真实 Agent 验证脚本 `scripts/verify-gost-agent-sync.mjs`，在 `docs/guide/agent.md` 补充版本、首次启用和重建影响。789 份已有源码／文档核对，仅上述 3 份已有文件变化；新增脚本见 [本单代码差异](05代码差异.diff)。本单没有覆盖其他上游集成改动。

## 真实场景与连接结论

- **首次启用：** 两份已有 GOST 配置原来没有本地接口，候选 Agent 下发后两份进程都发生一次重建，旧连接关闭，新业务可用。这项影响已在 Agent 升级指南说明。
- **新增成功：** 主转发新增监听和限速依赖、隧道出口新增监听；两份共享进程 PID 及启动时间保持，原来的 2 条主转发 TCP 连接、1 条经真实 GOST 认证中继的隧道 TCP 连接及 UDP 转发均正常。新增端口实际回显成功。
- **端口冲突：** 主转发新增成功后，隧道出口在已被占用的 23005 端口失败。两份配置文件回到此前已生效内容；本次新增监听及限速依赖被撤回，原来 3 条 TCP 连接和 UDP 转发继续。外部占用的监听由夹具持有。
- **依赖／应用失败：** 分别在第一条执行命令前和第一份运行时新增完成后注入真实 shell 非零退出；验证 Agent 执行的回滚，不由夹具代为恢复。两份进程身份、3 条 TCP 长连接、UDP 和原配置保持。
- **配置准备失败：** 第二份配置携带无效 JSON，第一份文件恢复；两份进程身份、3 条 TCP 长连接和 UDP 均保持。此场景是第二处修正的实际回归。
- **修改／删除：** 修改主转发目标后只重建主转发服务，新连接到达修改后的目标，隧道连接继续；随后同时删除主转发和出口监听，两份服务按原方案重建，被删端口关闭，保留业务可用。
- **故障恢复：** 停止两份 GOST 进程，由正常健康检查刷新后再次交付恢复计划，两份服务重建、保留业务恢复。不承诺故障期间连接保留。
- **Agent 重启：** 单独重启候选 Agent，两份 GOST 进程保持，同一条业务 TCP 连接继续回显。
- **旧 Agent 回退：** 实际运行已发布 3.2.0 Agent，交付新面板为旧版本生成的计划；旧 Agent 将局部更新标记当作 shell 注释，执行保留的配置变化重启方案。两份服务实际重建、旧连接关闭、计划内业务恢复。没有因 3.2.0 数字高于上游门槛就声称支持新增能力。
- **入口依赖：** 改为执行真实隧道入口计划。新增监听同时添加真实 GOST chain 和 limiter，原 2 条隧道连接、进程身份保持，新入口实际转发成功；再次新增时制造 22005 冲突，本次新增监听、chain 和 limiter 均撤回，原有 3 组 chain 和 1 组 limiter 保持。
- **访问范围：** 控制接口为 `/run/forwardx-agent/gost-api/` 下的 Unix socket；目录权限为 0700。root 读取配置成功，普通 `nobody` 用户通过真实 curl 连接失败。未生成新的 TCP 公共管理监听。
