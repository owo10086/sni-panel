## 实际结果

- 先失败后修正：旧 EXCLUSIVE 探针在 frozen／verifying 阶段报 PANEL_MIGRATION_READ_ONLY；改为已有只读查询后通过。真实 SQLite 的源冻结和目标验证跨多次定时健康检查，拒绝业务写入仍健康；探针确实等待独占连接锁；成功 SELECT 不清除尚未修复的 SQLITE_FULL。
- 最终定向检查 43／43 通过，0 失败、0 跳过。涵盖健康保护、无缝迁移、普通迁移、事务、切库、通知共同保护和 TLS 私密缓存。类型与差异检查均退出 0。
- MySQL 8.4.11、PostgreSQL 18 实际隔离源／目标库：旧 Agent 3.2.0 在冻结前被拒绝，3.3.0 才能继续；一致快照保留编号、Token、监听端口、运行及累计流量。目标重复编号注入导致整个事务回滚，初始化账号和设置完整保持；成功导入用源管理员替换初始化管理员，保留目标连接设置、证书和私钥；再次导入被拒，重连仍保留结果，状态文件 0600。
- 真实停止并重启这两种数据库：健康状态实际变成 unavailable，恢复后变成 healthy；撤销迁移保护不会清除数据库故障，数据库恢复不会解除源冻结；没有重跑结构同步。Docker 动态端口在重启后变化，验收脚本读取新端口后重连，确认原数据保留；不声称原端口自动恢复。
- 两个真实面板进程经管理员批准、冻结、导出、导入及报告验证完成迁移；另一路覆盖转交前拒绝写、转交后禁止取消、状态重新加载、导入提交后标记恢复及源重启继续只读。现有 TCP echo 长连接仅证明旁路连接保持，受管 Agent／FXP 连接和计费验收属于 15，未以它代替。

## 前提及保护范围

- 接管入口检查同版本和同数据库、空业务目标、目标地址身份以及与源公开地址的一致性。Agent 能力门槛为本地 3.3.0；本单测试版本拒绝及候选能力存在，不声称第三方改造 Agent 仅凭自报版本也已证明所有能力。
- Setup 与指南明确要求两端各一个实例、同库没有其他写入。此次两端确为隔离单实例；程序无法侦测任意外部写入，不提供同库多实例协调，也不把文案前提写成自动检查。
- 源冻结先排空已准入请求和数据库操作；SQLite 同一连接锁，MySQL 事务及 PostgreSQL REPEATABLE READ 保持一致导出。冻结／验证跳过普通结构同步，后台准入和数据库故障保护各自生效。取消或健康恢复不能清另一项，后台启动有重复保护。
- 导入事务不携带浏览器会话，目标要求重新登录。私密接管信息保存在权限 0600 的状态文件；公开状态和错误不泄露 Token、私钥或数据库参数。TLS 缓存的实际保留／权限／脱敏回归通过。
- 仅尚未转交的源冻结可取消或超时解除；已转交／归档源库不能超时重新变成计费写入端。目标导入提交与状态标记之间崩溃可通过持久导入标记恢复。
