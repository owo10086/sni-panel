# 合并上游 v2.3.282

Status: ready-for-agent

**Decision date:** 2026-10-08

**当前阶段：** 本轮实施已进行，实际进度见 [实施接续](实施接续.md) 与 [工单索引](map.md)。本文作为本轮合并范围和验收要求的依据。

**范围调整（2026-10-10）：** 按用户先后两次要求，删除 Apple 和 Android 平台相关代码合并需求。两平台专属工程、依赖、应用版本、下载更新入口、构建与发布流程、IPA／APK 产物及原生验收均退出本轮范围；第 16、17 单取消，第 19、20 单按调整后的范围检查、提交和发布。网页的双语与窄屏适配继续按保留需求验收。

## Problem Statement

sni-panel 已将上游 v2.3.281 集成并发布为面板 3.2.5，Agent 与 FXP 仍为 3.2.0。上游 v2.3.282 增加单规则限额与托管权限、机器人业务工具、Google 登录、Discord 通知、双语界面、无缝迁移，并修复 GOST 共享运行服务、探测统计与手动探测等问题。用户需要实际合入本轮范围内的代码，使本项目获得这些新能力与修复。

本地已经提交并上线 SNI 分流、入口分流器、共享端口、出口计量、来源限制删除、规则批量操作以及独立发布约定。整体替换为上游代码会损失这些能力；按改写前的远古共同祖先直接合并，又会卷入不属于本次升级的历史差异。

本轮已确认的权限冲突是：本地此前允许普通归属用户启停、删除管理员代建的 SNI，上游则将代建规则和有限制的规则视为管理员托管，只允许普通用户查看。用户已明确选择上游方式，包括现有的限速 SNI。此决定必须同时落实到网页、业务接口、批量操作及机器人，避免出现不同入口执行不同权限的情况。

## Solution

以已上线的 sni-panel 为基础，集成上游 v2.3.281 到 v2.3.282 标签最终提交之间、本轮范围内的实际代码增量。接纳这些上游功能、默认设置和操作方式，并对本地已提交功能做必要的兼容处理。

规则归属遵循管理员当前用户筛选：“所有用户”下新增、复制、导入默认归管理员本人，指定用户下归该用户；资源权限、配额和端口范围按归属用户检查。管理员托管规则采用上游权限，SNI 不设例外。管理员重置规则统计时同时重置该规则的额度用量；普通用户不能重置托管规则或有限额规则的用量。

SNI 继续用入口分流器选择转发链、出口分流器选择落地机，并在出口统一计量、限速和限制连接数。单规则达量、到期或主机流量排除只影响对应规则及链路，不误停共享端口上仍正常的其他域名。

实现、验证和审查完成后提交代码，再对合并产物进行上线验收和正式发布。本次包含 Agent 生产代码变化，按本项目版本规则发布面板、Agent、FXP 3.3.0。安装、升级及发布仍使用 sni-panel。

## Implementation Decisions

### 1. 固定代码来源与合并方法

- 本地准备基线为 main 的 `b258398e55ab1bee06eedcc1475a96bd7a79ff83`，当前已发布面板 3.2.5、Agent/FXP 3.2.0。实际实施开始时重新记录当前提交与工作区状态，保护后来出现的用户改动。
- 上游内容基线为 v2.3.281 的 `63fd45b3910df094fbfcab6f865830bb7a6877a8`，目标为 v2.3.282 标签实际提交 `fb7e959bf19c80f417c9ff0e01e3d801478553cf`。差异包含三个提交、288 个文件、增加 21582 行和删除 8007 行。
- 固定最终标签，包含最后的人机验证配置；其中移动平台专属变化按最新范围排除。Release 元数据中较早的目标提交及后续上游 main 不替代本次目标。
- 在隔离工作树或临时分支按上游两版的内容增量集成，逐处处理三方冲突，不用上游整树覆盖当前项目。接纳本轮范围内的上游测试与回归覆盖，并保留本地测试入口。
- 文本冲突集中在规则界面、规则业务、文档、发布和版本模块；自动合并成功的心跳、计量、迁移和机器人模块仍按行为检查。
- 为全部上游产品变化记录实际处理结果：直接合入、按本地既有功能适配、已存在等价实现，或按最新决定排除 Apple 和 Android 平台专属内容。以固定基线区分本轮专属合并变更与既有功能，网页共用功能按保留需求处理。最终保留实际提交、产物身份及验证证据。

### 2. 讨论规则与最终权限决定

- 功能和操作方式以本轮确认的上游方式为准。只有实际改变本地已提交功能、且尚无决定的冲突才需要提问；一般实现选择和文本冲突自行处理。
- 采用上游自动托管，SNI 不豁免。管理员代其他用户创建规则或提交单规则限制参数时按上游持久化托管标记。
- 托管判定既包含已保存的托管标记，也包含正数限速、正数流量额度或到期时间。字段缺省为非托管不表示存量有限制规则保持原权限；现有正数限速 SNI 也执行托管只读规则。
- 普通用户不能编辑、启停、删除、排序及重置托管规则。清空限制不会解除已保存的托管标记。普通自建且无托管标记或规则限制的规则保持上游权限。
- 本项明确替代上一轮允许普通归属用户启停、删除管理员代建 SNI 的决定。相应用户指南与历史规格补充替代说明，保留旧实现记录。
- 前端单条和批量操作、后端接口及机器人统一鉴权，不能仅隐藏按钮。系统子规则仍通过根规则或模板管理，不允许直接操作派生规则绕过权限。

### 3. 用户筛选、资源与额度

- 管理员当前筛选决定新增、复制、导入的归属用户。“所有用户”下默认管理员本人；具体用户下按该用户操作；编辑已有规则不改变归属。
- 保留实际登录操作人与归属用户的区分。SNI 配置权限及管理员字段按实际操作人校验，资源访问、账号状态、套餐、余额、规则和端口配额及有效端口范围按归属用户校验。
- 保留本地规则数量与端口去重口径，派生子规则不重复占用规则配额；同一用户复用 SNI 入口端口不增加一份端口配额，新规则仍增加规则数量。并发预留遵循现有保护机制。
- 保留行内选择、全选、批量修改、删除、复制与逐项结果反馈。托管限制按上游纳入这些入口，成功与失败项不能因界面合并而错误归纳。
- 保留已确定的“全部统计”用户范围：覆盖该范围所有分页，不受列表搜索、链路、分类或勾选缩小。普通用户的全量重置按上游跳过不可重置的托管规则；显式操作不可重置规则时拒绝。

### 4. 单规则限制与统计重置

- 接纳管理员默认收起的规则配置：限速、流量额度、计量方式、创建时间及到期时间。0 或空表示相应限制关闭，到期为空表示无独立期限；创建日期用于记录，不是定时启用开关。
- 限制适用于管理员本人及其他用户的规则。账户权限、套餐和余额约束同时生效；管理员身份不绕过规则运行限额。
- 达量或到期时在期望状态中暂停逻辑规则及相关成员、入口和出口，保存的启用开关、资源与端口不被改写为用户停用。限制解除后按保存配置和其他运行条件恢复。
- 流量额度使用逻辑规则独立计数；首次采用已有累计统计建立基线，后续在已鉴权、去重的计费事务内累计。切换链路、替换派生成员、修改日期以及普通启停均不清零。
- 按上游绑定统计和额度重置。管理员重置目标规则统计时，同一事务重置逻辑规则额度计数，再协调运行状态；达量规则可能恢复。全部重置也有同样效果，确认提示和指南说明这一影响。
- 普通用户不能重置托管或有限额规则的用量；不会另增独立的额度重置操作。规则重置不清零账户套餐流量、余额或按量计费记录，也不会消除到期限制。
- 展示累计、额度、剩余和计量方式。规则额度、账号可创建的规则/端口配额及账户套餐流量是不同概念，文案分别说明。

### 5. SNI 的运行与计量兼容

- 沿用既有架构：独立 FXP 入口分流器按域名选择转发链下一跳，出口分流器选择落地机；分流表是规则推导的期望状态，不引入新链路资源或替代运行时。
- 继续按可读明文 SNI 转发，ECH 扩展存在不直接导致拒绝；未知域名、无 SNI、非 TLS 和无效握手仍断开，不新增默认落地机。
- 多条规则可在同一入口端口共存，并支持跨转发链共用。入口分流器身份由入口主机和入口端口稳定确定，不依赖某一条规则的身份。
- 保留分流表热更新及影响范围：新增规则保留既有连接，修改目标只影响该规则；暂停或移除受限域名时不撤掉其他规则仍需使用的共享监听。
- 单规则限额和现有主机流量排除都必须在生成分流表前应用，根规则策略传播到相关派生入口与出口。达到一项限制不能借另一项恢复或重建绕过。
- 沿用出口作为 SNI 流量、限速和连接数限制的唯一业务执行点；入口 SNI 报告不能重复入账。新的逻辑额度计数使用现有出口报告到根规则的汇总，不改成按每台入口主机累计。
- 普通非 SNI 规则按上游在入口执行限速；多入口普通规则的上限按每台入口独立执行。SNI 不把此逻辑复制到入口而放大总限速，相关能力检查按实际执行限制的主机判断。
- 保留按域名在入口及出口有效配置中判断运行状态，不将端口有人监听视为每条 SNI 都在运行。
- 保留已上线的空来源名单、旧防火墙来源规则迁移、回执确认和失败重试。主机地址变化不会恢复已删除的自动来源名单。

### 6. 本地端口、流量排除与恢复保护

- 遵循既有端口约定：数据库端口冲突、资源/套餐范围和 SNI 可复用性仍校验；真实主机监听占用不恢复为创建、修改或随机端口选择的拦截条件。内核警告与用户态绑定错误保留。
- 端口占用快照和新的有界探测数据按相同单位裁剪并说明实际覆盖，缺失数据不能解释为已经核实正常。
- 主机流量排除继续是运行时参与调整，保存成员与端口不变。一个入口超量时保留其他健康入口；固定必要中继或出口超量时暂停相关链，同端口其他健康链继续服务。
- 保留数据库存储/初始化故障保护、后台暂停、TLS 缓存权限和脱敏。迁移冻结状态与数据库健康状态共同约束后台写入，不能互相误清或重复启动调度器。
- 现有验证码/2FA 有界 Map 清理等价修复与可选 iperf3 安装继续有效，避免吸收上游其他改动时退回旧行为。

### 7. Agent、GOST 与探测累计计数

- 合入 Agent 的 GOST 增量新增监听与依赖、私有本地控制接口及对应回归；新增失败仅回滚本次新增，不以重启健康共享进程作为失败兜底。
- 首次启用 GOST 局部更新接口可能重启一次共享运行服务。配置修改、删除及进程故障仍沿用上游重建路径。采用上游兼容与升级方式，不承诺仅升级面板或首次启用完全无中断。
- 本地版本线按实际能力维护。旧 Agent 3.2.0 的数值高于上游 2.2.195，不代表拥有新增接口、累计计数或迁移能力；相应门槛采用本地实际支持版本或已存在的能力信息，保持旧 Agent 回退可用。
- 累计计数包含进程周期身份、总次数、成功数和批次信息。面板按单调快照差分，重复、乱序和旧周期报告不重复累计，逐跳健康缓存不额外变成失败次数。
- 旧抽样记录继续显示延迟，不用于精确失败率或稳定性评分。缺少新计数时明确显示暂无准确统计；显示平滑不改变稳定性计算，聚合不能截断原始探测次数。

### 8. 手动探测、监控与分类统计

- 探测请求、原始参数、结果、批次、汇总状态及首次投递时间持久化。全部任务入库后再统一投递，重复报告不重复汇总，旧批次不覆盖新批次，重试不延长首次执行超时。
- 多入口、多出口和备用中转按完整可用路径检查，备用中转不当作额外串行节点。自动探测不覆盖未结束的手动任务，部分结果、超时和失效原因继续可见。
- 仅自测保留当前运行状态与配置版本，配置变更仍走正常应用路径。运行恢复期间待执行任务继续按上游快速心跳和就绪机制重试，不靠延长超时掩盖失败。
- 独立主机监控增加实时报告触发、隔离请求及超时、页面恢复和网络重连刷新、最后更新时间与重试；临时失败保留旧数据，避免误报不存在及大曲线参数展开异常。
- 规则分类数量按当前用户与搜索范围独立计算，分类或链路筛选只影响当前分页和汇总；加载期间不以当前页替代总量。

### 9. 双语界面、人机验证与 Google

- 合入完整中文/English 界面、语言选择、安装初始化语言参数及长文案布局。手动偏好优先，自动模式以浏览器语言为主，已有地区信息作兜底，不新增访客定位请求。
- 本地 SNI、批量操作、品牌和提示文案同步纳入语言支持；用户输入内容和原始诊断文本不被翻译覆盖。中文沿用领域词汇并自然表达，日期金额适配语言。
- 登录/注册人机验证默认开启，关闭后服务端和浏览器一致停用；密码、限流、邮箱验证与 2FA 保留。最终标签中的此补丁必须纳入。
- Google OAuth 默认关闭，配置后提供注册、登录、显式绑定、确认解绑与新账号设密码。遵守现有注册开关、邮箱白名单、默认权限、账号禁用、2FA 和会话约定，不自动合并同邮箱账号。
- 合入上游一次性浏览器状态、PKCE、签名/受众/nonce 校验、超时与限频。客户端密钥不返回浏览器，也不写入明文审计。

### 10. 通知渠道与受控 AI 工作流

- 通知默认 Telegram，可选择 Discord，渠道二选一并保留另一方配置与用户绑定。Discord 使用自己的 Bot 身份、私聊命令与交互，不复用 Telegram 凭据。
- 合入绑定/解绑、公告订阅、查询、一次性网页登录、管理和 AI 按钮、主机及规则事件通知；保留私聊限制错误、长度处理、限流、有界队列、Token 校验和重连处理。
- AI 沿用既有开关与权限，扩展规则、链路、用户授权、套餐订阅、计费、主机和系统设置等上游受控工具。复用网页业务接口，不在机器人中复制一套较弱的授权。
- 流程采用理解目标、按需最小上下文、受控计划、业务校验及逐项预览确认。缺少参数时动态按钮补充，旧按钮和配置变化需重新校验；重启或确认过期保留待办。
- 按上游持久化作用域、步骤、状态和结果，隔离渠道、用户与会话；重复确认不重复执行，不确定结果停止自动重试，局部更新保留未修改配置和授权。订阅续期写入正确的业务真值，避免被权益同步覆盖。
- 模型响应执行正文超时与体积限制。凭据、数据库迁移、升级和任意命令等不进入新增 AI 写工具。上游工具没有提供的 SNI 创建参数不擅自扩展，已有规则被 AI 操作时仍执行其托管权限。

### 11. 无缝迁移

- 合入普通迁移与无缝迁移，表单默认选中上游无缝模式。功能集成不意味着本次原地升级要执行生产迁移。
- 无缝前提按上游校验：两端同版本、同数据库类型、单实例、目标无业务数据、旧公开地址正确、全部 Agent 具备当前要求的实际能力。目标初始化管理员由源账号替代，新端配置和 TLS 保持目标配置，不迁移浏览器 Cookie 或覆盖目标证书。
- 冻结源业务与后台写入，等待在途操作完成后导出一致快照；原样保留 ID、Token、端口、累计计费和运行状态。目标事务导入与校验，验证期只接收报告，不下发重建或清理。
- 旧地址持续转交原始加密请求、事件连接、流量报告及支付回调。迁移完成后必须长期保留旧接入地址和转交服务，不支持无缝增量合并。
- 阶段和私密接管信息持久化并限制读取权限；导入失败事务回滚，转交前可取消或按上游冻结时限解除，转交后不恢复旧库写入。网络结果不确定时保留验证状态继续处理，避免双端计费。
- 普通模式继续允许切换 Agent 接入地址，并说明可能重建运行时和中断连接。既有 SNI 共享监听、计量及来源清理不得在迁移验证期被无故重建或撤除。

### 12. 数据结构、依赖和配置

- 接入上游用户 Google/Discord 身份、绑定及一次性代码字段；规则流量限制、计量方式、有效期、托管标记、暂停原因及独立额度计数。

- 本地已有 SNI 限速字段保持同一业务字段，不创建第二份相互覆盖的配置。旧记录按上游默认值及托管推断处理，并测试升级数据，而不是只测试新建数据。
- 环境语言、Discord Token 和迁移状态位置等采用上游可选配置，升级保留已有配置。依赖及锁文件以本轮保留的功能为准。
- 自动结构同步、迁移冻结和隔离目标状态按上游协调；不能在应只读阶段执行普通结构写入。配置缓存、迁移接管凭据和运行机密均由受限持久目录管理，不纳入代码或公开诊断。

## Testing Decisions

### 验证原则与既有入口

优先在已有真实业务边界测试：使用临时数据库的公开业务路由及会话，结合 Agent 心跳、报告和实际期望状态；通过接口结果、持久化用量、用户可见状态和真实转发判断是否正确。无需为本次合并新建一套服务抽象或单独的测试 API。

沿用此前已经讨论并使用的入口：规则归属与 SNI 权限集成、规则额度预留、真实心跳分流配置、已去重的流量报告、数据库故障与 TLS 缓存、手动探测分发、机器人业务流程、前端交互以及隔离 Linux 的 Agent/FXP 网络验证。这些入口适用于本轮，继续采用其高层行为检查。

测试只断言外部可观察的行为和必要持久状态，不通过比较实现函数、内部调用顺序或代码片段证明正确。吸收上游回归时保留本地有效案例，将已被新决定替代的“普通用户可启停托管 SNI”断言更新为上游只读行为。权限与额度关键行为可按已有入口先写失败用例，再逐步实现；不要一次批量编写与实现结构同形的低价值测试。

### 验证执行与上线证据

- 实施期间定期类型检查并运行受影响的单组测试；合并结束运行完整面板测试、类型、前后端构建、文档和版本一致性检查。本轮范围内的新增上游测试进入实际执行集合，本地与保留功能有关的有效回归不丢失；Apple 和 Android 专项验证随范围调整取消。
- 在隔离 Linux 环境完成 Agent 和 FXP 的 Go 测试与静态检查，使用真实 GOST 和 FXP 验证共享监听、热更新、额度、出口计量、来源规则清理及连接行为。期望配置通过不能替代实际网络验证。
- 数据库损坏、断连、迁移冻结、额度耗尽、安装失败等故障注入优先放在隔离环境。多数据库分别记录实际验证环境，未提供环境的项目不能记为通过。
- 同一入口端口设置两条 SNI，一条达量或到期后用真实 TLS 验证其停止而另一条仍可用，再验证管理员重置或修改限制后的恢复。这是本轮与上游结合的关键验收。
- 迁移使用隔离双面板，至少保留一条真实业务长连接并观察受管运行时身份，检查转交前失败回滚、转交后继续与计费唯一性。
- Agent 升级前核查本地已知退役 SNI 快照残留，升级后检查活跃监听和退役端口；不要把来源防火墙清理等同于历史运行时快照已经回收。
- 使用最终合并产物重新做候选上线验收，记录实际提交、镜像摘要或产物哈希、版本、登录、关键 SNI 与普通转发、主机状态及新增能力。正式镜像再核对版本、资产来源与关键转发。
- 最终执行规范与规格两轴代码审查，修复确认的问题后重验受影响行为，再提交。记录取消范围、未覆盖拓扑及剩余限制，不沿用上一轮产物的通过结果替代本轮验收。
