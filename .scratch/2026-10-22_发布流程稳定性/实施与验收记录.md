## 补充检查发现并修复的问题

1. FXP 完整竞态检查发现两个旧测试同时读写同一配置变量。监听端改为读取不可变副本，生产代码不变。
2. Agent 的 UDP 连发测试要求 32 包全部返回，却遗漏生产已存在的 25 毫秒旧包淘汰规则。临时副本的诊断记录证明包等待约 45～58 毫秒后按该规则被丢弃。修正为保留 32 包真实连发、全部写入成功、已收载荷精确匹配及不重复、末包必须返回；原 TCP/UDP 精确单包、引用替换和 15 秒总截止保留。用固定时间补齐阈值前 1 纳秒、恰到阈值和无更新包的边界。不改生产规则或增加超时。
3. 本地 Docker 的依赖安装将 pnpm 缓存放在工作区卷根部，第一次检查如实记录为非干净源码。增加 `.pnpm-store/` 忽略项；缓存不参与源码或发布包。最终检查重新生成记录，不篡改旧记录。
4. 删除旧工作流后，安装脚本静态检查仍读取旧文件；已按统一入口更新。保留第一次失败日志，修正后重新运行相关整组。
5. 隔离 FXP 夹具原先绑定宿主临时目录，独立 Docker 守护进程看不到该目录。改为明确复制测试文件至隔离容器，保留 `--network none`、退出码和清理检查。

6. 最终本地整仓命令曾错误地把 `DATABASE_TYPE=mysql` 带入 SQLite 初始化场景，四项检查报 `schemaType=mysql / configuredType=sqlite`。这是本轮验证命令配置错误，已保存完整失败命令日志和失败 JSON；将 SQLite 功能检查与 MySQL 升级检查分开运行，与正式工作流保持一致，不改业务代码或断言。

7. 本地最小 Ubuntu 镜像缺少 jq 时，原管理脚本的两项真实检查会自动跳过。功能清单首项增加 jq 依赖门槛，统一环境明确准备该工具；文档补充依赖。最终冻结提交后重新运行，要求这两项实际通过，不把跳过作为验收。

8. Mac 完整 FXP 检查的两个大 UDP 数据报用例受到宿主 `message too long` 限制而失败；相同模块在固定 Go 版本的 Linux 环境完整通过。本轮没有放宽或删除这些用例，Mac 结果不作为 Linux 发布依据。
