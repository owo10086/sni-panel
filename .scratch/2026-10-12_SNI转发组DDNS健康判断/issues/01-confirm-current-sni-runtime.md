# 01：只凭有效的分流运行确认判断入口是否准备好

**What to build（交付内容）：** 主机型转发组能够分清“入口在线”和“分流确实准备好”。只有全部应运行规则的最新配置都得到有效运行确认，入口才能被新选中；离线、重启、旧报告和确认过期都有明确处理，页面说明实际阻塞原因。

**Blocked by（前置依赖）：** 无工单依赖；获得实施授权后可以开始。

**Status:** completed

**授权边界：** 2026-10-12 用户批准按五张方案拆分本地工单。本单尚未实施；ready-for-agent 表示拆分完成，不代表已获得代码实施、部署、推送或发布授权。

**依据与范围：** 《SNI 转发组 DDNS 健康判断调整》第四节及 A04、A19、A20、A21、A24。只覆盖主机型转发组的 SNI 入口；正常的规则停用、到期和限制继续决定哪些规则应运行，不要求被排除的规则运行。本单建立有效确认与失效处理，第 02 单接续完成各类观察时间和恢复资格，第 03 单再取消 SNI 落地目标检测门槛。

**验收标准：**

- [x] 经现有 Agent 报告流程确认全部应运行规则，而非只检查共享端口的第一条代表规则。缺少规则、分流未运行、Agent 不满足已有能力要求时，入口没有新的选择资格。
- [x] 核对实际生效的规则身份、域名、目标地址和端口、限速及连接数等已有要求。仅保存成功、命令下发成功、端口存在或旧配置运行，均不能当作最新配置已生效。
- [x] A04：修改落地地址、端口或限制后，旧报告不能放行尚未应用新配置的备用。当前入口失去有效准备状态时进入故障观察。
- [x] A19：国内检测关闭时，分别验证确认离线后重新上线和 Agent 重启。必须取得本次有效分流确认，断线前报告与晚到的旧报告都不能恢复资格；未被现有判断认定为离线的短暂通信波动不额外算作故障。
- [x] A20：有效分流确认采用现有 Agent 健康结果有效期，当前为 5 分钟。在线信号、Bing 检测和命令回执不能续期。确认失效立即停止新的选择资格；当前入口从失效时开始观察，到期自动检查并按现有条件切换，无合格备用则保留解析。
- [x] A21：入口明确确认运行内容未变化且面板有对应完整已核实内容时，可以续期，不要求重复上传完整配置。面板没有对应内容时必须等待完整确认；不得把没有内容的在线报告当作未变化确认。
- [x] A24：同组使用 443 和另一个端口，一个应运行的分流器停止时，不能凭另一个正常端口放行整个成员。覆盖非 443 端口，不新增端口网络检测。
- [x] 页面分别说明入口离线、分流未运行、配置未生效、等待重新确认和确认过期；相应中英文说明一致。
- [x] 自动检查经过真实报告处理流程，观察成员状态、选择结果及到期检查；不得只手工修改健康字段。检查时让本单尚未调整的其他健康条件满足，以便单独证明有效确认能正确阻止选择。
