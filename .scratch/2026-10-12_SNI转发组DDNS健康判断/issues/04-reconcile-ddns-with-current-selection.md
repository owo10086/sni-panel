# 04：新域名确实更新，失败或中途变化不虚报成功

**What to build（交付内容）：** 转发组的新域名得到真实更新，不因入口和地址未变而沿用旧域名的成功结论。解析服务失败或更新中途配置变化时，面板不虚报切换成功，并按现有重试、再次核对和调度流程继续处理；无合格入口时保留已有解析。

**Blocked by（前置依赖）：** 无工单依赖；获得实施授权后可以开始。可在现有健康条件全部满足的组上独立验证，不必等待 SNI 新判断完成。

**Status:** completed

**依据与范围：** 规格第六节及 A03、A14、A15。保留现有手动同步、排序、事件和已开启通知，不新增管理入口。涉及共享 DDNS 流程时，保留其他组原有行为。

**验收标准：**

- [x] A03：原入口和地址不变，只把组入口域名换成新域名，仍对新域名发出更新请求；旧域名的成功记录不能使本次更新被跳过。新建入口域名也按当前配置处理。
- [x] A15：解析服务明确失败时，不提交成功切换结果、不发送成功切换通知；显示真实失败原因，并按现有方式重试。重试成功后状态与实际请求结果一致。
- [x] A15：请求发出后、响应返回前，修改入口所需分流配置或组入口域名。按最新要求重新核对，旧配置不能取得资格，过时响应不能把面板写回旧的成功结论。
- [x] A15：解析服务可能已接受旧请求但面板再次核对未通过时，后续检查不能因旧成功记录跳过必要更新；有合格入口时最终按最新有效配置处理，无合格入口时明确显示不可用并遵守保留解析规则。
- [x] A14：所有入口故障时保留已有解析，明确显示不可用，不虚报恢复。主机流量超量排除继续使用原有特殊处理，不被普通健康故障的保留规则覆盖。
- [x] 无旧解析、无可用地址时沿用现有失败处理，不为完成更新而降低入口资格；系统 DDNS 未启用时保留已有说明，不把建议入口描述成已完成远端解析更新。
- [x] 检查手动同步、成员排序、事件记录和已开启的切换通知。事件与通知描述的成员、域名及结果与实际行为一致；仅换域名且入口未变时沿用已有通知含义。
- [x] 相关页面状态、中英文提示和检查随本单更新；通过观察解析请求、失败重试、最终状态和通知触发条件证明行为，不向真实收件人发送验收消息。

**独立检查示例：** 先完成旧域名的成功更新，保持成员和地址不变，只改新域名，记录新请求。再分别模拟一次服务失败以及响应期间修改配置，证明不会出现错误成功状态，并能继续按当前要求处理。

**完成依据：** 留下请求目标、请求值、返回结果、重试及最终面板状态。与第 03 单合并后的 SNI 完整流程在第 05 单再次验收。
