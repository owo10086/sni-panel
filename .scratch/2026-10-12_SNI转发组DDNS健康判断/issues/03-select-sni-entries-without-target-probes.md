# 03：SNI 入口正常时，不再被落地目标检测卡住

**What to build（交付内容）：** 主机型转发组中的 SNI 入口在有效分流确认、在线状态、已开启的国内检测及必要观察时间全部满足后，可以参与 DDNS。缺少、过期或失败的 SNI 落地目标检测不再卡住选用或单独触发整组切换；同组普通规则和原有限制继续生效。

**Blocked by（前置依赖）：** 02：故障与恢复按各自的观察时间推进。第 02 单已依赖第 01 单，无须重复列出。

**Status:** completed

**本轮完成记录：** 2026-10-12 用户调用 `implement` 并指定本需求目录后实施。下文授权边界保留开单时的历史说明；本轮只实施、隔离验收并本地提交，不含部署、推送和发布。实际结果见 [实施与验收记录](../实施与验收记录.md) 及 [代码复查记录](../代码复查记录.md)。

**授权边界：** 本单仅已完成拆分。必须另获实施授权且前置工单完成后才能修改代码；不包含部署、推送或发布。

**依据与范围：** 规格第二、三、七节及 A01、A02、A05、A06、A11、A16、A18。只调整主机型转发组内 SNI 部分的健康资格，不新增外部入口检测、检查机器、管理入口或配置开关。

**验收标准：**

- [x] A01：两台入口各承载 12 条共用 443 的 SNI 规则，全部配置已生效且其他条件满足。只提供代表规则目标结果或完全不提供逐条目标结果，两种情况均可选出入口并发出 DDNS 更新请求。
- [x] A02：分别提交 SNI 目标失败、过期和缺失结果；入口自身正常时，这些结果既不阻止 DDNS，也不单独触发整组切换。目标结果后续更新不能破坏第 02 单的入口故障与恢复计时。
- [x] A05：开启国内检测时，结果未知、失败、过期或不属于本次有效上线后的结果，不能当作通过；等待或故障处理沿用规格要求。
- [x] A06：关闭国内检测且其他条件满足时，不等待国内检测结果。关闭检测也不能跳过有效分流确认和应有恢复观察。
- [x] A11：同组混有普通规则时，普通规则目标检测继续影响成员健康；普通规则失败不能因为存在正常 SNI 而被放行，已完成有效恢复观察后也不多等一轮。
- [x] A16：分别检查规则停用、到期、用量额度、权限限制和恢复启用，只检查现有规则允许且应运行的分流内容，不重新放行已撤除业务。主机流量超量仍按原有退出与解析处理执行。
- [x] A18：普通转发组、转发链、单机端口转发和隧道中的 SNI 保持原有行为；检查各自已有关键场景，不扩大本次适用范围。
- [x] 页面不再把缺少 SNI 落地检测描述成阻止切换的“等待国内健康度检测”；普通规则仍按实际阻塞原因提示。单条业务目标检测及历史记录可以继续用于查看业务情况。
- [x] 相应中英文当前说明和旧检查中“每个 SNI 目标必须健康”的要求更新为本规格；不改写历史发布和验收记录。
- [x] 从真实 Agent 报告入口到成员状态、观察时间、DDNS 请求和选用结果走通，不靠直接修改一个健康字段证明完成。
