# 02：故障与恢复按各自的观察时间推进

**What to build（交付内容）：** 分流、国内检测和普通规则各自的故障与恢复观察不会相互清空或重复等待。入口首次启用、刚恢复后作为备用、自动切回和面板重启后重新取得状态，都按规格取得选择资格；到期能自动推进。

**Blocked by（前置依赖）：** 01：只凭有效的分流运行确认判断入口是否准备好。

**Status:** completed

**本轮完成记录：** 2026-10-12 用户调用 `implement` 并指定本需求目录后实施。下文授权边界保留开单时的历史说明；本轮只实施、隔离验收并本地提交，不含部署、推送和发布。实际结果见 [实施与验收记录](../实施与验收记录.md) 及 [代码复查记录](../代码复查记录.md)。

**授权边界：** 本单仅已完成拆分。必须另获实施授权且前置工单完成后才能修改代码；不包含部署、推送或发布。

**依据与范围：** 规格第五节，A07、A08、A09、A10、A11、A12、A13、A17、A22、A23、A25，并接续 A19、A20 的完整故障与恢复流程。使用第 01 单提供的有效分流确认；现有 Agent 已完成的有效观察继续计入。具体状态保存方式由本单设计并验证，不预先指定保存位置。

**验收标准：**

- [x] A07：分流停止期间持续收到正常 Bing 报告，故障时间不会被清空；按面板故障时间达到切换条件后，可以切到合格备用。
- [x] A09：国内检测或其他保留条件已完成故障观察时，分流刚出现故障不能把已完成的观察重新计算，也不能因另一项等待报告而掩盖已经成立的故障。
- [x] A08：分流重新取得有效运行确认后才开始本轮恢复观察，不能借用 Bing 一直正常的时间提前取得资格。
- [x] A10、A11：国内检测或普通规则已经按原有方式完成有效恢复观察，SNI 始终正常时不额外再等一轮；混合组中普通规则失败仍影响组健康。
- [x] A22：确属首次启用且没有此前分流故障或确认失效记录时，首次有效确认全部应运行配置、其他条件满足即可选用，不额外等待分流恢复时间。
- [x] A23：分别开启和关闭自动切回，当前入口已到故障切换时间但备用分流恢复未满观察时间时，都不能提前选中该备用。有其他合格成员则按优先顺序选择，否则保留解析并显示等待恢复；恢复到期自动重新判断。
- [x] A13：当前备用正常时，开启自动切回才主动回到更高优先级合格入口。当前入口故障时，即使关闭自动切回，也允许选择已完成恢复观察的更高优先级入口。
- [x] A25：恢复观察期间再次故障或有效确认过期，本轮分流恢复时间清零；下次有效确认后重新累计，不拼接两段正常时间，其他来源已完成的有效观察不重复等待。
- [x] A12：使用非默认故障及恢复时间，分别在等待中调长、调短设置。按更新后的面板设置判断并重新安排到期检查；已到期的条件及时推进，无须等待下一次偶然上报。
- [x] A17：面板重启或状态重新建立后，无法证明此前状态时，不能套用首次启用例外；重新确认后完成恢复观察。有完整有效依据的已完成观察不重复等待。
- [x] A19、A20：离线重连、Agent 重启或分流确认失效后，重新确认正常仍须完成恢复观察；报告缺失期间不计作正常时间。报告有效期与面板故障、恢复观察时间分别处理。
- [x] 页面与中英文说明能区分已经故障、等待重新确认和恢复观察未完成。检查通过真实报告处理和调度流程推进，不用手改时间或健康字段代替整个流程。

**独立检查示例：** 将恢复时间设为 120 秒，A 已满足故障切换条件，B 仅恢复 5 秒。验证 B 不被选中，C 合格时可选 C；没有 C 时保留解析，B 满 120 秒后自动重新判断。再在恢复中插入一次分流停止，证明计时重新开始。

**完成依据：** 留下各来源的状态变化、观察起止、设置变更以及实际选择结果。本单检查可提供有效落地检测以满足尚未取消的原有门槛，第 03 单再证明缺少 SNI 落地检测也能走通。
