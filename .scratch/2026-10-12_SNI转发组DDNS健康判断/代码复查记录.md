## Standards

标准轴发现的五类问题均已修复并复验：

| 发现 | 修复与复验 |
| --- | --- |
| v2 允许 Agent 时钟不准，不能直接把其时间当面板时间，也不能把首次到达的旧包误认作新包。 | 在既有配置回执中使用本次独有的确认值；确认后再建立时钟依据并接受完整运行状态。慢 10 分钟、快 10 分钟、未知时钟、时钟回拨均通过真实加密流程。 |
| 心跳合并处理提前返回时漏掉 Agent 重启。 | 生命周期核对移至提前返回之前，正式 `coalesced-restart` 回归通过。 |
| 删除规则仍在旧分流表中；数据库清理副本后检查依据丢失。 | 同时检查应撤除副本和完整报告中已经不存在、停用或域名不符的规则身份，核对范围允许合法其他资源共用端口。真实删除、正确撤除、数据库已清理、旧表再次到达的 `deleted-domain` 回归通过。原独立复现也已由标准审查者复验通过。 |
| 旧心跳检查通过后暂停，新进程触发失效，旧请求恢复后又写回成功确认。 | 写入前再次核对生命周期边界与退休进程；正式 `concurrent-restart` 回归通过。 |
| 面板重启后未知时钟的旧 PID 先到，错误地把真正当前 PID 标为退休。 | 未获得本次确认值的回执前不变更已知进程身份、不退休当前进程。标准审查者以两个独立进程共享数据库实测旧 PID 先到、真正当前 PID 随后确认，结果通过。 |

原删除域名发现曾在“等待删除”阶段修复后被再次打开：独立复现证明数据库实际清理后仍有漏洞。本轮继续修复，并以真实清理断言和旧表再次到达补验后关闭，没有把中间的局部通过当作最终通过。

标准审查者最终确认该 P2 关闭。其他资源合法共用分流器不会仅因“不属于当前组”而被拒绝，这一项完成了实现核对；额外尝试创建共享案例时，现有创建接口先因端口占用拒绝该组合，因此不声称完成了这项额外创建验收。

## Spec

规格轴最终结论为：**未发现仍需阻止交付的规格问题；此前报告的问题均已关闭。** 按独立审查的发现归纳为以下七类：

| 发现 | 修复与复验 |
| --- | --- |
| 应用失败清空成功确认后一直等待，不开始故障计时。 | 从真实中断时间开始观察，失败回执会安排重新判断。`apply-failure` 自动切换及恢复回归通过。 |
| 运行表短暂缺一条后立刻补齐，队列合并吞掉恢复中断。 | 报告之间检查当前仍应运行的规则；保留中断，合法停用或删除按当前应运行范围处理。`brief-missing`、`deleted-domain` 通过。 |
| 离线前普通目标检测晚到，被当作混合组的新恢复结果。 | 过滤早于本次失效边界的报告；该范围的检测记录使用面板接收时间。`mixed` 同时证明旧包被拒绝、新报告仍能恢复。 |
| v2 未知时钟的旧包可能被抬成当前完整确认。 | 本次独有回执、完整表、可信时钟依据共同成立后才接受；未知时钟或尚未完成本次确认的普通、国内检测暂不采用。4 个 `clockless-*` 回归通过。 |
| 状态重新建立后，已有当前成员缺确认无限等待；普通及国内缺报告期限随评估滑动。 | 已有观察的分流缺失开始故障观察；缺普通及国内报告使用固定等待起点。跨进程当前 B 只在线不确认，以及两个固定等待期限回归通过。 |
| DDNS 响应期间当前入口短暂故障又恢复，未完成恢复却宣布成功。 | 提交前对同一当前入口也核对恢复已完成。`ddns-current` 通过，旧成功时间不被更新。 |
| DDNS 切回请求期间关闭自动切回，或改变影响选择的设置，旧请求仍提交。 | 提交前核对最新切回开关、故障/恢复时间、国内检测设置和启用成员顺序；变化时拒绝旧提交并重新同步。`ddns-failback-disabled` 通过，保留健康 B。 |

规格审查者独立运行了应用失败、短暂缺规则、删除域名、四类时钟、跨进程当前成员不确认，以及两类 DDNS 竞态的聚焦复验。通知仍在成功核对和提交之后产生；本地通知回归证明失败没有成功通知，重试成功后事件和通知符合实际结果。没有发现增加外部入口检测、检测开关或原生客户端范围。
