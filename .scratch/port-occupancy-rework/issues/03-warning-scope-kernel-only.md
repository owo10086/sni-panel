# 03 — 占用警告收窄到内核转发，未核实不再有界面出口

**What to build:** 规则上的端口占用警告只对内核转发（iptables / nftables）规则呈现；用户态转发不再产生占用警告，其端口问题由既有的红色 bind 失败报错承担。数据缺失、采集失败、过期时，规则上不出现任何标记。

**Blocked by:** 01 — Agent 只上报规则入口端口的占用，删除全量快照与截断机制

**Status:** ready-for-agent

## 警告范围

- [ ] 占用警告只对 `forwardType` 为 `iptables` 或 `nftables` 的规则产生
- [ ] 用户态转发（gost / forwardx / nginx / realm / socat / FXP）的规则不再产生占用警告
- [ ] 用户态规则报告未就绪且其入口端口上存在外部监听时，占用者名字仍要出现在**规则级错误**里（红色运行失败），这条路径不受本工单影响

## 未核实不呈现

- [ ] 主机离线、Agent 未上报、采集失败、数据过期、该端口不在覆盖集合里时，规则上**不出现图标、不出现文字**
- [ ] **数据已不新鲜时，规则接口不再返回警告缓存里那条上一次的有效结论**——警告缓存只在收到有效上报时才刷新，上报失效时里面留着的是上一次的结论
- [ ] 改的位置很具体：现状**已经**在规则接口里判过新鲜度，只是把过期条目**降级成「未经核实」**再返回。未经核实没有界面出口之后，那条降级分支要改成**丢弃**，不能只把降级删掉、让原条目直接返回——那才会在卡片上挂出一条无人再核实的旧警告
- [ ] 界面隐藏**不等于**清空提醒状态：本工单只管**规则接口返回什么**，提醒状态那一侧要保留上一次的有效占用（见工单 04）。两者是同一份事实的两种存活期，不得用同一份逻辑处理，也不得为了「一致」把其中一侧改成另一侧的行为
- [ ] 不得因此把「未核实」呈现为「端口空闲」或「一切正常」的肯定结论——做法是不出现任何结论，而不是出现一个肯定结论
- [ ] 移除既有的灰色「主机端口信息未经核实」标记及其提示文案

## 警告仍是独立标记

- [ ] 不得仅凭监听记录把 `isRunning` 置假或把规则标成运行失败；内核转发规则在有警告时仍显示为运行中
- [ ] 警告与运行状态并列呈现，在探测新鲜且可达、卡片显示为绿色低延迟时**依然可见**
- [ ] 警告内容只陈述可核实的事实：存在监听、绑定地址、传输协议、管理员可见进程名、采集时刻与最近核实时间
- [ ] **不得断言原监听进程会失去流量**
- [ ] 管理员可见进程名，普通用户可见「该端口存在占用」但不含进程名；两份内容在服务端分别构造，不依赖事后删除字段或页面隐藏
- [ ] 占用消失后警告自动消失，不需要手工清理

## 覆盖面

- [ ] 结论对本功能上线前已存在的规则同样生效，不需要任何人重建规则

## 测试

- [ ] 内核转发规则的入口端口上存在外部监听时，**运行状态保持为运行中**且规则上带出占用警告——两件事都要断言
- [ ] 探测新鲜且可达时警告依然出现（防止被单值状态枚举的提前返回吞掉）
- [ ] 用户态规则的入口端口上存在外部监听时**不产生占用警告**；该规则报告未就绪时其运行失败信息里含占用者名字
- [ ] 主机未上报、采集失败、数据过期、端口不在覆盖集合里时规则上**不出现任何标记**
- [ ] 数据已不新鲜时，规则接口不再返回缓存里那条上一次的有效警告
- [ ] 同一入口端口上的多条 SNI 分流规则不因分流器自身的监听而产生警告（ADR-0002 回归用例）
- [ ] 普通用户读到的结论不含进程名
