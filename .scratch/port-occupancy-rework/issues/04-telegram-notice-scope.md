# 04 — 占用提醒的范围与边沿

**What to build:** 端口占用的 Telegram 提醒范围随警告一起收窄到内核转发规则；保留占用出现、占用者变化、占用解除三个边沿，保留冷却窗口，并保证观测中断不会被当成占用解除。

**Blocked by:** 03 — 占用警告收窄到内核转发，未核实不再有界面出口

**Status:** ready-for-agent

## 触发范围

- [ ] 只有内核转发规则的端口占用会触发提醒
- [ ] 沿用规则上既有的提醒开关，不新增配置项
- [ ] 触发点挂在占用状态的变化检测上（收到有效上报时、规则集变动后），不挂在规则列表的读取上

## 边沿

- [ ] **状态键稳定，占用者身份是它的值而不是它的一部分**：键取规则 + 入口主机 + 端口 + 传输协议；占用者身份（进程名、绑定地址、受管实例标识）作为该键的值保存，判定靠比较同一个键的前后两个值
- [ ] **注意这一条与「未核实不触发转移」在现有实现里都已经成立**（键已是规则+主机+端口+协议、占用者已是值、判定入口已有「未核实直接返回」的短路）。列在这里是**要求保持不变**，不是待修的缺陷——不要为了「重构一下」去动这段本来正确的代码
- [ ] 真正要改的只有范围：把触发面收窄到内核转发规则
- [ ] 三种转移各自触发：无 → 有（占用出现）、有 → 另一个有（占用者换人）、有 → 无（占用解除）
- [ ] 占用者换人后旧值被接替，不得留下一条新旧并存、永远不会被再次访问的记录——把占用者塞进键里正是会造成这个结果
- [ ] 同一个持续存在的占用只提醒一次
- [ ] 占用消失时发出解除提醒
- [ ] **未核实不是占用已解除**：数据缺失、采集失败、过期、端口不在覆盖集合里时绝不发送解除提醒；解除只能由一份明确显示占用已经不在的有效上报触发
- [ ] 这些处境下判定**不产生任何转移**，上一次的有效占用原样保留——与界面相反，界面此时什么都不显示，提醒状态却要记得占用还在
- [ ] 既有的冷却窗口保留在最外层，与变化触发各司其职
- [ ] 状态记在内存，面板重启会重发一次，这是已知且接受的行为
- [ ] 规则被删除或停用时，它在提醒状态里的条目要跟着清掉——现状只靠容量上限淘汰，一条删掉的规则会留一个再也不会被访问的条目

## 措辞

- [ ] 消息内容与「运行异常」明确区分：这是一条警告，措辞不得暗示规则已经停止工作

## 测试

- [ ] 同一占用持续存在只发一次
- [ ] 占用者换人算一次新变化并再发一次
- [ ] 占用消失发出解除提醒
- [ ] 数据缺失 / 采集失败 / 过期 / 端口不在覆盖集合里时**不发解除提醒**，且上一次的占用状态被保留（下一份有效上报仍显示占用时不重复提醒，显示已不在时才发解除）
- [ ] 占用者由 A 换成 B 再消失时，解除提醒发且只发一次，不受旧占用者残留状态影响
- [ ] 冷却窗口仍在最外层生效
- [ ] 用户态规则的端口占用不触发任何提醒
