# 01 — Agent 端口占用快照的上报、缓存与占用判定

> 本工单已作废；端口占用相关实现以 `.scratch/port-occupancy-rework/spec.md` 和其下的新工单为准。

**What to build:** Agent 把它本来就在采集的主机监听情况整理成端口占用快照，随心跳上报；面板按主机缓存，并据此提供一处独立的占用判定，供后续所有工单调用。本工单**不改变任何用户可见行为**——不拦截创建、不改规则状态、不发提醒。它只是把数据和判定准备好。

**Blocked by:** None — can start immediately

**Status:** wontfix

## 采集与上报

- [ ] Agent 复用现有监听采集结果，提供端口、传输协议、绑定地址、占用进程名和采集时刻；不新增采集动作，不夹带原始命令输出行
- [ ] 快照是心跳中的独立字段并有自己的签名：只有监听变化才重传完整快照，规则状态变化不触发快照重传，反之亦然；快照有自己的强制上报触发，不依赖规则状态那一路
- [ ] 每次心跳都携带轻量的快照签名与**本次采集是否成功**；完整快照只在内容变化、或面板表示自己没有缓存时才传
- [ ] 上报内容有明确体积上限，且**快照能表达自身是否完整**；被截断时优先裁掉最不可能被问到的条目，不做任意截断

## 面板缓存与核实时间

- [ ] 面板按主机缓存快照，沿用现有有界缓存约定（遍历同时写入时使用不改变键位置的写入函数）
- [ ] 面板区分「最近核实时间」与「采集时刻」两个值：前者决定是否降级，后者说明内容取自何时
- [ ] 采集成功且签名与缓存一致时刷新最近核实时间、缓存内容不变；签名不一致时要求补传完整快照；**采集失败时两者都不刷新**——心跳到达本身不构成核实
- [ ] 最近核实时间沿用仓库既有的「新鲜期 + 未来偏移容忍值」约定；时间落在未来且超出容忍值时按不可信处理，不呈现为刚刚核实

## 占用判定（供后续工单复用的唯一实现）

- [ ] 判定是一处独立实现，只依赖快照、主机、端口、传输协议、执行方式与受管端口集合，不依赖请求上下文、不碰数据库连接
- [ ] 判定区分 TCP 与 UDP、IPv4 与 IPv6、以及不同绑定地址；只陈述客观事实（谁在监听、绑在哪、什么协议、是否受管），把「算不算冲突」留给调用方按执行方式决定
- [ ] **受管占用不等于端口可用**：只有当新规则要用的确实就是那个已存在的监听本身时才算可复用；其余受管占用按绑定冲突处理，进程名或运行时类型相同不足以证明可复用
- [ ] 快照缺失、采集失败、过期或该端口落在截断范围外时，判定返回**未经核实**，绝不返回「空闲」
- [ ] 判定同时产出**按角色分别构造**的两份占用说明：管理员那份含进程名，普通用户那份从构造时就不含

## 不做

- [ ] 本工单不改动任何规则的运行状态字段、不改动创建校验结论、不发送任何提醒；已建成规则的状态、探测结果与卡片颜色均不因快照上报而变化

## 测试

- [ ] Agent 侧：绑定地址与进程名保留、TCP/UDP 分开、IPv4 与 IPv6 分别识别、采集时刻带上、体积上限生效且完整性标志正确
- [ ] Agent 侧：快照签名只随监听变化翻转，规则状态变化不影响它，反之亦然
- [ ] 心跳侧：签名一致时刷新核实时间而不重传内容、签名不一致时补传完整快照、采集失败时核实时间不前进
- [ ] 判定侧：受管但不可复用的监听按冲突处理、截断范围外的端口返回未经核实、两份角色说明的进程名差异
