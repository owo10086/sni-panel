# 02 — 持续占用检测与规则上的独立警告标记

> 本工单已作废；端口占用相关实现以 `.scratch/port-occupancy-rework/spec.md` 和其下的新工单为准。

**What to build:** 面板用每次有效快照与现有启用中的规则比对，发现入口端口上存在不可复用的外部监听时，在规则上带出一个与运行状态并列的独立警告，并在占用出现、变更、消失时发出提醒。警告**不改变规则运行状态**。本工单天然覆盖本功能上线前就已存在的规则，不需要任何人重建。

**Blocked by:** 01 — Agent 端口占用快照的上报、缓存与占用判定

**Status:** wontfix

## 变化检测的位置

- [ ] 变化检测发生在面板**收到一份有效快照**时（心跳路径），以及规则创建、启用、修改之后（规则集变了，同一份快照的结论也变了）
- [ ] 规则列表的读取路径只负责**展示**已算出的结论，不承担变化检测；无人打开列表时占用照样被发现、提醒照样发出
- [ ] 判定复用工单 01 建立的那一处实现，不新写一份

## 警告是独立标记

- [ ] 不得仅凭监听记录把 `isRunning` 置假或把规则标成运行失败；内核转发规则在有警告时仍显示为运行中
- [ ] 警告与运行状态并列呈现，在探测新鲜且可达、卡片显示为绿色低延迟时**依然可见**，不被运行状态或探测结果掩盖
- [ ] 警告内容只陈述可核实的事实：存在监听、绑定地址、传输协议、采集时刻与最近核实时间；不断言原监听进程会失去流量
- [ ] 管理员可见进程名，普通用户可见「该端口存在占用」但不含进程名；两份内容在服务端分别构造，不依赖事后删除字段或页面隐藏
- [ ] 占用消失后警告在后续心跳中自动消失，不需要人工操作
- [ ] 快照缺失、采集失败、过期或该端口被截断时，规则上标明**主机端口信息未经核实**，不呈现为端口空闲、也不呈现为存在占用

## Telegram 提醒

- [ ] 新增按状态变化触发的提醒路径，不复用现有「运行状态由真变假」的条件——仍在工作的内核转发规则永远不满足该条件
- [ ] 触发状态键包含规则、入口主机、端口、传输协议、占用进程名与绑定地址；占用者由一个进程换成另一个进程算一次新的变化，不被静默吞掉
- [ ] 同一占用持续存在时不重复发送
- [ ] 占用消失时发出解除提醒，且**只能由一份明确显示占用不在的有效快照触发**；快照缺失、采集失败、过期或截断一律不得触发解除提醒
- [ ] 现有的提醒冷却窗口保留在最外层，占用者反复起停时不产生提醒风暴
- [ ] 提醒内容与「运行异常」明确区分，措辞不暗示规则已停止工作；沿用规则上既有的提醒开关，不新增开关
- [ ] 变化状态记在内存时，面板重启后可能重发一次，此行为明确记录，不按缺陷处理

## 测试

- [ ] 规则路由测试显式断言：有占用时**运行状态仍为运行中且警告同时出现**（两条都断言，缺一不可）
- [ ] 规则路由测试断言：探测新鲜且可达时警告依然出现
- [ ] 规则路由测试断言：普通用户拿到警告但响应中不含进程名
- [ ] 心跳测试断言：无人读取规则列表时，收到快照即完成变化检测
- [ ] 提醒判定测试覆盖：持续占用只发一次、占用者换人算新变化、有效快照显示占用消失才发解除、快照缺失或过期不发解除、冷却窗口仍然生效
