# 05 — 用户态转发绑定冲突与同一监听复用

> 本工单已作废；端口占用相关实现以 `.scratch/port-occupancy-rework/spec.md` 和其下的新工单为准。

**What to build:** 创建单主机用户态转发规则时，端口输入框和提交接口按实际监听地址判断绑定冲突。已有监听阻止新运行时启动时拒绝创建；新规则确实复用同一个受管监听时保持可用，包括现有 SNI 分流规则共用入口端口的情况。

**Blocked by:** 03 — 单主机内核转发创建校验：占用警告与确认

**Status:** wontfix

- [ ] 用户态执行方式的端口校验与创建使用同一占用判断；切换执行方式后重新校验，不将内核转发的可确认警告误当作用户态可用
- [ ] 用户态运行时监听所有地址时，已有进程即使只监听回环地址，同协议同端口的绑定冲突仍导致创建失败；结合实际绑定地址判断不同网卡和 IPv4、IPv6 的占用
- [ ] 仅在新规则确实复用目标受管运行时的同一个监听时放行；其他受管运行时占用同端口按绑定冲突处理，进程名称相同不足以证明监听可复用
- [ ] 单主机已有 SNI 分流规则的同入口端口复用能力保持正常；分流器出口监听和隧道监听只在实际复用同一监听时免于误报
- [ ] 普通用户能收到端口不可用结果，但校验响应、创建错误和页面均不泄露占用进程名
- [ ] 规则路由和 Agent 现有测试覆盖绑定地址、协议区分、受管监听身份及同端口 SNI 分流规则
