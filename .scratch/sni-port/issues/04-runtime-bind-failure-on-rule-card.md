# 04 — 受管运行时端口绑定失败时显示规则原因

> 本工单已作废；端口占用相关实现以 `.scratch/port-occupancy-rework/spec.md` 和其下的新工单为准。

**What to build:** 用户态受管运行时因端口被占而无法启动时，规则卡片显示端口冲突原因；占用解除后，规则随正常状态同步恢复，管理员无需重新创建规则。

**Blocked by:** 01 — Agent 端口占用快照的上报、缓存与占用判定

> 与 02、03 相互独立，可并行推进。依赖 01 只是为了共用占用说明的角色构造与措辞约定。

**Status:** wontfix

- [ ] Agent 将转发规则运行时的地址占用错误关联到对应规则，并把失败原因传给面板；无法获得进程名时仍显示端口占用，不伪造占用者
- [ ] 规则卡片显示受影响端口和可取得的原因；管理员可见占用进程名，普通用户只见端口占用信息，所有规则查询响应遵守相同权限限制，进程名在服务端构造返回值时即剔除
- [ ] 占用消失后，既有状态同步重新启动规则，成功运行时清除旧错误，无需管理员重建规则
- [ ] 本工单只覆盖**用户态执行方式**。内核转发没有 bind 动作，也就没有 bind 失败，其占用问题由工单 02 的持续检测负责；两者呈现方式不同——本工单是运行失败（规则确实没在工作），02 是独立警告（规则仍在工作），不得用同一字段表达
- [ ] 测试覆盖绑定失败、进程名不可取得、不同角色的卡片内容和占用解除后的恢复
