# 03 — 单主机内核转发创建校验：占用警告与确认

> 本工单已作废；端口占用相关实现以 `.scratch/port-occupancy-rework/spec.md` 和其下的新工单为准。

**What to build:** 创建单主机内核转发规则时，端口输入框校验与提交都依据端口占用判定。端口上存在不可复用的监听时给出警告，显式确认后仍可创建；缺少可靠依据时说明主机端口信息未经核实，并允许沿用数据库校验结果。

**Blocked by:** 02 — 持续占用检测与规则上的独立警告标记

> 02 不是代码层面的硬依赖，而是**交付顺序**：02 先落地，存量规则立刻获得保护，且警告的措辞边界、角色脱敏与「未经核实」语义都在那里定型，本工单直接复用同一套呈现，不重新发明。

**Status:** wontfix

## 校验结论

- [ ] 校验请求包含实际执行方式；选择内核转发且端口上存在不可复用的监听时，端口输入框显示警告
- [ ] 警告不等于不可用：不得把警告塞进既有的「已占用」布尔结论里，否则界面会把可以继续的情况显示成不可用
- [ ] 提交时默认阻止未经确认的请求；确认以一个显式入参表达，默认不确认
- [ ] 即使外部进程仅监听回环地址，内核转发也显示占用警告并要求确认；警告只陈述可核实的事实（存在监听、绑定地址、协议、采集时刻，管理员另可见进程名）并说明该端口的入站流量将由本规则接管，不断言原监听进程会失去流量
- [ ] 端口输入框校验与提交校验调用工单 01 的同一处判定，对同一端口给出完全一致的结论，不出现「输入框说可用、提交说占用」

## 权限与降级

- [ ] 普通用户和管理员都可以确认警告；普通用户的校验响应与界面不含占用进程名，两份内容在服务端分别构造
- [ ] 快照缺失、采集失败、过期或该端口被截断时，页面提示主机端口信息未经核实，允许按现有数据库校验结果创建规则，不把缺失依据呈现为端口空闲

## 测试

- [ ] 规则路由测试覆盖：警告出现、未确认被拒、确认后放行、回环占用同样警告、两处校验结论一致
- [ ] 规则路由测试覆盖：普通用户可确认但看不到进程名、快照缺失与过期时的降级路径
