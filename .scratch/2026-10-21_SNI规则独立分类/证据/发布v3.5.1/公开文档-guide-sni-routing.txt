data-v-cb09c906><!--[--><!--]--><main class="main" data-v-cb09c906><div style="position:relative;" class="vp-doc _sni-panel_guide_sni-routing" data-v-cb09c906><div><h1 id="sni-分流" tabindex="-1">SNI 分流 <a class="header-anchor" href="#sni-分流" aria-label="Permalink to &quot;SNI 分流&quot;">​</a></h1><p><a href="./sni-routing.en">English guide</a></p><p>SNI 分流让多条 TCP 转发规则共用同一个入口端口，并根据 TLS ClientHello 中的完整 SNI 域名选择转发目标。转发链的入口分流器按域名选择该规则所属转发链的下一跳，出口分流器再按域名选择落地机。因此，不同转发链可以共用同一台入口主机的同一个入口端口，每条转发链仍可以配置多台落地机。</p><p>转发链、单机端口转发和直接隧道的按规则限速、连接数限制和流量统计统一由出口分流器执行。入口组可以包含多台并行接收连接的主机，在入口分别执行限制会使总额度随入口数量增加；出口是连接到达落地机前的唯一必经点。入口分流器产生的流量数据会被忽略，出口继续提供唯一计量来源。</p><p>端口资源也可以引用入口组，由每台入口直接按域名连接规则保存的落地机。此方式没有额外公共出口，限制由每台入口分别执行，用量汇总到同一原规则；步骤见文末<a href="#端口资源通过入口组直接分流">端口资源通过入口组直接分流</a>。它与上文转发链的出口集中计量是两种不同路径。</p><p>管理员管理的对象始终是 <strong>SNI 分流规则</strong>。分流器内部持有的分流表由面板根据启用的规则生成，属于运行时派生数据，没有单独的创建页面，统一由面板维护。每台入口主机的入口分流表只包含引用该主机和入口端口的规则，路由目标为各条转发链自己的下一跳；出口分流表的路由目标为各条规则保存的落地机地址和端口。</p><h2 id="使用条件" tabindex="-1">使用条件 <a class="header-anchor" href="#使用条件" aria-label="Permalink to &quot;使用条件&quot;">​</a></h2><p>开始配置前，先确认以下条件：</p><ol><li>出口主机的 Agent 版本为 <code>2.2.195</code> 或更高版本，并且状态在线。使用转发链或主机型转发组时，所有启用入口主机也须满足同一最低版本要求。版本未上报或无法识别时须先修正。</li><li>流量能够到达入口，转发链入口能够访问下一跳，出口主机能够访问每条规则填写的落地机地址和端口。</li><li>承载资源已经在「链路管理」中创建并启用。SNI 分流支持主机型转发组、转发链、端口转发资源（单机或引用入口组）和直接隧道。</li><li>端口转发资源可以直接选一台主机，或引用由主机成员组成的入口组；每台启用入口都需具备独立分流器能力和相应权限。</li><li>直接隧道使用单一出口主机，未启用出口组、负载均衡或额外出口节点。</li><li>创建、复制、导入或修改配置需要管理员权限。管理员可以为所选普通用户配置；采用上游管理员托管权限：普通归属用户只能查看管理员代建或具有限速、流量额度、有效期的规则，不能编辑、启停、删除、排序或重置统计。系统生成的子规则由根规则统一管理。</li></ol><p>转发链入口 Agent 版本不足、未上报版本或版本格式无法识别时，入口版本检查视为未满足要求，相关规则显示入口版本异常并停止运行。创建、修改、启用和批量导入 SNI 分流规则时均会检查入口版本，错误提示包含所需最低版本。</p><h2 id="创建承载资源" tabindex="-1">创建承载资源 <a class="header-anchor" href="#创建承载资源" aria-label="Permalink to &quot;创建承载资源&quot;">​</a></h2><p>首次配置可以使用单机端口转发完成最短验证：</p><ol><li>按照<a href="./agent">安装 Agent</a>和<a href="./hosts">主机管理</a>将一台主机接入面板，并确认主机在线。</li><li>进入「链路管理」，创建端口转发资源。</li><li>资源类型选择主机，只添加上述在线主机，并启用该资源。</li><li>确认主机允许使用计划中的入口端口，并且目标服务可从该主机访问。</li></ol><p>生产链路也可以使用转发链或单出口隧道。转发链至少需要入口主机和出口主机，也可以引用入口组。所有相关入口主机均运行入口分流器，最后一台启用的主机运行出口分流器。两跳转发链的入口将连接送往出口分流器；三跳及更长转发链的入口将连接送往下一台中转主机的监听端口。转发方式只影响中转成员，两跳转发链的入口和出口均由分流器承担。</p><p>单出口隧道需要先配置入口主机、单一出口主机和隧道协议，并保持出口组与负载均衡关闭。隧道入口维持原有传输方式，分流器仍位于出口。单机端口转发只有一台主机，由该主机的分流器监听入口端口并选择落地机。上述承载资源使用相同的 SNI 规则字段，切换承载方式时可以保留域名和目标，并重新检查新资源的端口与版本要求。</p><h2 id="使用主机型转发组" tabindex="-1">使用主机型转发组 <a class="header-anchor" href="#使用主机型转发组" aria-label="Permalink to &quot;使用主机型转发组&quot;">​</a></h2><p>例如两台入口 A、B 为 <code>api.example.com</code> 和 <code>files.example.com</code> 提供服务，两条规则共用 <code>18443</code>，分别指向不同落地机。</p><ol><li>在「链路管理」保存一个<strong>主机型转发组</strong>，添加 A、B，设置成员优先顺序、故障观察时间、恢复时间和是否自动切回。确认每台启用成员的 Agent 至少为 <code>2.2.195</code>。业务连接仍需要入口能够访问落地机。</li><li>在「转发规则」选择该组，打开 SNI 开关，填写域名、入口端口和落地机。转发组中选择的转发工具不影响 SNI：每台启用成员在业务端口直接分流到落地机，没有额外公共出口。</li><li>等待各台成员确认最新配置。保存成功只表示面板已保存；离线或配置应用失败成员显示待同步或失败原因，准备完成前不能被选作新的当前入口。修改目标、限速或连接数后，旧配置仍有相同域名也不算就绪。</li><li>SNI 入口的切换资格取决于 Agent 在线、所有应运行端口和域名的当前分流配置已生效，以及已开启的国内健康检测通过。缺少、失败或过期的 SNI 落地目标检测不阻止 DDNS，也不单独触发整组切换。例如一个业务目标停机，但 A 的分流和 Bing 检测仍正常时，组继续使用 A。混有普通规则时，普通规则仍须通过原有目标检测。</li><li>有入口域名时继续使用该组的 DDNS。业务域名可通过 CNAME 指向组入口域名，例如 <code>api.example.com → entry.example.com</code>；客户端 TLS 握手仍须携带 <code>api.example.com</code>，分流按业务域名匹配。更换组入口域名后，即使入口和地址没有变化，也会更新新域名。DDNS 更新失败时页面保留失败原因，不宣布切换成功，并按现有方式重试。</li></ol><p>分流运行确认有效期为 <strong>5 分钟</strong>。入口明确确认已核实的运行内容未变化时可以续期；只有在线信号、Bing 检测或命令回执不能续期。确认离线、Agent 重启或确认过期后，要重新取得当前分流运行确认。面板重启后缺少完整依据时，也要重新确认并完成恢复观察。</p><p>故障与恢复观察读取组内设置，各项分别计时。Bing 持续正常不能清掉分流故障，也不能让刚恢复的分流提前完成恢复。首次启用取得有效确认后不额外等待分流恢复；曾故障的备用入口必须完成恢复观察，当前入口已经故障也不能跳过。例如恢复设为 120 秒，B 才恢复 5 秒而 C 已合格时，选择 C；没有合格入口则保留现有解析，等待到期后自动再判断。自动切回开启时回到合格的高优先级入口，关闭时保留当前健康备用；当前入口故障时仍可选择已恢复的高优先级入口。页面分别显示分流未运行、配置未生效、确认过期或恢复观察等实际原因。</p><p>DNS 缓存可能让部分客户端继续访问旧入口。已建立连接不会自动迁移；旧入口仍可达时可以继续服务，断开的连接需要重连。备用机提前准备配置，不能消除 DNS 缓存造成的等待。</p><p><strong>限制和用量：</strong> 限速与最大连接数由每台入口分别执行。例如每条规则限速 10 Mbps，A、B 同时服务时各自执行 10 Mbps，不能当作全组严格共用 10 Mbps。每台最终分流器按实际匹配到的成员规则报告流量，面板去重并汇总到根规则和归属用户。切换前后、旧新入口同时存在的真实用量都计入；重新同步、启停和提高额度不清零累计用量。达量或到期只撤掉对应域名，其他共用端口业务继续服务。</p><p><strong>保存和成员变更：</strong> 创建、修改、启停、换组及成员更换整体保存。面板内端口冲突、域名重复、权限或版本异常时拒绝保存；写入中途失败恢复原设置和原成员规则。保存后的机器离线或应用失败另显示待同步，不会把旧配置当作新配置完成。</p><p><strong>撤除失败的保护：</strong> 正常热更新只撤掉对应域名，其他域名的连接继续使用。如果更新失败，旧分流表仍包含已停用、删除、达量、到期或失去权限的域名，面板下发的保护会停止该入口这个端口的旧分流器，并清除旧配置和恢复记录，防止重启后重新放行。这种失败会暂时影响该入口共享端口上的其他域名；页面显示失败或待同步，补齐配置后再恢复准备资格。保护沿用已有 Agent 下发通道，最低版本要求仍为 <code>2.2.195</code>。</p><p>如果当前分流表已经安全，只是删除第一条规则后留下了包含旧域名的恢复文件，保护仅清理这份旧文件，正常监听和其他域名的连接继续保留。</p><p>修改落地地址或端口后，原来的检测记录保留作历史数据，入口须确认新分流配置生效，取得切换资格不再等待新目标连接检测。解析服务返回切换结果时，还会重新确认候选入口和组域名仍符合当前保存的设置；在等待解析响应期间又保存了新配置，不会把旧判断当成切换成功，并会重新安排更新。</p><p><strong>复制和批量配置：</strong> 批量导入选择已保存的主机型转发组，沿用 <code>规则名#SNI域名#目标地址#目标端口</code>，统一指定入口端口。每项独立保存，失败项列出原因并保留供重试，成功项保持。JSON 导出保留承载资源说明、业务域名、端口、落地机、限速、连接数、额度和到期时间；重新导入时确认目标资源，复制或导入到同一入口的重复域名仍会拒绝。简写文本只包含四个字段，额度和到期时间通过规则编辑或 JSON 文件设置。累计用量属于原规则，复制或新建导入的规则从新规则用量开始。</p><p>同一入口主机上的业务域名跨端口、跨资源保持唯一；同一端口可以承载多个不重复域名的 SNI 规则，并与普通转发互斥。成员副本属于同一根规则，不会被当作重复域名。</p><h2 id="创建第一条规则" tabindex="-1">创建第一条规则 <a class="header-anchor" href="#创建第一条规则" aria-label="Permalink to &quot;创建第一条规则&quot;">​</a></h2><p>进入「转发规则」，选择「添加规则」，先选择承载资源，然后打开「SNI 分流转发」开关。开关位于协议与源端口之间，打开后表单切换为分流形态：入口端口默认设为 <code>443</code>，可以修改为允许范围内的其他端口，SNI 域名成为必填项，协议锁定为 TCP，出站故障转移关闭，并出现限速与最大连接数两个字段。</p><p>开关置灰时，灰色文字写明了原因，常见的是承载资源不支持分流（隧道型转发组、直接选择入口组或出口组、多出口隧道、含非主机成员的资源）。普通用户看不到该开关。</p><p>打开开关后填写以下字段：</p><table tabindex="0"><thead><tr><th>字段</th><th>填写要求</th></tr></thead><tbody><tr><td>规则名称</td><td>填写能够区分业务用途的名称</td></tr><tr><td>使用资源</td><td>选择已经启用的主机型转发组、转发链、单机端口转发或直接隧道</td></tr><tr><td>入口端口</td><td>默认 <code>443</code>，可修改；编辑已有规则时保留保存的端口</td></tr><tr><td>SNI 域名</td><td>填写完整域名，例如 <code>api.example.com</code></td></tr><tr><td>目标地址</td><td>填写落地机的 IP 地址或域名，例如 <code>10.0.0.20</code></td></tr><tr><td>目标端口</td><td>填写目标服务监听端口，例如 <code>8443</code></td></tr><tr><td>规则限速 Mbps</td><td>填写该域名允许使用的带宽，<code>0</code> 表示无限制</td></tr><tr><td>最大连接数</td><td>填写该域名允许同时建立的连接数，<code>0</code> 表示无限制</td></tr></tbody></table><p>SNI 域名只填写域名本身，不包含 <code>https://</code>、端口、路径或通配符。域名匹配忽略大小写和末尾的点，但建议始终使用规范的小写完整域名。填写完域名后面板会校验该域名在当前入口主机上是否已被占用，冲突时在输入框下方写明与哪条规则冲突。</p><p>入口端口锁定后跳过普通规则的端口占用探测，因为多条 SNI 分流规则可以共用入口监听。保存时仍检查普通转发规则占用、域名重复及端口范围。关闭开关后恢复普通转发规则的端口探测，入口端口也恢复为打开开关之前的值。</p><h3 id="使用-443-以外的入口端口" tabindex="-1">使用 443 以外的入口端口 <a class="header-anchor" href="#使用-443-以外的入口端口" aria-label="Permalink to &quot;使用 443 以外的入口端口&quot;">​</a></h3><p>需要把分流组建在别的端口上时，点击锁定框右侧的「修改入口端口」，端口即可编辑。三种情况会用到它：</p><ul><li>主机或链路资源限定的端口范围不包含 <code>443</code>。</li><li>面板自身占用了该主机的 <code>443</code>（见 <a href="./cloudflare-cdn">Cloudflare CDN</a>），此时 <code>443</code> 上的分流规则无法启动。</li><li>要往一个已经建在非 <code>443</code> 端口上的分流组里补充域名。</li></ul><p>编辑一条已有的 SNI 分流规则时，入口端口保持规则原有的值并锁定，不会被改写为 <code>443</code>。</p><p>保存规则后，客户端仍然连接链路入口地址与入口端口。例如入口为 <code>203.0.113.10:443</code>，SNI 域名为 <code>api.example.com</code>，客户端发出的 TLS ClientHello 必须携带 <code>api.example.com</code>。分流器匹配成功后，连接才会转发到该规则的目标地址和目标端口。</p><h2 id="让多个域名共用入口端口" tabindex="-1">让多个域名共用入口端口 <a class="header-anchor" href="#让多个域名共用入口端口" aria-label="Permalink to &quot;让多个域名共用入口端口&quot;">​</a></h2><p>继续创建规则，打开「SNI 分流转发」开关，并保持入口端口与第一条规则相同。使用转发链时，可以继续选择同一条转发链，也可以选择另一条引用相同入口主机的转发链。每条规则填写各自唯一的完整 SNI 域名和落地机地址、端口：</p><table tabindex="0"><thead><tr><th>入口端口</th><th>SNI 域名</th><th>转发链</th><th>落地机</th></tr></thead><tbody><tr><td><code>443</code></td><td><code>api.example.com</code></td><td>转发链 A</td><td><code>10.0.0.20:8443</code></td></tr><tr><td><code>443</code></td><td><code>files.example.com</code></td><td>转发链 B</td><td><code>10.0.0.30:9443</code></td></tr><tr><td><code>443</code></td><td><code>admin.example.com</code></td><td>转发链 A</td><td><code>10.0.0.40:443</code></td></tr></tbody></table><p>上述示例中的两条转发链须引用同一台入口主机或具有共同成员的入口组。该入口主机的 <code>443</code> 端口只有一个入口分流器，分流表同时包含三条路由，并将每个域名送往所属转发链的下一跳。各条转发链保留自身的出口分流器端口，各条规则独立保存落地机、限速、连接数限制和流量统计。</p><p>端口资源引用入口组时，按下文的端口资源共享范围处理；跨转发链共享仍保留原有行为。隧道 SNI 分流规则仍须引用同一条隧道才能共用入口端口；单机端口转发 SNI 分流规则仍须引用同一个端口转发资源。隧道、单机端口转发和转发链之间保持入口端口互斥。</p><p>普通转发规则与 SNI 分流规则保持端口互斥。同一入口主机上的相同完整域名仍须唯一，即使规则引用不同入口端口或承载资源。某条规则未设置限速或最大连接数时，该规则保持无限制，也保持独立于用户、隧道或转发组的同类限制。</p><h2 id="检查生效状态" tabindex="-1">检查生效状态 <a class="header-anchor" href="#检查生效状态" aria-label="Permalink to &quot;检查生效状态&quot;">​</a></h2><p>在「转发规则 → sni规则组」查看 SNI 分流规则，按同一承载资源和入口端口分组；普通「全部」和其他分类不包含 SNI。主机型转发组展示当前入口和各备用成员的配置状态；当前入口已生效时，备用等待同步不会把正在工作的业务显示为全部不可用。转发链规则只有在所有相关入口分流器和出口分流器都确认对应域名进入当前有效配置后，才显示为运行中。仅出口确认、仅入口确认或入口组中部分主机确认时，规则继续等待生效。规则还须处于启用状态，承载资源处于启用状态，入口版本满足要求，且规则尚未进入删除等待状态。</p><p>分组信息分别展示入口与出口，入口组保留每台入口主机的明细。展开分组后检查以下信息：</p><table tabindex="0"><thead><tr><th>信息</th><th>含义</th></tr></thead><tbody><tr><td>入口与出口生效状态</td><td>分别检查每台入口主机和出口主机是否得到运行观测、对应域名是否生效</td></tr><tr><td>当前生效版本</td><td>各个分流器正在使用的配置版本；规则保存完成与配置生效是两个独立状态</td></tr><tr><td>入口未匹配连接</td><td>客户端使用该入口主机未配置的域名，常见原因包括域名拼写错误、DNS 指向错误或端口扫描</td></tr><tr><td>出口未匹配连接</td><td>可能来自入口与出口配置不同步，也可能来自直接访问出口的外部探测或错误域名；须结合两端生效状态和配置错误判断</td></tr><tr><td>最近配置错误</td><td>各个分流器最近一次应用配置失败的原因；存在有效旧版本时，继续使用该版本</td></tr></tbody></table><p>转发链的两类未匹配计数分别显示。入口计数可帮助检查客户端域名，出口计数须结合两端配置和外部直连情况排查，不能仅凭计数增加判定两端配置不同步。隧道和单机端口转发维持出口确认域名生效的运行状态定义。</p><p>保存或修改规则后，先等待分组状态变为运行中，再使用携带正确 SNI 的客户端连接入口地址和端口。仅验证端口建立 TCP 连接不足以证明域名已经匹配，实际请求必须发送 TLS ClientHello。</p><h2 id="查看分组与域名配置" tabindex="-1">查看分组与域名配置 <a class="header-anchor" href="#查看分组与域名配置" aria-label="Permalink to &quot;查看分组与域名配置&quot;">​</a></h2><p>在「转发规则 → sni规则组」按资源查看分组，展开规则查看域名、入口和落地地址；点击所属资源查看简约文字详情。侧边栏不再提供独立「SNI 入口」，也不再提供重复的入口概览；旧地址直接跳到 SNI 分类。</p><p>入口生效信息继续区分实际配置状态、配置编号和未匹配连接。Agent 版本不足、未上报或无法识别时，应在「主机管理」检查并完成升级，再确认入口域名生效；转发链入口分流器的最低 Agent 版本为 <code>2.2.195</code>。</p><p>管理员会在相关组头下看到「域名配置不一致」、具体入口主机与端口以及缺少的域名。提示复用原有完整关联核对，收起组内规则仍可见，没有异常时不额外占行。普通用户不调用或显示管理员的跨用户核对结果；原核对未覆盖的直接隧道 SNI 不凭空显示一致或缺失。</p><p>相关入口主机在相同端口上共享规则时，核对比较完整关联范围内的启用域名集合，不按当前页或当前小组重算。单入口与多入口配置可以合法并存，例如 <code>api.example.com</code> 使用甲乙入口、<code>files.example.com</code> 仅使用甲入口时，乙会缺少 <code>files.example.com</code>；提示显示在使用乙的相关分组，客户端 DNS 应与规则实际引用的入口一致。</p><p>以上提示表示面板规则配置差异，不能代替实际下发、生效、主机在线或业务目标可达的判断，也不参与入口选择、组切换与 DDNS。配置变更仍通过原有规则编辑及权限流程完成。</p><h2 id="配置变化与既有连接" tabindex="-1">配置变化与既有连接 <a class="header-anchor" href="#配置变化与既有连接" aria-label="Permalink to &quot;配置变化与既有连接&quot;">​</a></h2><table tabindex="0"><thead><tr><th>配置变化</th><th>既有连接</th><th>新连接</th></tr></thead><tbody><tr><td>修改域名</td><td>仅该规则的既有连接断开，其余规则保持连接</td><td>使用新域名</td></tr><tr><td>修改落地机地址或端口</td><td>仅该规则的既有连接断开；转发链入口分流表保持原配置</td><td>使用新落地机</td></tr><tr><td>修改单条规则的限速或连接数上限</td><td>仅该规则的既有连接断开，分流器进程保持</td><td>使用新限制</td></tr><tr><td>新增共用入口端口的规则</td><td>保持该端口上的既有连接，包括其它转发链的规则</td><td>可以匹配新增域名</td></tr><tr><td>停用或删除单条规则</td><td>仅该规则的既有连接断开，其余规则保持连接</td><td>该域名停止匹配并断开</td></tr><tr><td>停用承载资源</td><td>该资源的全部连接断开，共用入口端口的其余转发链保持连接</td><td>该资源的域名停止匹配</td></tr><tr><td>停用或删除入口端口上的最后一条规则</td><td>该端口的连接断开</td><td>入口停止提供该端口的分流服务</td></tr><tr><td>出口主机离线或出口分流器重启</td><td>使用该出口分流器的全部规则连接断开</td><td>恢复运行前无法建立连接</td></tr><tr><td>入口主机离线或入口分流器重启</td><td>使用该入口主机和端口的全部转发链连接断开</td><td>恢复运行前，该入口无法建立连接</td></tr></tbody></table><p>转发链入口分流器的运行时身份由「入口主机 + 入口端口」确定，删除编号最小的规则也保持相同身份。新增、修改和删除路由使用分流表热更新，监听端口保持打开，只关闭本次发生变化的规则连接。修改落地机地址仅改变出口分流表，入口下一跳和入口分流表内容保持相同。隧道删除首条 SNI 分流规则后，其余规则共用的入口配置也保持相同。</p><h2 id="升级前检查" tabindex="-1">升级前检查 <a class="header-anchor" href="#升级前检查" aria-label="Permalink to &quot;升级前检查&quot;">​</a></h2><p>面板升级确认区域复用已有管理员只读查询，检查转发链 SNI 分流规则关联的入口 Agent 版本。所有入口满足要求时显示检查通过和最低版本；存在版本异常时列出主机名称、当前版本或未上报状态，并提供进入「sni规则组」的导航。查询期间显示检查状态，查询失败时显示错误原因。没有转发链 SNI 分流规则时，省略入口版本提示。</p><p>升级前须确保所有相关入口 Agent 支持分流器。面板升级后，已有转发链 SNI 分流规则的入口监听统一切换为入口分流器，切换时既有连接发生一次中断。完成切换后的新增、修改和删除继续使用分流表热更新，并按上表处理连接。入口 Agent 版本异常时，相关规则停止运行并显示异常；恢复符合要求的版本后，继续检查入口和出口的生效状态。</p><h2 id="连接问题排查" tabindex="-1">连接问题排查 <a class="header-anchor" href="#连接问题排查" aria-label="Permalink to &quot;连接问题排查&quot;">​</a></h2><p>规则创建后无法连接时，按照以下顺序检查：</p><ol><li>比对客户端发送的 SNI 与规则中的域名是否完全一致。<code>example.com</code>、<code>www.example.com</code> 和 <code>api.example.com</code> 是三个不同的匹配值。</li><li>使用转发链时，分别查看入口和出口的未匹配连接数。入口计数增加时，检查域名拼写、客户端 DNS 指向及「sni规则组」中的域名与入口配置提示；出口计数增加时，检查入口和出口的生效状态、配置版本与最近配置错误，并排查外部直接连接出口的探测。隧道或单机端口转发的出口计数增加时，检查客户端域名是否存在于出口分流表。</li><li>使用入口组时，检查每台入口主机的 Agent 版本和域名生效状态。只有部分入口生效时，客户端可能因 DNS 选择不同入口而出现连接差异。</li><li>未匹配连接数没有增加时，检查客户端是否连接了正确的入口地址和端口，再检查入口安全组、防火墙、转发链各台主机以及出口主机是否在线。</li><li>确认目标服务能够从出口主机访问，并检查落地机地址、端口和目标服务证书配置。</li></ol><p>配置修改后未生效时，检查对应入口主机与出口主机的「当前生效版本」和最近配置错误。受影响的分流表版本保持相同并出现错误时，该分流器仍使用上一份成功配置；根据错误内容修正端口占用、规则字段或 Agent 运行环境。仅修改落地机地址时，入口分流表内容保持相同属于预期行为。</p><h2 id="行为边界与限制" tabindex="-1">行为边界与限制 <a class="header-anchor" href="#行为边界与限制" aria-label="Permalink to &quot;行为边界与限制&quot;">​</a></h2><p>未匹配任何 SNI 域名的连接会立即断开，系统不会设置默认目标。入口端口只响应分流组中配置的特定域名，因此端口扫描、普通 TCP 探测或未携带 SNI 的客户端可能表现为连接后立即关闭。</p><p>面板不再为 SNI 分流端口维护来源 IP 放行名单，覆盖转发链出口和隧道 SNI 出口。升级后，在线 Agent 会清理此前由该功能安装的防火墙规则，包括已退役端口的残留；离线主机在恢复正常心跳后继续清理。此变更兼容现有 Agent 和 FXP runtime，无需先升级它们。清理失败或无法核实时会记录失败并自动重试；应核对主机上的实际规则，不能只凭分流器显示运行中判断清理完成。</p><p>完成清理后，在网络及其他防火墙允许访问的前提下，任意来源都可以直连出口分流端口，并通过已配置的 SNI 域名访问对应落地机。SNI 域名用于选择目标，不提供账号或密钥认证；目标服务若只信任出口主机 IP，外部直连也会以出口身份访问。需要访问控制时，请使用服务自身认证或另行设置防火墙与云安全组。面板的其他防火墙规则、中国区域白名单插件和管理员自行配置的限制继续独立生效。</p><p>入口来源 IP 改变后，只要客户端已经到达新入口、下一跳网络恢复且路由有效，就不再需要等待面板更新出口来源名单。客户端仍访问旧地址、DNS 缓存未更新、下一跳地址变更或其他防火墙限制仍可能造成中断。</p><p>未知域名、未携带 SNI、非 TLS 或握手未在读取时间内完成的连接仍会断开，匹配成功的 TLS 握手原样传输到后续目标。按规则限速、连接数上限、最大来源 IP 数限制和出口统一流量计量继续生效。</p><p>SNI 分流只支持 TCP，并依赖客户端发送可解析的 TLS ClientHello。客户端携带加密客户端问候（ECH）扩展不影响分流：只要 ClientHello 中的明文 SNI 可读，连接就按该域名匹配。只有完全取不到明文 SNI 的连接才无法匹配。</p><p>使用单一出口的转发链、单机端口转发或直接隧道时，出口主机是整个分流组的单点。出口主机离线、网络中断或分流器停止时，同组全部域名均无法访问。</p><p>共用同一台入口主机和端口的转发链也共用一个入口分流器，该进程停止会同时影响该端口的全部转发链。分流表热更新保持监听运行，日常规则变更仅影响对应规则的连接。</p><p>客户端真实 IP 无法保留到最终目标。最终目标看到的连接来源是出口主机或分流器使用的本机地址，不能依赖来源地址执行客户端访问控制或审计。</p><p>SNI 分流规则共用的入口端口仅对分流表中的完整域名产生有效转发，并保持与普通转发规则互斥。这一行为会影响通用端口探测、监控和未携带 SNI 的健康检查，监控请求应使用该入口分流表中的实际域名。</p><h2 id="权限与流量故障转移" tabindex="-1">权限与流量故障转移 <a class="header-anchor" href="#权限与流量故障转移" aria-label="Permalink to &quot;权限与流量故障转移&quot;">​</a></h2><p>管理员为普通用户配置规则时，面板检查归属用户的资源授权、套餐、余额、有效端口和额度；共用 SNI 入口端口只占一份端口配额。管理员代建或具有限速、流量额度、有效期的规则对普通用户为只读，包括存量限速 SNI。清空限额不会解除已保存的托管标记；单条、批量和机器人入口执行相同权限。</p><p>单规则额度按最终分流器累计流量计量；主机型转发组汇总所有入口成员的实际用量，到期或达量只暂停对应域名，保存的启用开关不改变，共享端口上的其他正常域名继续服务。管理员重置规则统计时会同时清空该规则的额度计数，可能恢复达量暂停的规则；账户套餐用量、余额和到期限制不因此重置。</p><p>主机流量故障转移默认关闭。开启后，只有超量入口退出时，同一链的其他正常入口和共同出口继续工作；固定中继或出口超量时，经过它的链暂停。同一入口端口上的其他健康链仍保留域名和共享监听。重置流量或关闭开关后按原成员与端口恢复，无需重建规则。</p><h2 id="端口资源通过入口组直接分流" tabindex="-1">端口资源通过入口组直接分流 <a class="header-anchor" href="#端口资源通过入口组直接分流" aria-label="Permalink to &quot;端口资源通过入口组直接分流&quot;">​</a></h2><p>这个方式适合多台入口同时为相同的一组域名提供服务。它不挑选一台主入口，也不把入口组最后一台主机当成公共出口。主机型主备转发组仍使用自己原有的切换方式。</p><ol><li>创建由主机组成的入口组，例如 A、B，并保存端口转发资源，让该资源引用入口组。</li><li>管理员在「转发规则」选择这个端口资源，开启 SNI，使用统一 TCP 端口，例如 <code>18443</code>。</li><li>保存 <code>api.example.com → X:443</code>、<code>files.example.com → Y:8443</code> 两条规则。X、Y 是规则各自的落地机，可以不同，无需为了这个方式安装 Agent 或 FXP。</li><li>检查 A、B 的逐入口状态。客户端连接 A 时，走「A → X」或「A → Y」；连接 B 时，走「B → X」或「B → Y」。A 与 B 不串联，TLS 握手和业务内容原样传递。</li></ol><h3 id="当前内容确认与解析" tabindex="-1">当前内容确认与解析 <a class="header-anchor" href="#当前内容确认与解析" aria-label="Permalink to &quot;当前内容确认与解析&quot;">​</a></h3><p>每台入口独立比较当前应有的完整内容，包括业务域名、规则归属、落地地址与端口、限速、连接数和其他限制。旧目标、缺少一条域名、仅命令回执、仅端口监听或仅 Agent 在线都不能代替完整确认。入口组引用多个相关 SNI 资源时，须核对该入口应运行的全部相关内容。</p><p>A 完整、B 缺一条时，A 可以先具备解析资格，B 继续显示具体等待原因。资格还要求在线、有效完整确认、已开启的国内健康检测通过，以及应有的恢复观察已经结束。SNI 目标连接探测缺失或失败不单独阻止这个资格；普通规则仍使用自己的目标检测。</p><p>A／AAAA 发布全部合格入口；CNAME 保持单目标方式。关闭自动解析后，由管理员根据页面建议自行维护 DNS。新入口从未确认完整配置时不能首次保底发布。普通健康故障下保留一条原解析的既有保底，只能使用仍启用、未移除、未因额度退出的原成员；保留地址仍须显示故障或等待，不算就绪。没有这类成员时，不能把已退出的地址重新加入。</p><h3 id="共享端口、用量与成员调整" tabindex="-1">共享端口、用量与成员调整 <a class="header-anchor" href="#共享端口、用量与成员调整" aria-label="Permalink to &quot;共享端口、用量与成员调整&quot;">​</a></h3><p>同一入口主机和端口使用共享分流器，仍检查普通端口互斥、域名唯一、资源权限和端口范围。这里只扩展端口资源引用入口组的组合，不把隧道、主备转发组和转发链的共享范围混在一起，也不开放直接 SNI 隧道的多出口。</p><p>创建时不恢复主机现场占用预检。面板内冲突、权限或域名重复导致保存失败时，整笔保存保持旧内容；保存后某台主机执行失败时，单独显示该入口错误，其他健康入口继续服务。成员移除、停用或达量退出后，不再具备解析资格，停止未确认和待结算内容继续保留以便重试。</p><p>每条规则在各入口分别执行限制。例如 10 Mbps 是 A、B 各自 10 Mbps，不能当作跨机器共用总限速。A 实际 30 GB、B 实际 20 GB，原规则汇总 50 GB；重复报告不能重复加用量或扣费。规则达量或到期只撤掉该域名，正常共享域名继续运行；撤除失败时沿用本页的旧配置保护。</p><p>来源采样不按共享端口猜域名，不新增 SNI 专用来源 IP 数据。变更后的操作验收应实际连接两台入口，检查最终落地、未知域名拒绝、各入口确认与 DNS 结果；文档描述不代替实际验收。</p></div></div></main><footer class="VPDocFooter" data-v-cb09c906 data-v-2a865e41><!--[--><!--]--><div class="edit-info" data-v-2a865e41><div class="edit-link" data-v-2a865e41><a
