# 02：订阅套餐销售库存与订单闭环

Status: completed

**交付行为：** 管理员可以配置和查看订阅套餐销售库存，购买者从下单、付款到发放或关闭订单均获得一致的库存结果，并发、重试和迟到付款不会超售或重复发放。

**Blocked by:** 无（可独立开始）。

## 验收标准

- [x] 套餐管理、购买展示及相关接口形成完整路径，管理员能保存销售库存，用户能看到与自身权限相符的库存及售罄信息。
- [x] 三种受支持数据库的初始化和迁移默认一致，旧套餐库存为 `0＝不限`，历史已售订阅不追溯扣减；升级后的新销售即使不限库存也累计销售占用。
- [x] 新购、管理员新分配和兑换每份消耗 1 份销售库存；续费不额外占用，已有服务可按既定规则续期。
- [x] 待支付订单预占库存；未付款取消、过期或支付创建失败后正确释放，重复关闭或重试不会重复释放。
- [x] 已售订阅取消或到期不返还销售库存，展示和后台判断均保持销售总量语义。
- [x] 库存检查、预占和发放具有一致的原子边界；并发下单、管理员分配与兑换无法超售。
- [x] 支付回调、发放重试和订单状态转换保持幂等，不重复占额、发放或入账。
- [x] 已关闭订单迟到付款时重新检查实时库存；有库存可按既有流程处理，无库存则保留真实已付款及发放失败状态，供管理员补货重试或通过支付渠道退款，不虚报成功或超售。
- [x] 不新增自动退款系统；既有订单权限、支付校验、余额与账务边界保留。
- [x] 本单新增或变更的销售、兑换、关闭、回调、发放和库存配置写入正确刷新相关展示；组合第 04 单短缓存后仍正确失效，库存和支付判断始终读取实时状态。
- [x] 降低库存不撤销已有订阅；后续新销售遵循新限额，不实际替现有产品设定业务库存数字。
