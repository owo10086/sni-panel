# 03：按量资源库存与每账号逻辑规则上限

Status: completed

**交付行为：** 管理员可以设置按量资源的占用账号数和每账号逻辑规则上限；普通与 SNI 用户在创建、批量变更和删除规则时得到一致的限额与费用结果。

**Blocked by:** 无（可独立开始）。

**规格对应：** [唯一规格](../spec.md)；用户故事 2、8–17、19、21、33、35；实施决定 4、6–8、10–13、18、21。

**执行边界：** 用户已通过 `$implement` 明确授权本地实施、验证、审查及当前分支中文提交。按固定上游 v2.3.289 兼容适配，保留既有工作区内容，不创建工作树；不推送、不打标签、不发布或部署。

## 验收标准

- [x] 按量资源的库存与每账号逻辑规则上限可配置、保存、读取和展示；三种受支持数据库的初始化与迁移均以 `0＝不限` 为旧配置默认值。
- [x] 按转发组、隧道、主机优先级选首个已启用匹配计费配置，一条逻辑规则只归属一个有效计费资源。
- [x] 同一账号在同一有效资源拥有至少一条未逻辑删除的根规则即占 1 份库存，多条规则不重复占额，停用规则仍占用；库存满时，已有占用者仍可在自身上限内增加规则。
- [x] 每条 SNI 域名根规则分别计数，自动生成的成员副本不重复计数；两个域名共用一个入口端口按 2 条规则、1 个端口计算。
- [x] 资源规则上限与既有账号最大规则数、最大端口数叠加执行，保留并发配额预留和共享端口去重；降低限额不删除已有规则。
- [x] 普通与 SNI 的单次创建、导入、复制、编辑、资源切换、移组、变更所属用户及恢复删除状态均按需要实时校验，新用户进入和旧资源释放一致，批量操作不能绕过限制。
- [x] 并发库存与规则上限检查和写入保持原子；拒绝或回滚不会遗留占额、重复规则、跨账号数据或不完整归组关系。
- [x] 根规则先结算成功再逻辑删除，结算失败保留规则与库存占用；最后一条根规则逻辑删除后释放资源库存。
- [x] 逻辑库存释放不跳过真实停止确认、监听和端口清理；受管副本不占库存，其待结清重试、欠费停用、历史墓碑和最终清理继续有效，不漏账或重复收费。
- [x] 保留计费用户锁先于数据库事务、个人分组账号隔离、MySQL 旧快照修复和规定死锁条件下最外层完整回滚重试，不局部重跑结算或提交后动作。
- [x] 创建规则仍只按既有数据库冲突、端口范围和套餐限制校验；遵守 ADR-0004，不恢复创建前的主机监听占用门槛。
- [x] 本单新增库存配置及规则写入、部分变更、删除和结算路径正确刷新相关展示；组合第 04 单短缓存后仍正确失效，执行限额始终实时判断。
- [x] 保留资源权限、SNI 校验、个人分组和跨账号隔离，不用库存校验替代既有授权。

## 验证入口

沿用带账号上下文的普通／SNI 规则 API、配额预留、批量导入／复制／移组、删除计费和个人分组验证。覆盖最后一份库存并发竞争、同账号多规则、共享端口、生成副本、结算失败及逻辑删除后尚未停止的状态；使用真实 MySQL 并发回归核对旧快照、空范围死锁与完整事务重试，不能仅以 SQLite 通过代替。

## 实施与验证结果（2026-10-24）

- `a3dbf82` 将资源库存和每账号逻辑规则上限放入既有规则写入事务，覆盖单次／批量、修改资源或用户和恢复删除状态；保留计费用户锁顺序、MySQL 当前读及最外层完整事务重试。
- 库存与跨进程竞争专项通过，包含资源归属优先级、同账号多规则只占一份、停用仍占用、库存满后已占用者继续增加、最后根规则删除释放、转移与恢复失败回滚。真实 MySQL 回归覆盖旧 RR 快照之后的名额／规则上限竞争。
- 新增 SNI 组合回归通过：两个域名根规则按 2 条逻辑规则／1 个共享端口计算，成员副本不计数；账号规则额度、账号端口额度与资源上限同时生效。
- 新增根删除结算故障注入通过：账务写入失败时不提前标记逻辑删除，库存仍占 1；恢复后删除释放，账单只写 1 次。既有停止确认、待结清、墓碑、欠费停用和成员副本清理继续由本地回归覆盖。
- 性能验收定位到主备组反复重开已结清历史副本，补上与链式组一致的跳过保护；未结清副本继续重试，墓碑仍等待 Agent 停止确认。扩展既有结算／欠费停用故障测试到主备组，修前两项因重开结算失败，修后相关 5 项通过，保留只结算一次及完整墓碑断言。
- 明确写入有效子副本关联的更新省去不影响库存的专属事务／重复读取；判断只依赖本次 patch，不能依据可能过期的旧副本状态。副本转回逻辑根规则及根规则恢复、换资源或换账号仍保留原实时事务、产品锁和当前读。SQLite 与两版真实 MySQL 回归覆盖转换占额、满库存／个人上限拒绝、所属用户回滚及根转子释放后再次占额。
- ADR-0004 的创建规则边界保持，新增库存校验不恢复主机监听占用前置门槛。规则与库存写入在提交后失效相关展示，权限和限额执行仍实时。
- SQLite、MySQL 执行真实业务验证；PostgreSQL 仅核对 schema 生成与 `0` 默认值，**未进行真实 PostgreSQL 业务回归**。
